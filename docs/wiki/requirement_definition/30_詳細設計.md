## 1. 実装方針

### 1.1 技術前提

- Python 3.12.x
- FastAPI等のASGI Web Framework
- Pydantic等の型付きSchema Validation
- SQLAlchemy等のORM / SQL Abstraction
- PostgreSQL
- Local Filesystem Artifact Store
- Web APIと別ProcessのWorker

### 1.2 実装原則

- Domain / ApplicationはWeb FrameworkとORM Modelへ直接依存しない
- Application ServiceはPortを介してPersistence、Artifact Store、Scientific Coreを利用する
- Scientific CoreはProduct Domain、DB Repository、Web API Schemaを参照しない
- 7 Entityを維持する
- ComparisonとLineageはQuery Modelとする
- Entity更新とArtifact File書込みの失敗補償を明示する
- 未決事項をCoding Agentが補完しない
- 実装から要件を変更しない

## 4. Snapshot詳細設計

### 4.1 Schema

```text
causal-analysis-spec/2
```

### 4.2 Canonicalization

1. 未知FieldをRejectする
2. Schema Versionを検証する
3. Operationに無関係なFieldをRejectする
4. Key順を固定する
5. UUID、日時、Enumを文字列へ正規化する
6. 非有限FloatをRejectする
7. Dataset / Graph Hash、Input Result IDを含める
8. Canonical JSONを生成する
9. SHA-256 Hashを生成する
10. Submit後の変更を禁止する

### 4.3 Validation Override

Data Eligibility `WARN`を継続する場合、以下を必須とする。

```json
{
  "reason": "Scientific justification",
  "actor": "user-id",
  "warning_codes": ["LIMITED_OVERLAP"]
}
```

## 7. Scientific Core Adapter

### 7.1 Port

```python
class ScientificCorePort(Protocol):
    def run_discovery(...) -> list[ScientificResultDescriptor]: ...
    def run_identification(...) -> list[ScientificResultDescriptor]: ...
    def run_estimation(...) -> list[ScientificResultDescriptor]: ...
    def run_refutation(...) -> list[ScientificResultDescriptor]: ...
    def run_sensitivity(...) -> list[ScientificResultDescriptor]: ...
```

### 7.2 Discovery Adapter

- Algorithm Outputを保存する
- BackendがBackground Knowledgeを正式Supportする場合のみAlgorithm Inputへ渡す
- Supportしない場合はPost-hoc Graphを別Versionにする
- Graph Type、Endpoint、Backend Version、Warningを保持する

### 7.3 Identification Adapter

ENH-E1必須:

- RANDOMIZED
- BACKDOOR

Validation:

- DAG要件
- Treatment / Outcome Node
- Adjustment Column
- Treatment / Outcome混入
- Treatment Descendant
- Known Collider
- Back-door Path Blocking

CPDAG / PAGで一意判断できない場合は`REQUIRES_REVIEW`。

### 7.4 Data Eligibility

Check Result:

```json
{
  "check_code": "LIMITED_OVERLAP",
  "status": "WARN",
  "message": "...",
  "evidence": {}
}
```

総合Status:

```text
FAIL > WARN > PASS
```

### 7.5 Estimation Adapter

- Input Identification Resultを検証する
- Estimator Capability Registryを参照する
- Treatment EffectとDiagnosticsを別Descriptorで返す
- 未対応OptionをRejectする

### 7.6 Refutation Adapter

必須Method:

- PLACEBO_TREATMENT
- DATA_SUBSET

### 7.7 Sensitivity Adapter

必須Dimension:

- ADJUSTMENT_SET
- PROPENSITY_CLIPPING

## 8. Worker詳細設計

### 8.1 Execution Claim

`FOR UPDATE SKIP LOCKED`等で1件をClaimし、同一Transactionで`RUNNING`へ遷移する。

### 8.2 Explicit Dispatch

```python
match execution.operation:
    case ExecutionOperation.DISCOVERY:
        outputs = core.run_discovery(...)
    case ExecutionOperation.IDENTIFICATION:
        outputs = core.run_identification(...)
    case ExecutionOperation.ESTIMATION:
        outputs = core.run_estimation(...)
    case ExecutionOperation.REFUTATION:
        outputs = core.run_refutation(...)
    case ExecutionOperation.SENSITIVITY:
        outputs = core.run_sensitivity(...)
    case _:
        raise UnsupportedExecutionOperationError(execution.operation)
```

### 8.3 ExecutionProcessor Sequence

1. Executionを再取得する
2. Cancel済みなら終了する
3. Dataset Artifactを取得しHashを検証する
4. Graphを必要に応じて取得する
5. Upstream Resultを必要に応じて取得する
6. Snapshot Hashを検証する
7. Scientific Inputへ変換する
8. Scientific Coreを呼ぶ
9. 1件以上のResult Descriptorを検証する
10. Artifact候補をTemporary領域へ書く
11. Artifact Storeへ保存する
12. Result群、Artifact Metadata、Execution Statusを1 Transactionで保存する
13. Temporary Fileを削除する

### 8.4 Failure Compensation

| Failure | 処理 |
|---|---|
| Input Artifact取得失敗 | `FAILED` |
| Scientific Core技術例外 | Log Artifact保存を試行し`FAILED` |
| Artifact Store保存失敗 | Resultを保存せず`FAILED` |
| Artifact保存後DB失敗 | Orphan Cleanup対象、`FAILED` |
| Scientific Negative Outcome | Result保存、`SUCCEEDED` |
| Cancel要求 | Safe Pointで`CANCELLED` |

### 9.2 Migration方針

- 旧Run / Attempt互換を追加しない
- Dual-writeを行わない
- DowngradeはRepository規約に従う
