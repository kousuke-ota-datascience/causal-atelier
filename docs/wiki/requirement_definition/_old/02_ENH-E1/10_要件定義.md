## 1. 適用範囲

初期版は、前処理済み表形式データを対象に、次を一続きで実行する。

```text
Dataset登録
→ 因果探索の複数実行
→ Graph比較・選定
→ ATE/ATT推定の複数実行
→ Result比較
→ 判断メモ・来歴確認
```

主対象用途は売上改善とする。

本書は、完成後のAriadneが満たす要件を自己完結的に記述する。実装移行、資産流用および変更対象module等は本書の対象外とし、別途コーディング計画またはコーディングプロンプトで定義する。

## 2. 利用者

| Actor | 初期版の責務 |
|---|---|
| Analyst | Dataset登録、探索・推論条件設定、Execution、比較、Graph選定、判断メモ記録 |
| Viewer / Reviewer | Resultと来歴のread-only確認 |
| Operator | 実行環境と保存領域の運用。初期価値検証の主対象外 |

初期版では高度なRole別権限モデルを実装しない。Project単位の基本的な閲覧・編集権限で開始する。

## 4. 業務シナリオ

### 4.1 シナリオ分類

| 分類 | 定義 |
|---|---|
| E2E | 利用者目的を完了させ、価値提供可能性を検証する一連のシナリオ |
| AS | E2Eを構成する分析作業シナリオ |
| CR | 複数E2E / ASに横断して必要な比較・来歴能力 |

### 4.2 E2Eシナリオ

#### 4.2.1 E2E-01 因果探索からGraph候補を決定する

前処理済みDataset Versionを登録し、複数アルゴリズムおよびparameter条件で因果探索を実行する。Graph結果を比較し、推論に使用するGraph Versionを決定する。

**完了条件**

- 2件以上のDiscovery Resultを比較できる
- 変更条件とGraph差分を確認できる
- 採用Graph Versionと選定理由を保存できる

#### 4.2.2 E2E-02 採用Graphを使用して因果効果を評価する

採用Graph Versionを入力としてCausal Designを指定し、複数EstimatorでATEまたはATTを推定する。Resultとdiagnosticsを比較し、採用・不採用の判断理由を記録する。

**完了条件**

- 2件以上のEstimation Resultを比較できる
- 科学的負結果を技術失敗と区別できる
- Resultから使用条件へ遡れる

#### 4.2.3 E2E-03 分析結果と来歴を第三者が確認する

ViewerがResults / Lineage Workspaceを開き、採用Result、判断理由、使用Dataset、Graph、algorithm、parameter、diagnosticsおよびArtifactを確認する。

初期版では承認状態やコメントスレッドを管理せず、read-only確認の成立のみを検証する。

#### 4.2.4 E2E-04 Identification-first

1. Dataset Versionを登録する
2. FIXED Graph Versionを選択する
3. Research Context、Causal QuestionおよびCausal Designを入力する
4. Identification Executionを実行する
5. Identification ResultとData Eligibility Resultを保存する
6. `IDENTIFIED`の場合のみEstimationへ進む
7. 同一Identification Resultを複数Estimatorが参照する
8. Treatment EffectとDiagnosticsを比較する
9. RefutationとSensitivityを実行する
10. Annotationへ採用理由、仮定および限界を記録する
11. Resultから全上流条件へ遡る

#### 4.2.5 E2E-05 非識別結果

1. 識別不能なGraph / Causal Questionを指定する
2. Identification Executionは技術的に`SUCCEEDED`となる
3. Identification Resultは`NOT_IDENTIFIED`となる
4. 非識別理由を保存する
5. 通常Estimationの受付を拒否する
6. Result比較とLineage確認は可能とする

#### 4.2.6 E2E-06 Graph Provenance

1. Discovery ResultからGraph Versionを作成する
2. Constraint適用Graphを別Versionとして作成する
3. User Editを別Versionとして作成する
4. 各VersionのOrigin、Parent、理由を確認する
5. Algorithm Outputを人為編集結果として表示しない

### 4.3 分析シナリオ

| ID | シナリオ | 説明 |
|---|---|---|
| AS-01 | 複数探索アルゴリズム比較 | 同一Datasetに対する複数探索AlgorithmのGraphを比較する |
| AS-02 | パラメータ感度比較 | 同一Algorithmのparameter変更によるGraph差を比較する |
| AS-03 | Graph選定・簡易修正 | 出力Graphを選定し、必要な修正と理由を保存する |
| AS-04 | ATE/ATT推定 | Causal Designに基づきTreatment Effectを推定する |
| AS-05 | 複数推定器比較 | 固定条件下でEstimatorだけを変更しResultを比較する |
| AS-06 | 識別不能・推定不能・信頼不能 | 数値結果を採用できない状態をResultとして保存する |
| AS-07 | Dataset Version再評価 | 分析条件を再利用し、Dataset Versionだけを変更して再評価する |

AS-07はSHOULDとし、Golden Path受入れ試験の必須条件にはしない。

### 4.4 横断シナリオ

| ID | シナリオ | 説明 |
|---|---|---|
| CR-01 | 複数Result比較 | 共通条件、変更条件、結果差分を生成する |
| CR-02 | Resultから来歴への遡及 | Resultから入力・設定・Artifactを復元する |
| CR-03 | 上流Resultを下流入力として同定 | Discovery Result由来のGraph VersionをEstimationへ渡す |
| CR-04 | 目的メモからResultまでの追跡 | Project / Executionの目的・理由snapshotとResultを対応付ける |
| CR-05 | 判断理由の記録 | 採用GraphまたはResultの理由、仮定、限界を記録する |

## 6. カバーするアルゴリズム

### 6.1 選定原則

初期版では、異なる仮定を持つ複数の因果探索法と、異なる推定戦略を持つ複数のEstimatorを比較できることを重視する。

アルゴリズム固有の仮定、適用条件および警告はUIとResultに表示する。すべての出力GraphをDAGとみなさず、実際のGraph typeとendpoint semanticsを保持する。

### 6.2 初期対応範囲

| 分類 | Algorithm / Estimator | 初期UIでの扱い | 主な用途・位置付け |
|---|---|---|---|
| Discovery | PC | MUST | 制約ベース探索。parameter sensitivityの基準ケース |
| Discovery | GES | MUST | スコアベース探索。PCとの比較対象 |
| Discovery | LiNGAM | SHOULD | 非Gaussian性等の追加仮定を置く探索法 |
| Discovery | NOTEARS | MAY | 連続最適化ベースの探索法 |
| Estimation | Difference in means | MUST | 未調整baseline。因果推定としての限界をwarning表示する |
| Estimation | Outcome regression / OLS | MUST | Outcome modelによる調整推定 |
| Estimation | IPW | MUST | Propensity score weightingによる推定とoverlap / balance診断 |
| Estimation | AIPW | SHOULD | Outcome modelとpropensity modelを組み合わせた推定 |
| Estimation | g-computation | MAY | Outcome modelに基づく標準化推定 |

Golden Path受入れ試験では、Discoveryを2種以上、Estimatorを2種以上使用する。

### 6.3 ENH-E1対応範囲

- Identification: `RANDOMIZED`, `BACKDOOR`
- Data Eligibility: schema、missingness、sample size、post-treatment、初期overlap
- Refutation: Placebo Treatment、Data Subset
- Sensitivity: Adjustment Set Variation、Propensity Clipping Variation
- Graph: User-defined / Imported / Discovered / Constraint Adjusted / User Edited
- Graph Type: DAG / CPDAG / PAGの意味保持

CPDAG / PAGに対して一意なIdentification判断ができない場合は`REQUIRES_REVIEW`とする。

## 7. インターフェース要件

### 7.1 Web App

- 4つのWorkspaceでGolden Pathを完了できること
- 設定JSONを直接編集しなくても主要条件を指定できること
- ComparisonとLineageを視覚的に確認できること

### 7.2 Web API

- Web Appで使用するProject、Dataset Version、Execution、Result、Graph Version、ArtifactおよびAnnotation操作を提供すること
- APIを正本のControl Plane interfaceとすること
- idempotency、validationおよびstatus取得を提供すること

### 7.3 CLI

- CLIとWeb/APIの実行粒度は独立であり、識別用IDを共有しないこと
- 物理実装上、Web/API実行時に発行されるAriadne `execution_id`はCLI実行時に生成しないこと
- Discovery / Inferenceの科学計算を実行できること
- manifest、設定hash、code version、ResultおよびArtifactを出力すること
- Project管理、判断メモ、Web比較UIの全機能をCLIへ重複実装しないこと
- 将来、CLI出力をWebへ登録するimport interfaceを検討可能な出力形式とすること

### 7.4 Scientific Capability

Web App、Web APIおよびCLIは、利用可能なOperation、Estimator、Identification Strategy、Refutation Method、Sensitivity Methodおよび対応するInput Contractを一貫して表現すること。
