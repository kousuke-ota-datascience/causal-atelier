## 3. Architecture Principle

### 3.1. Layer

- Domain: Resource、state、invariant、value object
- Application: use case、transaction、policy、planner、executor control
- Port: repository、artifact store、runner、clock、auth、event
- Adapter: SQL、Filesystem / Object Storage、Scientific library、ML library
- Interface: Web API、Worker、CLI、Frontend

DomainはWeb Framework、ORM、plot library、ML libraryおよびlegacy moduleへ依存しない。

### 3.2. Capability分離

```text
Shared Product Core
├── Project / Context
├── Data / Analysis View
├── Workflow Core
├── Result / Artifact / Lineage
└── Security / Audit

Analysis Capabilities
├── Exploratory
├── Causal
└── Predictive
```

各Capabilityは次を一組として持つ。

- Family Specification Schema
- Planner
- Stage Runner
- Family Validation
- Result Schema
- UI Workspace
- Benchmark / Acceptance Test

## 5. Generic Workflow Core

### 5.1. Planner

`PlannerRegistry`がAnalysis FamilyとSpecification Schema VersionからPlannerを解決する。

```text
AnalysisSpecification
  ↓
PlannerRegistry.resolve(family, schema_version)
  ↓
Family Planner
  ↓
ExecutionPlan
```

PlannerはDomain上の不変Planを生成し、実行しない。

### 5.2. Plan

Execution PlanはStage DAGである。単純な直列もDAGの一形態として表現する。

- Stage keyはPlan内一意
- Stage Typeはnamespace / name / version
- Edgeはoutput nameとinput nameをbindingする
- cycle禁止
- required input未解決禁止
- Runner未登録禁止

### 5.3. Executor

Generic Executorは、canonical lifecycle/application serviceがclaim済みのworkflow execution contextを受け取り、Analysis内容を知らずに次を実行する。

1. dependency解決
2. Stage sequencingとStage-level outcome construction
3. Runner解決・invocation
4. workflow-level validation
5. in-memory / temporary output binding

canonical Executionのclaim、lease、state、cancel、retry/rerun/revise、transaction、Result/Artifact metadata persistenceおよびExecution aggregate commitは、canonical lifecycle/application serviceの責務であり、Generic Executorの責務ではない。

### 5.4. Runner Registry

```text
exploratory.profile.v1
exploratory.chart.v1
causal.discovery.v1
causal.identification.v1
causal.estimation.v2
causal.refutation.v1
causal.sensitivity.v1
predictive.prepare.v1
predictive.split.v1
predictive.train.v1
predictive.evaluate.v1
predictive.explain.v1
```

巨大な`if stage_type == ...`をExecutorへ追加しない。

## 6. Family別Workflow

### 6.1. Exploratory

```text
PROFILE / AGGREGATE / VISUALIZE
```

軽量operationは単一Stage Planでもよい。高負荷集計またはchart materializationは非同期Executionとする。

### 6.2. Causal

```text
DISCOVERY
または
IDENTIFICATION → ELIGIBILITY → ESTIMATION → DIAGNOSTICS
                                 ├→ REFUTATION
                                 └→ SENSITIVITY
```

Discoveryは必須前段ではない。Graph Versionを直接登録できる。

### 6.3. Predictive

```text
PREPARE → SPLIT → TRAIN → EVALUATE → EXPLAIN
```

- PREPARE: feature frameとfitted前のpreprocessing definition
- SPLIT: immutable partition artifact
- TRAIN: train / validationのみを使用
- EVALUATE: frozen modelをuntouched testへ適用
- EXPLAIN: frozen modelと明示datasetを使用

TuningはTRAIN内部または独立TUNE Stageとして実装できる。いずれの場合もExecution Planに明示し、test partitionを参照しない。

## 8. Result / Artifact / Lineage

### 8.1. Result

共通EnvelopeとFamily Schemaを分離する。Resultのanalytical statusはType別に制約する。

### 8.2. Artifact Commit

```text
Runner writes temporary object
  ↓
hash / size / schema validation
  ↓
metadata transaction commits
  ↓
temporary object promoted to final URI
  ↓
outbox emits ARTIFACT_COMMITTED
```

promotion失敗時はcompensation jobがmetadataとobjectを整合させる。

### 8.3. Lineage

Lineage Query Serviceはforeign key、snapshot reference、LineageEdgeを統合してDAG Projectionを返す。履歴のないclientが独自推測しない。

## 9. Comparison Design

### 9.1. Same-family Comparison

- comparison keyを検証する
- invariant conditions
- changed conditions
- result differences
- warnings / diagnostics differences

### 9.2. Cross-family Summary

Cross-familyでは単位の異なるmetricを同じ軸でrankしない。次の関係を表示する。

- shared Context
- shared Dataset / Analysis View
- exploratory result motivated analysis
- predictive result generated causal hypothesis
- selected / rejected Result and rationale

## 10. Frontend State Design

- server state: API query cache
- route state: selected IDs、filter、comparison selection
- draft state: unsaved form
- authoritative state: backend Resource status

Button enablementをclient local stateだけで決定しない。Backendが`operation availability`と拒否理由を返す。

## 11. Security Design

- Authentication: development header / production OIDC
- Authorization: Project role
- Audit: write / execute / export
- Artifact: signed or controlled download
- Preview: row / column limit、masking option
- Prediction / local explanation: sensitive output policy
- Secret: environment / secret manager、Artifact・logへ出力しない

## 12. Deployment

```text
Reverse Proxy / Static Frontend
        │
        ▼
FastAPI Control Plane ─ PostgreSQL
        │                    │
        └──── Outbox ────────┘
                 │
                 ▼
              Worker Pool
                 │
                 ▼
     Local / S3 / Azure Artifact Store
```

APIとWorkerは別processとし、Worker数を水平拡張できる。Runner capabilityはWorker startup時に登録・検査する。

## 13. Failure Model

| Failure | 扱い |
| --- | --- |
| Validation rejection | Executionを作成せず4xxまたはREJECTED Command Result |
| Technical stage failure | Stage FAILED、Execution FAILED、retry可否を記録 |
| Prerequisite unmet | Stage SKIPPED_DUE_TO_PREREQUISITE、分析Resultとして理由保存 |
| Analytical negative result | Execution SUCCEEDED、ResultにNOT_IDENTIFIED等を保存 |
| Artifact commit failure | Executionを成功扱いせずcompensation対象 |
| Client disconnect | server-side Execution継続。cancelは明示Command |

## 14. Schema / Dependency Boundary

- 因果分析の正規Schemaは`causal-analysis-spec/2`とする。
- Analysis Specification、Execution Plan、ResultおよびArtifact Descriptorはschema-versioned readerを介して解決する。
- Product DomainはWeb Framework、ORM、分析libraryおよび移行用moduleへ依存しない。
- 因果推論library、機械学習libraryおよび可視化libraryはPort / Adapterの背後へ隔離する。
- Capability固有AdapterはGeneric Workflow Coreの状態遷移、transactionおよびArtifact commitを制御しない。

## ENH-E4 approved target architecture delta

### Current / Target boundary
CurrentのCausal/Family persistent lifecycle、複数claim、非対称Stage、複数ownership、typed/generic lineageはobserved baselineである。Approved Targetはone canonical Product runtime Execution authorityであり、family差はworkflow adapterへ限定する。

### Runtime responsibilities
Product API/workerがcanonical root。canonical repository/serviceがclaim/lease/state/terminal ownershipを持つ。persistent StageExecutionは全workflowへ適用する。GenericExecutorはsubordinate workflow infrastructureでありlifecycle ownerではない。

### Result, Artifact, Lineage
ExecutionResult/StageResultはsemantic levelであり、one Result ownership contractの下に置く。Artifact metadata authorityとphysical storeを分離する。typed structural lineageとgeneric-only lineageはrelationごとに排他的なauthorityとし、legacy ArtifactLineageはProduct authorityではない。

### Legacy, science, migration, CLI
legacy orchestration/runtime/persistenceはretire/archive boundaryで扱い、`ariadne.causal`、`ariadne.preprocessing`、`ariadne.shared`等のshared scientific capabilityは保持する。Product-only clean bootstrapは`product_migrations`を使いroot legacy migrationsを呼ばない。standalone low-level CLIはpersistent lifecycle外である。
