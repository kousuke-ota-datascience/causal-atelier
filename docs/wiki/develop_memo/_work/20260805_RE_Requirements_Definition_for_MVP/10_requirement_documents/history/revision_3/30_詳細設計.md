## 1. 実装方針

### 1.1 技術前提

- Python 3.12以上
- FastAPI等のASGI Web framework
- Pydantic等の型付きschema validation
- SQLAlchemy等のORM / SQL abstraction
- PostgreSQL
- 初期Artifact StoreはLocal filesystem
- WorkerはWeb APIとは別processとして起動する

製品要件は特定frameworkに依存しない。ここでの技術選択は初期実装の標準構成である。

### 1.2 実装原則

- Domain / ApplicationはWeb frameworkとORM modelへ直接依存しない
- Application ServiceはPortを介してPersistence、Artifact、Scientific Coreを利用する
- Entity更新とArtifact file書込みは完全な単一transactionにできないため、失敗補償を明示する
- 読取Projectionは正本Entityを変更しない
- batchはEntityではなくCommand結果とQuery条件として扱う

## 3. Domain Model

### 3.1 Entity class

各Entityは識別子とdomain invariantを持つ。ORM modelをDomain Entityとして直接公開しない。

主要method例:

| Entity | Method | 責務 |
|---|---|---|
| Project | `update_metadata()` | name、topic、objective、memo更新 |
| Execution | `mark_running()` | `QUEUED`から`RUNNING`へ遷移 |
| Execution | `mark_succeeded()` | 正常完了 |
| Execution | `mark_failed()` | 技術失敗情報を保持して終了 |
| Execution | `request_cancel()` | cancel要求を記録 |
| Execution | `increment_retry()` | 技術的retry回数更新 |
| GraphVersion | `apply_edit()` | DRAFT Graphを更新 |
| GraphVersion | `fix()` | DRAFTからFIXEDへ遷移 |
| Annotation | `update_content()` | statement、rationale、assumptions、limitations更新 |

### 3.2 Value Object

独立Entityにしないが型として定義する。

- `ExecutionSnapshot`
- `AnalysisSpec`
- `DiscoveryAnalysisSpec`
- `EstimationAnalysisSpec`
- `GraphDocument`
- `ScientificOutcome`
- `ArtifactDescriptor`
- `ComparisonView`
- `LineageView`

Value Objectは不変とし、canonical JSON生成機能を持つ。

## 4. Repository Port

### 4.1 Repository一覧

```python
class ProjectRepository(Protocol): ...
class DatasetVersionRepository(Protocol): ...
class ExecutionRepository(Protocol): ...
class ResultRepository(Protocol): ...
class ArtifactRepository(Protocol): ...
class GraphVersionRepository(Protocol): ...
class AnnotationRepository(Protocol): ...
```

共通的な汎用Repositoryを作らず、Entityごとの必要操作だけを定義する。

### 4.2 主要method

| Repository | Method |
|---|---|
| ProjectRepository | `add`, `get`, `update` |
| DatasetVersionRepository | `add`, `get`, `list_by_project`, `exists_hash` |
| ExecutionRepository | `add_many`, `get`, `list_by_project`, `claim_next`, `update` |
| ResultRepository | `add_many`, `get`, `list_by_execution`, `get_many` |
| ArtifactRepository | `add_many`, `get`, `list_by_execution`, `list_by_result` |
| GraphVersionRepository | `add`, `get`, `list_by_project`, `update` |
| AnnotationRepository | `add`, `get`, `update`, `list_by_target` |

### 4.3 Unit of Work

```python
class UnitOfWork(Protocol):
    projects: ProjectRepository
    dataset_versions: DatasetVersionRepository
    executions: ExecutionRepository
    results: ResultRepository
    artifacts: ArtifactRepository
    graph_versions: GraphVersionRepository
    annotations: AnnotationRepository

    def commit(self) -> None: ...
    def rollback(self) -> None: ...
```

Application Serviceの変更処理はUnit of Work境界内で実行する。

## 5. Application Service

### 5.1 ProjectDataService

主要use case:

- `create_project(command)`
- `update_project(command)`
- `register_dataset_version(command, uploaded_file)`
- `get_dataset_preview(query)`

Dataset登録sequence:

1. upload fileをtemporary領域へ保存
2. file type、size、schemaを検証
3. content hashとprofile summaryを生成
4. 同一Project / dataset key / hashの重複を検査
5. Artifact Storeへcommit
6. DB transactionでArtifact metadataとDataset Versionを保存
7. DB保存失敗時はcommit済みfileをorphanとして記録し、cleanup対象とする

### 5.2 ExecutionService

主要use case:

- `create_execution_batch(command)`
- `get_execution(execution_id)`
- `get_prefill(execution_id)`
- `request_cancel(execution_id)`
- `retry_execution(execution_id)`

Batch作成:

1. Project境界を検証
2. Dataset VersionとGraph Versionを解決
3. operation別Analysis Specをvalidation
4. variantごとにExecution Snapshotを生成
5. canonical hashを計算
6. 1 transactionで複数Executionを`QUEUED`として保存
7. batch keyとExecution ID群を返す

### 5.3 GraphVersionService

主要use case:

- `create_from_discovery_result(command)`
- `update_draft(command)`
- `fix_graph(graph_version_id)`

制約:

- source ResultはDiscovery Graphである
- DRAFTのみ変更可能
- FIXED後は新Graph Versionを作成する
- parent Graph指定時は同一Projectである

### 5.4 ComparisonQueryService

処理:

1. Result集合を取得
2. 同一Project、同一operationを検証
3. Execution Snapshotをcanonical pathへflatten
4. 全Executionで等しい値をcommon conditionsへ分類
5. 異なる値をchanged conditionsへ分類
6. operation別Result比較器でresult differencesを生成
7. warningとlineage summaryを付加

Comparisonは保存しない。

### 5.5 LineageQueryService

Resultを起点として次を辿る。

```text
Result
→ Execution
→ Dataset Version
→ input Graph Version [Estimation]
→ source Discovery Result
→ source Discovery Execution
→ Artifact
→ Annotation
```

循環参照が発生した場合は同一Entity IDの再訪を停止する。

## 6. Web API実装

### 6.1 Router責務

Routerは次だけを行う。

- path / header / bodyのparse
- authentication context取得
- schema validation
- Application Service呼出し
- Response schemaへの変換

Routerへdomain rule、SQL、Scientific Core呼出しを記述しない。

### 6.2 Schema変換

- Request schema → Application Command
- Domain Entity / Query View → Response schema
- Domain error → HTTP error

Pydantic model等は`interfaces/web_api/schemas`に配置し、Domain Entityから分離する。

## 7. Worker詳細設計

### 7.1 Execution claim

PostgreSQLを前提とする初期方式:

```sql
SELECT execution_id
FROM execution
WHERE status = 'QUEUED'
ORDER BY requested_at
FOR UPDATE SKIP LOCKED
LIMIT 1;
```

同一transaction内で`RUNNING`、`started_at`およびworker tokenを更新してcommitする。

worker tokenを論理Entity属性として公開する必要はなく、persistence上の内部columnとして保持してよい。

### 7.2 ExecutionProcessor sequence

1. Executionを再取得
2. cancel済みなら終了
3. Dataset Artifactを取得しhashを検証
4. Estimationの場合はGraph VersionとGraph Artifactを取得
5. Execution SnapshotをScientific Inputへ変換
6. Scientific Coreを呼び出す
7. Artifact候補をtemporary領域へ書き出す
8. Artifact Storeへ保存しhashを取得
9. DB transactionでResultとArtifact metadataを保存しExecutionを`SUCCEEDED`へ更新
10. temporary fileを削除

### 7.3 Failure compensation

| Failure | 処理 |
|---|---|
| 入力Artifact取得失敗 | ExecutionをFAILED、error summary保存 |
| Scientific Core技術例外 | log Artifact保存を試行し、FAILED |
| Artifact Store保存失敗 | DBへResultを保存せず、FAILED |
| Artifact保存後のDB失敗 | fileをorphan cleanup対象として記録、ExecutionはFAILED |
| Scientific negative outcome | Resultを保存し、ExecutionはSUCCEEDED |
| cancel要求 | safe pointで中止し、CANCELLED |

### 7.4 Retry

- retry可能なのは`FAILED`のみ
- Snapshotを変更しない
- retry countを増やして同一Executionを`QUEUED`へ戻す
- Algorithmやparameterを変更する場合は新Executionを作成する

## 8. Transaction設計

### 8.1 Transaction境界

| Use case | Transaction |
|---|---|
| Project作成・更新 | 1 DB transaction |
| Dataset Version metadata登録 | Artifact保存後、1 DB transaction |
| Execution Batch作成 | 全Executionを1 DB transactionで作成 |
| Graph Version作成・固定 | 1 DB transaction |
| Annotation作成・更新 | 1 DB transaction |
| Worker claim | 短い専用transaction |
| Worker Result保存 | Result、Artifact metadata、Execution statusを1 DB transaction |

### 8.2 Optimistic concurrency

Project、Graph Version、Annotationには`revision`列をpersistence内部属性として設けてもよい。更新Requestが古いrevisionの場合は競合Errorとする。

Execution SnapshotとFIXED Graphは更新禁止のため、optimistic update対象外である。

### 9.1 Domain Error

- `EntityNotFound`

- `InvalidAnalysisSpec`
- `GraphAlreadyFixed`

### 9.2 Infrastructure Error

- `ArtifactStoreUnavailable`
- `ArtifactHashMismatch`
- `DatabaseUnavailable`
- `ScientificCoreExecutionError`
- `QueueClaimError`

### 9.3 Error変換

Domain Errorは`23_API・インターフェース設計.md`のHTTP status / error codeへ変換する。Worker内のInfrastructure ErrorはExecution failureとして記録し、通常はAPI requestへ直接throwしない。

## 10. Scientific Core Adapter

### 10.1 責務

- Execution SnapshotからScientific Inputを組み立てる
- Dataset / Graph ArtifactをCoreが読める参照へ変換する
- Scientific OutputをResult候補とArtifact候補へ分割する
- Core固有例外を共通Infrastructure Errorへ変換する

### 10.2 禁止事項

- CoreからDB repositoryを呼ばない
- CoreからWeb API schemaを参照しない
- Core内でExecution statusを更新しない
- Core内でArtifactの最終保存先を決めない

## 11. CLI詳細設計

### 11.1 Command処理

1. config読込
2. schema validation
3. Dataset / Graph locationとhash取得
4. Scientific Core呼出し
5. local output directoryへArtifact保存
6. Manifest作成
7. 終了code返却

### 11.2 Exit Code

| Code | 意味 |
|---:|---|
| 0 | 技術的に正常完了。科学的負結果を含み得る |
| 2 | config / input validation error |
| 3 | input file / Artifact error |
| 4 | Scientific Core technical error |
| 5 | output write error |

科学的負結果はexit code 0とし、Manifestの`scientific_status`で表現する。

## 13. Logging・Observability

最低限、次をstructured logへ出力する。

- request ID
- execution ID
- project ID
- worker process ID
- operation
- algorithm / estimator
- status transition
- elapsed time
- exception type

Dataset row内容や機微な入力値をlogへ出力しない。

初期metric:

- Execution件数とstatus別件数
- queue待機時間
- execution時間
- technical failure率
- Artifact保存失敗数
