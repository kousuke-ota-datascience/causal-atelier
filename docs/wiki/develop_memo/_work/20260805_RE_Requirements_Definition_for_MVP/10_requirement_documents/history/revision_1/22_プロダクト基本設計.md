## 2. システム構成

初期版はモジュラーモノリスを基本とする。

```text
Analyst / Viewer
      |
      v
   Web App
      |
      v
 FastAPI Web API
   |      |       \
   |      |        \--> Artifact Store
   |      +-----------> Metadata DB
   |
   +--> Execution Queue / Worker
              |
              v
       Scientific Core
       ├── Discovery
       ├── Graph utilities
       ├── Identification / preflight
       ├── Treatment Effect Estimation
```

```text
Local CLI
  ├── Scientific Core

  ├── local Artifact
  └── MLflow adapter [optional]
```

## 3. アーキテクチャ原則

### 3.1 プロダクト層とScientific Coreを分離する

Scientific Coreは、Web、WorkerおよびCLIから再利用する。

- 数値実装をinterfaceごとに複製しない
- Metadata DBやFastAPIへの依存をScientific Coreへ持ち込まない
- optional ETL、Azure、S3等のAdapterをcore import時に要求しない

### 3.2 初期版は単純なExecutionモデルを使う

- 1 algorithm / parameter / estimator条件 = 1 Execution
- 複数条件は`batch_key`で束ねる
- WorkerはExecution単位で処理する
- 初期版ではStage / Attempt Entityを作らない
- retry回数とerror summaryはExecutionに保持する

### 3.3 Snapshotを正本とする

Execution submit時に、次をcanonical JSONとして固定する。

- objective / rationale
- Dataset Version
- Graph Version
- analysis specification
- algorithm / estimator
- parameters
- random seed
- code / runtime version

Execution後に元フォームを変更しても、過去Executionのsnapshotは変えない。

### 3.4 ComparisonとLineageはQuery Modelとする

ComparisonおよびLineageを独立CRUDモジュールにしない。

- Comparison APIは選択されたExecution / Resultから差分を生成する
- Lineage APIは明示参照を辿って表示用graphを生成する

### 3.5 WebとCLIのIdentityを分離する

Web/API:

- `execution_id`を持つ
- Queue、status、cancel、retryを管理する

CLI:

- Ariadne `execution_id`を生成しない
- manifest、hash、code version、Result、Artifactを保存する
- 初期版ではProject、AnnotationおよびWeb比較機能を重複実装しない

## 4. プロダクトモジュール

初期版の利用者向けモジュールは4つに限定する。

| Module | 主な責務 |
|---|---|
| Project / Data Workspace | Project目的、Dataset Version登録・確認、最近の分析 |
| Discovery Workspace | 条件設定、一括実行、Graph比較、Graph選定・簡易修正 |
| Inference Workspace | Causal Design、preflight、複数Estimator実行、diagnostics比較 |
| Results / Lineage Workspace | Result比較、判断メモ、来歴、Artifact、read-only共有 |

内部モジュール:

- Execution Service
- Comparison Query Service
- Lineage Query Service
- Artifact Service
- Scientific Core Adapter

## 5.3 Discovery Workspace

### 目的

同一Datasetに対する複数探索条件を実行・比較し、推論に使用するGraph Versionを決める。

### 画面構成

```text
左ペイン: 入力・実行条件
中央: Graph表示・重ね合わせ・差分
右ペイン: 条件差分、warning、採用・修正操作
下部: Execution status / Result table
```

### 入力

- Dataset Version
- objective
- rationale
- feature columns
- algorithm selection
- parameter grid
- random seed
- optional graph constraints

### 操作

- batch submit
- status refresh
- Result選択
- Graph比較
- Graph選定
- edgeの簡易追加・削除・方向変更
- edit rationale入力
- Graph Version FIXED

### 比較表示

**同一条件**

- Dataset Version
- feature set
- seed等

**変更条件**

- algorithm
- alpha
- independence test
- score / threshold
- constraints

**結果差分**

- graph type
- node / edge count
- edge追加・削除
- endpoint / direction変更
- warning
- runtime

### 制約

- PC / GES結果を一律DAGと表示しない
- Graph typeとendpoint semanticsを表示する

### 画面構成

### 操作

- assumptions / limitations記録

- Graph Version確認

- Execution snapshot確認

- manifest export
- read-only URLまたはProject共有

```text

→ Discovery Execution
→ Discovery Result
→ Graph Version
→ Estimation Execution
```

## 6. Web API基本設計

API resource数も初期Entityに合わせて限定する。

### 6.1 Project / Dataset

```text
POST   /projects
GET    /projects/{project_id}
PATCH  /projects/{project_id}

POST   /projects/{project_id}/dataset-versions
GET    /projects/{project_id}/dataset-versions
GET    /dataset-versions/{dataset_version_id}
GET    /dataset-versions/{dataset_version_id}/preview
```

### 6.2 Execution

```text
POST   /projects/{project_id}/execution-batches
GET    /executions/{execution_id}
POST   /executions/{execution_id}/cancel
POST   /executions/{execution_id}/retry
GET    /projects/{project_id}/executions
```

`execution-batches`は複数Executionを生成するcommand endpointであり、Batchを正本Resourceとして必須化しない。responseには`batch_key`と生成された`execution_ids`を返す。

### 6.3 Result / Comparison

```text
GET    /executions/{execution_id}/results
GET    /results/{result_id}
POST   /comparisons/query
GET    /results/{result_id}/lineage
```

### 6.4 Graph Version

```text
POST   /projects/{project_id}/graph-versions
GET    /projects/{project_id}/graph-versions
GET    /graph-versions/{graph_version_id}
POST   /graph-versions/{graph_version_id}/fix
```

DRAFT Graphの編集は`PATCH`または新Version作成commandとして実装する。FIXED後の上書きは禁止する。

### 6.5 Annotation / Artifact

```text
POST   /projects/{project_id}/annotations
PATCH  /annotations/{annotation_id}
GET    /artifacts/{artifact_id}
GET    /artifacts/{artifact_id}/download
POST   /results/{result_id}/export
```

## 7. Worker基本設計

### 7.1 処理単位

WorkerはExecutionを1件ずつ処理する。

```text
QUEUED
→ claim
→ RUNNING
→ Scientific Core実行
→ Artifact保存
→ Result保存
→ SUCCEEDED
```

技術例外時:

```text
RUNNING
→ error summary / log Artifact保存
→ FAILED
```

Scientific Coreが`NOT_IDENTIFIED`等を返した場合:

```text
RUNNING
→ Result(scientific_status=NOT_IDENTIFIED)保存
→ SUCCEEDED
```

### 7.2 Queue

初期版では次のいずれかを選ぶ。

- DB-backed queue: `execution.status=QUEUED`をWorkerがclaim
- 既存Queue Adapterを最小利用

Transactional Outbox、lease、heartbeatの完全モデルは初期必須にしない。ただし多重実行防止のclaim tokenまたはrow lockは必要とする。

## 8. Scientific Core interface

### 8.1 Discovery

```text
run_discovery(
  dataset_ref,
  algorithm,
  parameters,
  constraints,
  seed
) -> DiscoveryResultDTO
```

DTOは少なくとも次を返す。

- graph type
- node / edge / endpoint representation
- warnings
- diagnostics
- artifact payloads

### 8.2 Estimation

```text
run_estimation(
  dataset_ref,
  graph_ref,
  causal_design,
  estimator,
  parameters,
  seed
) -> EstimationResultDTO
```

DTOは少なくとも次を返す。

- scientific status
- estimate nullable
- uncertainty
- diagnostics
- warnings
- artifact payloads

Scientific CoreはMetadata Entityを直接保存しない。

## 11. 初期E2E処理フロー

### 11.1 Discovery

```text
Dataset Version選択
→ algorithm / parameter grid入力
→ batch command
→ 複数Execution作成
→ Worker実行
→ Result / Artifact保存
→ Comparison Query
→ Graph選定・修正
→ Graph Version FIXED
```

### 11.2 Inference

```text
Dataset Version + Graph Version選択
→ Causal Design入力
→ estimator群選択
→ batch command
→ 複数Execution作成
→ Worker実行
→ Result / Artifact保存
→ Comparison Query
→ Annotation記録
→ Lineage確認
```
