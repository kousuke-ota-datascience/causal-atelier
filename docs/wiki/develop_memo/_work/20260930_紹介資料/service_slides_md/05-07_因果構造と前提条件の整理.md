# 23. Slide 23｜因果構造と前提条件の整理

## 23.1. Message

**因果効果を推定するには、変数間の時間順序と役割を整理し、何を交絡として調整し、何を調整してはいけないかを明示する必要がある。**

## 23.2. Chart

**チャートタイトル:** DAGで整理する変数の役割

Messageを説明・論証するための主たる視覚表現として、以下の構造を採用する。

### 23.2.1. Chart Structure

- 既存の論理フロー／概念図を主チャートとして用い、要素間の関係・順序が一目で追える構造にする。

```text
      Confounder C
       ↙       ↘
Treatment T → Outcome Y
       ↓
   Mediator M

Collider例：T → Z ← U → Y
```

**PowerPoint上の配置・強調**

- 中央に簡潔なDAGを置き、Confounder / Mediator / Colliderを色分けする。
- ノード数は少なくし、概念理解を優先する。
- DAG自動生成のような表現は避ける。

### 23.2.2. Chart内の最小表示テキスト

実際のPowerPoint上では、以下のラベル・短文を中心に表示する。Supporting Logicの全文をスライド上へ掲載しない。

- Confounder C
- ↙       ↘
- Treatment T → Outcome Y
- Mediator M
- Collider例：T → Z ← U → Y

## 23.3. Supporting Logic

- Confounder：TreatmentとOutcomeの双方へ影響し、調整対象候補となる。
- Mediator：Treatment効果の経路上にあり、Estimandによっては調整すると意味が変わる。
- Collider：不適切に条件付けするとBiasを導入し得る。
- Temporal Ordering：Treatment後に決まる変数をPre-treatment covariateとして扱わない。
- DAGは真実を自動発見するものではなく、Domain Knowledgeとデータ生成過程の仮定を可視化する道具として使う。

**旧Key Messageから保持する補足論点**

> **因果分析では「変数を多く入れるほど安全」ではなく、因果構造に基づいて調整変数を選ぶ。**

> この補足はMessageとは別の第二メッセージとして扱わず、Messageを支える論点としてのみ使用する。
