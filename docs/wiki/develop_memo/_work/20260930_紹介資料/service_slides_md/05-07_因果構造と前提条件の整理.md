# 24. Slide 24｜因果構造と前提条件の整理

## 24.1. Message

**因果効果を推定するには、変数の時間順序と因果上の役割を分け、Estimandに応じて「何を調整するか」を設計する必要がある。**

## 24.2. Chart

**チャートタイトル:** 同じ「関連変数」でも、因果上の役割でAdjustmentは変わる

### 24.2.1. Chart Structure

Confounder / Mediator / Colliderを一つのDAGへ混在させず、3つの独立した最小DAGを横並びで比較する。

```text
A｜Confounding                 B｜Mediation                  C｜Collider

    C                               T                          T      U
   ↙ ↘                              ↓ ↘                         ↘    ↙ ↓
  T → Y                             M → Y                         Z    Y

Pre-treatment C                 Post-treatment M              ZにConditioningすると
TとY双方に影響                 Treatment経路上                非因果Pathを開き得る
        ↓                              ↓                           ↓
Adjustment候補                 Total Effectでは               原則として安易に
                              安易に調整しない                 調整しない
```

最下部にTemporal Orderingの帯を置く。

```text
Pre-treatment ---------------- Treatment ---------------- Post-treatment
         変数の役割を時間順序とEstimandから判断する
```

**PowerPoint上の配置・強調**

- 3つのDAGカードを同じ大きさで横並びにする。
- 各カードは `構造 → 役割 → Adjustment上の含意` の順で読む。
- Confounderだけを「Adjustment候補」として強調し、Mediator / Colliderは「入れれば安全ではない」ことを対比する。
- 下段にTemporal Orderingを置き、Treatment後に決まる変数をPre-treatment Covariateと同様に扱わないことを示す。
- DAGはDomain Knowledge / Data Generating Processに関する仮定の可視化であり、自動的に真の因果構造を発見する図として描かない。

### 24.2.2. Chart内の最小表示テキスト

- **Confounder**｜TとYの双方に影響
- → Adjustment候補
- **Mediator**｜Treatmentの効果経路上
- → Total Effectでは安易に調整しない
- **Collider**｜複数の原因が合流
- → ConditioningでBiasを導入し得る
- Pre-treatment → Treatment → Post-treatment
- **変数を多く入れるほど安全、ではない**

## 24.3. Supporting Logic

- ConfounderはTreatmentとOutcome双方の原因となる変数で、Backdoor Pathを閉じるためのAdjustment候補となる。ただし具体的なAdjustment SetはDAG全体とEstimandに依存する。
- MediatorはTreatmentからOutcomeへの因果経路上にある。Total Effectを対象とする分析でMediatorへConditioningすると、推定対象を変えたりBiasを導入したりする可能性がある。Direct / Indirect Effectを対象にする場合は別のEstimandと追加Assumptionが必要になる。
- Colliderは複数の変数から矢印が入る変数で、不適切にConditioningすると閉じていた非因果Pathを開き、Selection Biasを導入し得る。
- Treatment後に決まるPost-treatment Variableを、単にPrediction性能が高いからという理由でAdjustmentへ入れない。
- 「利用可能な変数をすべて回帰式へ入れる」という変数選択は、因果推論では安全策にならない。
- DAGは仮定を可視化し、必要なAdjustmentや識別条件を議論する道具である。データだけから真のDAGを一意に確定する装置ではない。
- 実務ではDomain ExpertとData Scientistが、施策割付、データ取得時点、業務Processを照合しながらCausal Structureを設計する。

## 24.4. Speaker Note

因果分析では、Outcomeと関連している変数をすべて入れれば良いわけではありません。たとえばTreatmentとOutcomeの両方に影響するTreatment前のConfounderは調整候補になります。一方、Treatment後に生じるMediatorを調整すると、知りたいTotal Effectそのものが変わる場合があります。Colliderへの条件付けは、逆に存在しなかったBiasを作ることがあります。

そのため、変数名や相関の強さだけではなく、いつ決まり、TreatmentやOutcomeとどのような関係にあるかを業務知識と合わせて整理します。DAGは、その仮定を関係者で確認できる形にするための道具として使います。
