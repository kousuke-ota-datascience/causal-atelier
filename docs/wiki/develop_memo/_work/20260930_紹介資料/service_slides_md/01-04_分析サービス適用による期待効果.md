# 4. Slide 4｜分析サービス適用による期待効果

## 4.1. Message

**分析結果を業務Actionへつなげ、収益向上・コスト削減・ROI改善へ接続する。**

## 4.2. Chart

**チャートタイトル:** 予測分析・因果推論が生み出す業務効果

Slide 3で示したPredictive / Causalの違いを、顧客にとっての具体的なBusiness Outcomeへ接続する。左右対称のValue Chainで、**分析結果 → 業務Actionの最適化 → 直接的な業務改善 → 期待されるBusiness Outcome**の順に示す。

売上向上率、コスト削減率、ROI等の具体的な数値は案件固有の条件に依存するため記載せず、どのような効果につながり得るかという効果の種類を示す。

## 4.3. Supporting Logic

### 4.3.1. Slide 4の役割

- Slide 1ではPredictive / Causalがそれぞれ「将来の見通し」「施策の効果」という判断材料を提供することを示した。
- Slide 2では、業務課題を「何を知りたいか」へ落とし込み、その問いによってPredictive / Causalを選ぶことを示した。
- Slide 3では、両者は推論対象・成立条件・評価基準まで異なることを示した。
- Slide 4では、その違いを再説明するのではなく、**分析結果を業務Actionへ利用することで、どのような具体的Business Outcomeにつながり得るか**を示す。
- 想定読者は予測分析・因果推論のPoC活用を検討する顧客側関係者であるため、抽象的な「意思決定能力の向上」だけで終わらず、自社業務へマッピングしやすい即物的な期待効果まで示す。
- 一方で、案件固有の条件なしに効果量を保証しない。示すのは「期待される効果の種類」と、その効果へ至る論理経路である。

### 4.3.2. PredictiveからBusiness Outcomeへの接続

- Predictiveは、設備状態、停止リスク、解約確率、品質指標、消費電力量等の将来・未知のOutcomeを予測・推定する。
- 予測結果を結果発生前に利用することで、保守・点検の対象や時期、要員配置、対応対象、運転計画等のActionを変更できる。
- 例えば機材の停止リスクを実運用上十分な性能で予測できれば、高リスクな機材を優先して点検・保守し、突発停止や過剰な予防保全を減らせる可能性がある。
- この場合のValue Chainは、**停止リスク予測 → 保守・点検対象の優先順位付け → 突発停止・過剰保全の削減 → 停止損失・保守コストの削減 → 稼働率・生産性向上**となる。
- 解約予測では、高リスク顧客を事前に把握して対応対象の優先順位を変えることで、限られた対応リソースを重点対象へ配分できる。
- したがってPredictiveのBusiness Valueは、予測精度そのものではなく、**予測を利用して時期・対象・対応を変えた結果として生じる業務改善**にある。

### 4.3.3. CausalからBusiness Outcomeへの接続

- Causalは、施策・介入を変えたときにOutcomeがどの程度変化するかという因果効果を、明示した前提のもとで推定する。
- その情報を利用することで、施策を実施するか、継続するか、変更するか、どの対象へ施策を適用するか、どの施策へ予算・人員を優先配分するかを判断できる。
- 例えば顧客施策で対象ごとの効果差を妥当に評価できれば、効果が期待される顧客群へ施策を集中し、効果が乏しい顧客群への不要な施策配信を減らせる可能性がある。
- この場合のValue Chainは、**施策効果推定 → ターゲティング最適化 → 不要施策の削減・有効対象への集中 → 施策費削減 / 増分収益向上 → 施策ROI改善**となる。
- 複数施策を比較する場合は、単なる平均Outcomeの差ではなく、対象とするEstimandとIdentification Assumptionのもとで介入効果を評価し、その結果を投資配分や施策ポートフォリオの見直しへ接続する。
- したがってCausalのBusiness ValueはEffect Estimateそのものではなく、**効果情報を使って施策・対象・投資配分を変えた結果として生じる業務改善**にある。

### 4.3.4. 期待効果は業務ドメインによって異なる

- 同じPredictive / Causalでも、最終的なBusiness Outcomeは適用業務によって異なる。
- Predictiveでは、設備保全、エネルギー管理、品質管理、顧客対応、審査等の業務で、停止損失削減、保守・対応コスト削減、稼働率改善、品質改善、リスク低減等につながり得る。
- Causalでは、マーケティング、CRM、価格・販促、プロダクト施策、業務施策等で、施策費削減、増分収益向上、ROI改善、継続率改善等につながり得る。
- 本スライドでは特定業界・業務へ限定せず、顧客が自社のユースケースを想起しやすい代表例を提示する。

### 4.3.5. 分析結果とBusiness Outcomeを直接同一視しない

- 予測精度が向上しただけでは、停止損失削減やコスト削減は発生しない。予測結果を利用して保守、配置、対応優先順位等のActionが変わる必要がある。
- 因果効果を推定しただけでも、ROI改善は発生しない。推定結果を利用して施策選択、ターゲティング、投資配分等のActionが変わる必要がある。
- さらに、Actionを変えた場合でも、実際のBusiness Outcomeは市場環境、業務制約、実装品質、運用定着等の影響を受ける。
- そのため本資料では、収益向上・コスト削減・ROI改善等を**期待効果の種類**として示し、案件固有のデータや検証なしに効果量を保証しない。

### 4.3.6. Why Usへの接続

- 本スライドで示すBusiness Outcomeは、分析手法を適用するだけで自動的に得られる便益ではない。
- 価値を生むには、業務課題から適切な問いを定義し、その問いに合ったPredictive / Causalの分析を設計し、得られた結果を具体的なDecision / Actionへ接続する必要がある。
- Predictiveでは、単に高精度なモデルを作るだけでなく、どの予測を誰がどの業務判断に使うかまで設計する必要がある。
- Causalでは、単にEffect Estimateを算出するだけでなく、Causal Question / Estimand、Identification Assumption、推定・診断を整合的に設計し、施策選択やターゲティング等のActionへ接続する必要がある。
- したがって次のSlide 5では、**分析手法の適用に閉じず、業務課題から分析・Actionまでを一貫して設計・検証する当チームの支援価値**を示す。

## 4.4. Speaker Note

ここまで、PredictiveとCausalでは答える問いや分析上の前提が異なることを説明しました。では、それを実際の業務へ使うと何が良くなるのでしょうか。

Predictiveでは、将来の設備状態や停止リスク、解約リスク、品質指標等を事前に予測することで、対応する時期・対象・内容を変えられます。例えば機材の停止リスクを予測して保守・点検の優先順位を変えれば、突発停止による損失を減らしながら、不要な保守コストを抑え、稼働率や生産性の向上につなげられる可能性があります。

一方Causalでは、「誰に、どの施策を実施すると、どの程度Outcomeが変わるか」を評価します。例えば施策効果に対象ごとの差がある場合、効果が期待される対象へ施策を集中し、効果が乏しい対象への不要な施策を減らすことで、施策費を抑えながら増分収益を高め、施策ROIを改善できる可能性があります。

このように、顧客にとって重要なのは予測精度やEffect Estimateそのものではなく、それを業務Actionへ使った先にある収益向上、コスト削減、ROI改善といった成果です。

ただし、分析を実施すれば自動的にこれらの効果が得られるわけではありません。予測結果や因果効果を受けて、保守、配置、対応優先順位、ターゲティング、施策選択等のActionを実際に変えられることが必要です。また効果量は案件ごとのデータや業務条件に依存するため、この段階で特定の売上向上率や削減率を保証するものではありません。

つまり、価値につなげるには分析手法だけでなく、業務課題から問いを定義し、適切な分析を設計し、その結果を実際のActionへ接続するところまで一貫して考える必要があります。次に、その一連のプロセスに対して当チームがどのような価値を提供できるのかをご説明します。
