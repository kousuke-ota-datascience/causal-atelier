# 4. Slide 4｜分析サービス適用による期待効果

## 4.1. Message

**予測分析は「先回りして資源を配分する力」を、因果推論は「効果のある施策へ資源配分する力」を高める。**

## 4.2. Chart

**チャートタイトル:** 予測分析と因果推論が変える資源配分の判断

Slide 3で示したPredictive / Causalの分析上の違いを、顧客にとっての業務上の価値へ接続する。左右対称のValue Chainで、**得られる情報 → 変えられるDecision / Action → 期待される意思決定能力**の順に示す。

売上向上・コスト削減等の最終的なBusiness Outcomeを分析サービスの直接効果として置かず、分析結果を使って業務上のActionを変えられることを価値発現の条件として明示する。

### 4.2.1. Chart Structure

PowerPoint上では、Predictive / Causalを左右に並べた2本のValue Chainとする。

各列を、以下の3段階で上から下へ読ませる。

1. 分析から得られる判断材料
2. 判断材料によって変えられるDecision / Action
3. 期待される意思決定能力

```text
┌──────────────────────────────┬──────────────────────────────┐
│ 予測分析 / Predictive       │ 因果推論 / Causal            │
├──────────────────────────────┼──────────────────────────────┤
│ 将来の見通し                │ 施策の効果                    │
│              ↓               │              ↓               │
│ 対象・時期・量の             │ 実施・継続・変更する           │
│ 優先順位を変える             │ 施策の優先順位を変える         │
│              ↓               │              ↓               │
│ 先回りして                   │ 効果のある施策へ               │
│ 資源を配分する力             │ 資源を配分する力               │
└──────────────────────────────┴──────────────────────────────┘
                         ↓
        Actionが変わることで、業務効果につながる
```

**PowerPoint上の配置・強調**

- Predictive / Causalは同じ視覚ウェイトで左右対称に配置する。
- 最上段はSlide 1〜3との連続性を保ち、Predictiveを「将来の見通し」、Causalを「施策の効果」とする。
- 中段は分析処理ではなく、分析結果を受けて変えられる業務上のDecision / Actionを置く。
- Predictiveでは「対象・時期・量の優先順位を変える」、Causalでは「実施・継続・変更する施策の優先順位を変える」とし、両者とも資源配分の判断へ接続する。
- 下段ではMessageそのものを回収し、Predictiveを「先回りして資源を配分する力」、Causalを「効果のある施策へ資源を配分する力」と強調する。
- 最下部に左右共通の補足として「Actionが変わることで、業務効果につながる」を配置する。ただし、売上向上率、コスト削減率、ROI等の具体的数値は案件固有の条件なしには記載しない。
- Causal側の「効果のある施策」は、因果推論によって無条件に真の効果が確定するという意味ではない。対象とするEstimand、Identification Assumption、不確実性等を踏まえて、効果が支持される施策を意思決定に利用するという意味で用いる。

## 4.3. Supporting Logic

### 4.3.1. Slide 4の役割

- Slide 1ではPredictive / Causalがそれぞれ「将来の見通し」「施策の効果」という判断材料を提供することを示した。
- Slide 2では、業務課題を「何を知りたいか」へ落とし込み、その問いによってPredictive / Causalを選ぶことを示した。
- Slide 3では、両者は推論対象・成立条件・評価基準まで異なることを示した。
- Slide 4では、その違いを再説明するのではなく、**それぞれの分析結果をDecision / Actionへ使うと、どのような意思決定能力を高められるか**を示す。
- Predictive / Causal各論で扱う具体的な適用課題や詳細な期待効果は後続章に譲り、本スライドでは資料冒頭の共通価値として資源配分の観点に集約する。

### 4.3.2. Predictiveが高める意思決定能力

- Predictiveは、需要、リスク、発生確率、数量等の将来・未知のOutcomeに関する見通しを提供する。
- その見通しを結果が起きる前に利用できれば、対象、時期、数量、要員、在庫、予算等の配分を事前に変えられる。
- したがって主要な期待効果は、単に「予測精度が高いこと」ではなく、**限られた資源を、必要になる可能性が高い対象・時期・量へ先回りして配分しやすくなること**にある。
- 例えば、高リスク対象への対応優先度、将来需要に応じた在庫・生産量、繁忙予測に応じた要員配置等の判断へ接続できる。
- ただし、予測結果が得られても、それを受けて変更可能なActionがなければ業務価値は限定される。

### 4.3.3. Causalが高める意思決定能力

- Causalは、施策・介入を変えたときにOutcomeがどの程度変化するかという効果を、明示した前提のもとで推定する。
- その情報を利用することで、施策を実施するか、継続するか、変更するか、どの施策へ優先的に予算・人員を投じるかを判断しやすくなる。
- したがって主要な期待効果は、単に「Effect Estimateを得ること」ではなく、**限られた資源を、効果が支持される施策へ優先的に配分しやすくなること**にある。
- 効果の大きさだけでなく、不確実性、適用対象、前提の妥当性、実施コスト等を合わせてDecision / Actionを設計する必要がある。
- 観測データを用いる場合を含め、因果推論によって効果が無条件に確定するわけではない。どの前提のもとでどこまで効果を主張できるかを明示する必要がある。

### 4.3.4. 分析結果とBusiness Outcomeの間にはActionがある

- 予測値、予測確率、Effect Estimate等は、それ自体が売上向上、コスト削減、ROI改善等のBusiness Outcomeではない。
- 分析結果が価値を持つためには、誰が、いつ、どの結果を見て、どのDecision / Actionを変えるかが定義されている必要がある。
- そのActionが実際に変わり、業務プロセスへ反映された先に、売上、コスト、品質、リスク、顧客体験等のBusiness Outcomeが生じ得る。
- したがって、案件固有のデータ、運用条件、Action設計を確認せずに、分析サービス単体の効果率やROIを保証しない。

### 4.3.5. PoCで検証すべきことへの接続

- 本スライドで示す期待効果は、分析手法を適用すれば自動的に得られる便益ではない。
- 実際には、必要な判断材料を妥当に生成できるか、その結果を利用可能なDecision / Actionへ接続できるかを確認する必要がある。
- したがってPoCでは、モデルや推定値を作成することだけでなく、**業務上の意思決定に使える情報を再現可能な形で得られるか**を検証対象とする必要がある。

## 4.4. Speaker Note

ここまで、PredictiveとCausalでは答える問いだけでなく、推論対象や前提、評価方法まで異なることを説明しました。この違いは、業務上の価値にもそのままつながります。

Predictiveで得られるのは将来の見通しです。例えば、どの対象でリスクが高そうか、いつ需要が増えそうか、どの程度の数量が必要になりそうかが事前に分かれば、結果が起きる前に人員、在庫、予算、対応対象等の配分を変えられます。つまりPredictiveの価値は、先回りして資源を配分する力を高めることにあります。

一方Causalで得たいのは、施策を変えたときにOutcomeがどう変わるかという効果です。その情報があれば、どの施策を実施・継続・変更するか、どこへ予算や人員を優先投入するかを判断しやすくなります。つまりCausalの価値は、効果が支持される施策へ資源を配分する力を高めることにあります。

ただし、分析結果そのものが売上向上やコスト削減を生むわけではありません。分析結果を受けて業務上のActionを実際に変えられることが、価値が発現する条件です。そのため案件固有の条件を確認せずに、削減率やROI等を分析サービスの直接効果として約束することはしません。

この点から、PoCで本当に確かめるべきことも見えてきます。モデルや推定値を作れるかだけではなく、意思決定に使える情報を妥当に、再現可能な形で得られるかを検証する必要があります。

## 4.5. Slide 4からSlide 5への接続

> **期待効果は、分析結果をDecision / Actionへ接続できて初めて生まれる。ではPoCでは、モデルや推定値の作成を超えて何を検証すべきか。**
