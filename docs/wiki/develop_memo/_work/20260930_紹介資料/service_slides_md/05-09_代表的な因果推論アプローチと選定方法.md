# 26. Slide 26｜代表的な因果推論アプローチと選定方法

## 26.1. Message

**因果推論は手法名から選ぶのではなく、Treatmentの割付・時間・制度・交絡情報からIdentification Strategyを選定する。**

## 26.2. Chart

**チャートタイトル:** Data Generating ProcessからIdentification Strategyを選ぶ

### 26.2.1. Chart Structure

「データ・制度上の構造 → Identificationの考え方 → 主なAssumption」を主表とし、Estimator例は別列へ分離する。

| データ・制度上の構造 | Identification Strategy | 主なAssumption / 成立条件 | Estimation例 |
|---|---|---|---|
| Randomized Assignmentが可能 | Randomized Comparison / RCT / A-B Test | Randomization、Consistency等 | 群平均差、Regression等 |
| 必要なPre-treatment Confounderを観測 | Backdoor / Covariate Adjustment | Conditional Exchangeability、Positivity、Consistency | G-formula / Regression、Weighting、Matching、DR |
| Treatment前後 + 比較群がある | Difference-in-Differences | Parallel Trends等 | DiD Estimator / Regression等 |
| AssignmentがThresholdで決まる | Regression Discontinuity | 閾値近傍のContinuity、Manipulationがない等 | Local Regression等 |
| Valid Instrumentがある | Instrumental Variable | Relevance、Independence、Exclusion等 | Wald / 2SLS等 |
| Single Treated Unit + Donor Pool + Time | Synthetic Control | 適切なCounterfactualをDonorから構成可能等 | Synthetic Control Estimation |

- 左から `Data / Assignment` → `Identification Strategy` → `Assumption` の3列を主表示とする。

## 26.3. Supporting Logic

### 26.3.1. Slide 26の役割

- Slide 25ではIdentificationとEstimationを別問題として整理した。
- **Slide 26では、実案件のData Generating ProcessからどのIdentification Strategyが候補になるかを、成立条件とセットで比較する。**
- 主題は因果推論手法の網羅的カタログではなく、「どの比較構造を利用できるか」を先に判断する選定原則である。
- 次のSlide 27では、選択したStrategyに応じたDiagnostics / Refutation / Sensitivityを行い、EffectのClaim ScopeをEvidence Stackとして判断する。

### 26.3.2. Randomized Comparison｜Treatment AssignmentをDesignで制御できる場合

- Randomized Experiment / A-B Testでは、Treatment AssignmentをRandomizeすることで、平均的にTreatment以外の要因を群間でBalanceさせる。
- これにより比較可能性をDesign段階で作れるため、介入可能な案件では有力な候補となる。
- ただしRandomizationしただけで全ての問題が解消するわけではない。Noncompliance、Attrition、Missing Outcome、Interference、Cluster Assignment、Multiple Testing等は別途設計・分析が必要である。
- ITTを知りたいのか、Treatment ReceivedのEffectを知りたいのかでもEstimandは異なる。

### 26.3.3. Backdoor / Covariate Adjustment｜必要なConfounderを観測できる場合

- Observational Dataで、TreatmentとOutcomeの双方へ影響するPre-treatment Confounderを十分に観測できると仮定する場合、Covariate Adjustmentが候補になる。
- 中心AssumptionはConditional Exchangeability、Positivity、Consistency等である。
- `Covariateが多い = Exchangeabilityが成立` ではない。重要な未観測Confounderが残ればBiasは解消しない。
- Positivityが弱い場合、極端なWeightやExtrapolationが発生し、実質的に比較できないPopulationが生じる。
- Identification後のEstimatorとしてOutcome Regression / G-formula、Weighting、Matching、Doubly Robust等を選択できる。

### 26.3.4. Difference-in-Differences｜前後変化とComparison Groupを利用する場合

- DiDはTreatment GroupとComparison GroupのTreatment前後の変化差を利用してCounterfactual Trendを構成する。
- 代表的なAssumptionはParallel Trendsであり、Treatmentがなければ両群のOutcome Trendが同様に推移したと考えられることが必要になる。
- Pre-treatment TrendやEvent-studyは重要なDiagnosticだが、Treatment後のCounterfactual Trendを証明するものではない。
- Staggered Adoption、Treatment Effect Heterogeneity、Anticipation等がある場合、単純Two-way Fixed Effectsの解釈に注意する。

### 26.3.5. Regression Discontinuity｜ThresholdによるAssignmentを利用する場合

- RDはScore等のThresholdを境にTreatment Assignmentが変わる制度設計を利用する。
- Threshold近傍でPotential Outcomeが滑らかに変化し、対象がThresholdを精密操作していない等の条件が重要になる。
- 一般に推定されるEffectはThreshold近傍のLocal Effectであり、Population全体へ無条件にGeneralizeしない。
- Bandwidth、Functional Form、Manipulation Check、Covariate Continuity等を確認する。

### 26.3.6. Instrumental Variable｜Treatmentの外生変動を利用する場合

- IVはTreatmentへ影響するが、OutcomeへはTreatmentを介してのみ影響するようなInstrumentを利用する。
- Relevance、Independence、Exclusion Restriction等の強いAssumptionが必要である。
- Instrumentの妥当性はDomain / Institutional Knowledgeに依存する部分が大きく、統計検定だけで完全に証明できない。
- Binary Instrument等ではMonotonicity等のもとでLATEとして解釈される場合があり、対象Populationの範囲を明示する。

### 26.3.7. Synthetic Control｜少数UnitのInterventionを時系列比較する場合

- Synthetic Controlは単一または少数のTreated Unitについて、Donor Poolの組み合わせからCounterfactual Trajectoryを構成する。
- Policy導入、地域施策、企業単位の介入等で候補になる。
- Pre-treatment Fit、Donor Poolの妥当性、Concurrent Shock、Spillover等を確認する。
- Placebo-in-space / timeやDonor Sensitivity等を用いて結果の頑健性を評価する。

### 26.3.8. Causal MLの位置づけ

- Causal Forest、Meta-learner、Double / Debiased ML等は、Flexible nuisance modelingやHeterogeneous Effect Estimationで有用になり得る。
- しかし、未観測Confounding、Invalid Instrument、Parallel Trends違反等のIdentification Failureを自動的に解消するものではない。
- Causal MLを選ぶ場合も、どのEstimandをどのIdentification Assumptionで推定しているかを先に明示する。
- Algorithmic sophisticationとCausal validityを混同しない。

### 26.3.9. Strategy Selectionの実務フロー

案件初期では、概ね以下の順に確認する。

1. **Randomizeできるか**：可能ならExperiment Designを優先候補とする。
2. **Assignment Ruleは何か**：誰が何を基準にTreatmentを受けたか。
3. **Pre-treatment Confounderを観測できるか**：Covariate Adjustmentの可能性。
4. **Temporal / Comparison Structureがあるか**：DiD、Synthetic Control等の可能性。
5. **Threshold / Instrument等の外生変動があるか**：RD / IVの可能性。
6. **Assumptionを業務知識から説明できるか**：説明不能ならMethod適用を急がない。
7. **EstimandとStrategyが一致しているか**：Local Effect等を全体Effectへ読み替えない。

- 複数Strategyが候補になる場合、異なるAssumptionで結果をTriangulateすることもある。
- ただし複数Methodで同じ符号が出たことだけをCausal Validityの証明とはしない。

## 26.4. Speaker Note

因果推論の手法は、モデル精度のランキングのように一列に並べて選ぶものではありません。最初に見るのは、Treatmentがどう割り付けられたか、時間構造や制度上のRuleがどうなっているかです。

TreatmentをRandomizeできるならA/B Testのように比較可能性をDesignできます。Randomizeできなくても、必要なTreatment前のConfounderを観測できるならCovariate Adjustmentを検討できます。Policy導入前後と比較群があるならDiD、ThresholdでAssignmentが変わるならRD、外生的なInstrumentがあるならIVというように、利用できる構造によってIdentification Strategyが変わります。

重要なのは、各Strategyに前提条件があることです。DiDならParallel Trends、IVならExclusion Restrictionなど、その前提が業務Processと整合するかを確認します。Method名を選んだだけでは因果効果にはなりません。

また、RegressionやWeighting、Matchingは、Covariate Adjustment等でEffectが識別された後に、有限標本からどう推定するかというEstimation側の選択肢です。この順序を分けることで、「Propensity Scoreを使ったから因果推論」という説明を避けます。

Causal MLも同じです。複雑な異質効果を推定する能力はありますが、Identification Assumptionそのものを消すことはできません。案件ごとにData Generating Processを理解し、その構造に合うStrategyを選ぶことが中心です。
