```text

Competitive
= 十分競争可能。ただし構造的優位は未確認

Relative Weak候補
= 対応可能だが、他ProviderのBusiness ModelがよりFitしやすい可能性
```

## A01-04h.3. Supporting Logic

### A01-04h.3.1. このSummaryは何をまとめたものか

A01-04a〜gは、単純にProviderを「強い / 弱い」で固定評価したものではない。

各Profileについて、

```text
Deal Profile
    ↓
この商談で重くなるCustomer Selection Criteria
    ↓
Provider類型のCapability / Operating ModelとのFit
    ↓
当チームのPosition
```

の順で評価している。

この考え方の根底には、B2B購買が状況非依存の固定評価ではないというOrganizational Buying / BUYGRID / B2B Customer Journeyの知見がある。[T1][T2][T3][T8]

従って本Summaryは、

> 「SIerは常にDeliveryが強い」
> 「DS専門会社は常に分析が強い」

という固定Score表ではなく、**Deal条件に応じてどのCapabilityが顧客価値へ変換されるか**を整理したものである。

### A01-04h.3.2. Selection Criteriaの理論的土台

本資料で使用する主要Selection Criteriaは、単一の既存理論ではなく、以下を統合した分析フレームである。

- Webster & Wind：Organizational Buying / Buying Center。[T1]
- Sheth：複数購買関係者、Quality / Delivery / Price等のExpectation、Perceived Risk。[T2]
- Pemer & Skjølsvik：Professional ServiceのResource / Delivery / Relational QualityとQuality Signals。[T4]
- Patterson：Management Consultancy選定でReputation / Client-industry Experience / Feesが重要。[T5]
- Williamson / David & Han：Dependency / Governance / Transaction Riskを考えるTCE。[T6][T7]

したがって、A01-04a〜gで使う`Fit / Capability / Delivery / Economics / Risk / Evidence / Governance / Organizational Acceptability`は、これらを分析PoC購買へ翻訳した**当資料の統合フレーム**であり、学術研究に存在する固有の「8-factor model」ではない。

### A01-04h.3.3. Provider Positionの根拠

Provider類型のPositionは、学術研究が「このDealではこのProviderが1位」と実証したものではない。

以下の2段階で推論している。

**Step 1｜Providerが実際に何をOfferingとして持つか**

- BrainPad：専門人材によるData Analysis / Consulting等。[P1]
- Deloitte：AI Strategy / Data Modernization / bespoke AI solution / Engineering等。[P2]
- Accenture：Data & AI Strategy / Build / Scale / Cloud Data等。[P3]
- NTT DATA：AI Strategy / PoC / Model Training / Application Integration等。[P4]
- Palantir：Platform上でData / Model / Ontology / Workflow / Operational Applicationを統合。[P5]

**Step 2｜そのCapabilityが各Deal ProfileのSelection Criteriaへどう効くか**

この部分が当資料の分析仮説である。

例：

- 高Implementation Coupling → Delivery / RiskのWeightが上がる → SIer Capabilityが価値化しやすい
- 高Problem Novelty → Fit / Capability / EvidenceのWeightが上がる → Specialist Capabilityが価値化しやすい
- 高Standardizability → Reuse / Economics / Time-to-Valueが効く → Product Assetが価値化しやすい

このStep 2は、理論に基づく推論であり、Provider類型の市場順位を直接実証したものではない。

### A01-04h.3.4. Summaryから見える当チームの重点候補

A01-04a〜gを横断すると、当チームのPositionは一様ではない。

最もCapability Bundle全体が活きやすい候補は、

1. **高度分析 × Enterprise接続**
2. **高Novelty × Analytical PoC**
3. **High Criticality / GovernanceのうちAnalytical Complexityも高い案件**

である。

共通項は、

> **定型Solutionをそのまま適用しにくく、Question / Assumption / Evaluationを個別設計する必要があり、かつ分析結果をEnterprise環境で使う条件を無視できないこと**

である。

### A01-04h.3.5. なぜ当チームのCapability BundleとFitするのか

当チームの確認済みCapabilityは、

- Predictive / Causalを問いから使い分ける
- Scratch / mature OSSで非定型に設計する
- CausalではQuestion / Estimand / Assumption / Identification等を必要に応じて分ける
- Predictiveではunknown-data performance / calibration / error pattern等を必要に応じて評価する
- 特定Product導入を必須前提としない
- SIer内の分析組織としてEnterprise Contextを考慮できる

である。

したがって、Analytical Complexity / Problem Noveltyが高いほど前半のSpecialist Analyticsが、Implementation Coupling / Criticalityが高いほど後半のEnterprise Baseが価値化しやすい。

この交差領域を重点候補と置くことには内部整合性がある。

### A01-04h.3.6. それでも「Relative Advantage」ではない

このSummaryで最も重要な留保は、

> **Own Capability FitとCompetitive Advantageを混同しないこと**

である。

高度分析 × Enterprise接続は、当チームにFitする一方、NTT DATA型SIer AnalyticsやDeloitte / Accenture型Consulting AnalyticsもCapability上は十分参入できる。[P2][P3][P4]

高Novelty Analytical PoCでは、BrainPad型DS Specialistも強いCandidateになり得る。[P1]

したがって`Core Candidate`は、

> 「このProfileなら競合より強い」

ではなく、

> **「このProfileは当チームのCapability Bundleが最も価値化しやすく、Relative Advantageの有無を最優先で検証すべき」**

という意味である。

### A01-04h.3.7. Competitive Gapを実証するために必要なEvidence

重点Profileを真のWhy Usへ昇格させるには、少なくとも以下が必要である。

**People**
- Predictive / Causal specialist数
- Seniority
- Publications / patents / OSS / certifications

**Project Evidence**
- 高Novelty / 高Analytical Complexity案件
- Causal / Predictive案件数
- Enterprise接続まで含む事例
- High Criticality案件

**Operating Model**
- Specialist Direct Access
- 顧客とのQuestion Definitionから誰が入るか
- SI / Security / Production部門との連携方法
- PoC Team size / Lead Time

**Economics**
- Price
- Total engagement cost
- Product / License依存
- Handoff cost

**Market Evidence**
- 顧客が当チームを選んだ理由
- Competitive win / loss
- Repeat
- Customer reference

このEvidenceを同じDeal Profile上でRelevant Competitorと比較して初めて、`Relative Advantage`を主張できる。

### A01-04h.3.8. Profile別の「反証可能性」

本Summaryは、当チームが有利になる結論ありきではない。

以下の結果が得られればPositioning仮説は修正する。

- 高度分析 × Enterprise接続で、他SIer Analyticsが分析専門性・Delivery・Economicsの全てで優位
- 高Novelty PoCで、DS SpecialistがRelevant Evidence / Specialist Talent / Priceで優位
- High Governanceで、Consulting / SIerのRisk・Governance Capabilityが圧倒的で、当チームの分析専門性が選定に効かない
- Product Fit案件で、Custom BuildがProductより合理的というEvidenceが一貫して得られる
- Corporate Transformationで、当チームにPrime Contractorとしての実績・Capabilityが確認される

つまり、このProfile map自体もEvidenceによって更新されるべき仮説である。

### A01-04h.3.9. 01-05への示唆

本編01-05では、顧客に研究過程を見せる必要はない。

そこで、詳細分析を、

> **予測・因果の高度分析を、Enterprise利用まで見据えて柔軟に設計する。**

というValue Propositionへ圧縮する。

顧客から、

> 「それは他社もできますよね？」

と問われた場合に、A01-01〜A01-04hを使って、

1. Capability範囲が重なることを認める
2. Providerごとに競争力の源泉が異なることを示す
3. 顧客のSelection CriteriaはDealで変わることを示す
4. Deal Profile別に各ProviderのPositionが変わることを示す
5. 当チームがどのProfileを重点候補としているかを説明する
6. 「他社にできない」ではなく、Relevant Evidenceを使って個別商談でRelative Advantageを示す

という回答シーケンスを取る。

### A01-04h.3.10. Evidence / Inferenceの区分

**Published Evidence**
- Organizational Buying / Buying Center / Industrial Buyer Behavior。[T1][T2]
- B2B Buying ProcessのSituation / Complexity依存。[T3][T8]
- Professional ServiceでのQuality Signal / Reputation / Experience。[T4][T5]
- Dependency / Governanceを扱うTCE。[T6][T7]

**Provider一次情報**
- BrainPad / Deloitte / Accenture / NTT DATA / Palantirの公式Offering。[P1]〜[P5]

**当資料の分析仮説**
- Deal Profileの6軸
- Selection WeightのProfile依存
- Provider類型ごとのPosition
- 当チームのCore Candidate領域

これらはEvidenceを踏まえた分析仮説であり、Published Theoryそのものとして扱わない。

## A01-04h.4. Speaker Note

このSummaryで伝えたいのは、当チームがどの案件でも一番ということではありません。

分析単体ならDS専門会社、標準Productで十分ならAI Vendor、Corporate TransformationならConsulting、標準分析のProductionならSIerが合理的な場合があります。

一方、分析方法そのものを個別設計する必要があり、同時にEnterpriseで使うためのData / System / Security / Governanceも無視できない案件では、当チームが持つ複数Capabilityが同時に評価対象になります。そこを重点Positioning候補としています。

この評価は妄想ではなく、B2B購買・Professional Service購買・Transaction Governanceの研究と、実際の競合Providerが公開しているOfferingを材料に組み立てています。ただし、学術研究が当チームの競争優位を証明しているわけではありません。最後のRelative Advantageは、当チーム自身の人材・案件・顧客評価・Competitive Win / Lossで証明する必要があります。
