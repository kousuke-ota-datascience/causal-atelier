## A01-04h.3. Supporting Logic

### A01-04h.3.1. Summaryから見えること

A01-04a〜gを横断すると、当チームのPositioning候補は一様ではない。

特にCapability Bundle全体が活きやすいのは、

1. **高度分析 × Enterprise接続**
2. **高Novelty × Analytical PoC**
3. **High Criticality / GovernanceのうちAnalytical Complexityも高い案件**

である。

共通項は、

> **定型Solutionをそのまま適用しにくく、分析方法・前提・評価を個別設計する必要があり、かつ分析結果をEnterprise環境で使う条件を無視できないこと**

である。

### A01-04h.3.2. なぜこの領域なのか

当チームの確認済みCapabilityは、

- Predictive / Causalを問いから使い分ける
- Scratch / OSSで非定型に設計する
- 前提 / 評価 / Limitationを必要に応じて扱う
- SIer内の分析組織としてEnterprise Contextを考慮する

である。

したがって、Analytical Complexity / Problem Novelty / Implementation Coupling / Criticalityが同時に一定以上あるほど、複数Capabilityが一度に価値化しやすい。

### A01-04h.3.3. ただしRelative Advantageは別問題

このSummaryは**当チームの相対優位を実証したものではない**。

Core Candidateは、

> 「このProfileなら当チームが必ず競合より強い」

ではなく、

> **「このProfileでは当チームのCapability Bundleが最も活きやすく、Relevant Competitorとの差を優先的に検証すべき」**

という意味である。

特に、

- 高度分析 × Enterprise接続では他SIer Analytics / Consulting Analytics
- 高Novelty PoCではDS Specialist / Consulting Analytics
- High GovernanceではSIer Analytics / Consulting Analytics

がRelevant Competitorとなる。

### A01-04h.3.4. 01-05への示唆

本編01-05では、この詳細をすべて見せず、顧客に対して、

> **予測・因果の高度分析を、Enterprise利用まで見据えて柔軟に設計する。**

という一つのValue Propositionへ圧縮する。

「他社も同じでは？」という反論が入った場合に、A01-01〜A01-04hを用いて、

1. Capability範囲は競合と重なる
2. ただし各Providerの強みの源泉は異なる
3. 顧客が重視する軸はDealごとに変わる
4. Deal Profileごとに相対Positionも変わる
5. 当チームは特定ProfileでCapability Bundle全体が活きやすい

と説明する。

## A01-04h.4. Speaker Note

Profile別に見ると、当チームが常に有利という結論にはなりません。分析単体ならDS専門会社、標準Productで十分ならAI Vendor、全社TransformationならConsulting、標準分析の本番化ならSIerが合理的な場合があります。

一方、高度で非定型な分析を設計しながら、その結果をEnterprise環境で利用する条件まで考える必要がある案件では、当チームの複数Capabilityが同時に効きます。ここを重点Positioning候補と考えています。

重要なのは、重点候補と競争優位を混同しないことです。これらのProfileで本当に競合より選ばれるかは、案件実績、人材、Delivery Model、価格、Lead Time、顧客評価などを用いてさらに確認する必要があります。
