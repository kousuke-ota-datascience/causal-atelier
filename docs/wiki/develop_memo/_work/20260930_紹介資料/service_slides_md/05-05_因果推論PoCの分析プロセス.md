# 22. Slide 22｜因果推論PoCの分析プロセス

## 22.1. Message

**因果PoCでは、Estimatorより先に「何の効果を、どの前提で識別するか」を設計し、その後に推定と妥当性確認を行う。**

## 22.2. Chart

**チャートタイトル:** Causal PoCは「設計 → 推定 → Evidence化」の順に進める

### 22.2.1. Chart Structure

詳細工程を4つのPhaseへ束ね、EstimatorがCausal Designの後に位置することを明確にする。

```text

        ↓

   識別できるか？
   ├─ No → Question / Data / Designを見直す
   └─ Yes
```

**PowerPoint上の配置・強調**

- 4つのPhaseを左から右へ配置し、② Causal Designを最も大きくする。
- ②と③の間に `Identification Gate` を置き、Noの場合はEstimator選定へ進まない戻り矢印を示す。
- `Propensity Score` や特定アルゴリズム名は主Chartに置かない。
- 最後は分析結果ではなく `Decision / Next Phase` で閉じる。

## 22.3. Supporting Logic

### 22.3.1. Question / Estimand

- Causal Questionを、どのTreatmentの、誰に対する、どのOutcomeへの、どの期間・比較条件での効果かまで具体化する。
- そのDecisionに対応する対象量をEstimandとして定義する。
- ATE / ATT / CATE等の選択はEstimatorの選択ではなく、「何の効果を知るか」の選択である。

### 22.3.2. Causal Design

- Data Generating Process、Treatment Assignment、Temporal Ordering、Confounder / Mediator / Collider等を整理する。
- 必要なAssumptionを明示し、それらのもとでEstimandをObserved Dataから表現できるIdentification Strategyを設計する。
- この段階でIdentificationが成立しない場合、複雑なEstimatorを試すのではなく、Question変更、追加Data取得、実験、別Design等を検討する。

### 22.3.3. Estimation

- IdentificationされたEstimandに対し、有限標本からEffectを推定するEstimatorを選ぶ。
- Estimator選定ではModel Misspecification、Variance、Overlap、Sample Size等を考慮する。
- Effect EstimateにはUncertaintyを伴わせ、点推定値だけを成果としない。

### 22.3.4. Validation / Decision

- Designに応じたDiagnostics、Refutation / Placebo、Sensitivityを実施する。
- Diagnosticsで未観測交絡等の識別仮定そのものを証明できるわけではないため、残る仮定依存性をClaim Scopeへ反映する。
- 最後に「どの前提のもとで、誰に対して、どの程度の効果を主張できるか」と、Decision / Next Phaseを整理する。

## 22.4. Speaker Note

因果PoCでは、最初に「どの手法を使うか」を決めません。まず、何の効果を知りたいのかをEstimandまで固定し、その効果を手元のデータから因果効果として解釈するために、どの前提と比較設計が必要かを整理します。

ここで効果を識別できる見込みが立って初めて、RegressionやWeightingなどの推定方法を選びます。推定後も、診断や感度分析を行い、最終的にどこまで主張できるかをDecisionへ返します。この順序が、単なる手法適用と因果PoCを分けるポイントです。

## 22.5. Slide 22からSlide 23への接続

> **Workflowの起点は「何の効果を知るか」である。次に、曖昧なBusiness QuestionをTreatment・Outcome・Population・Time・Contrastへ分解し、Estimandとして固定する。**
