# 18. Slide 18｜代表的な予測アプローチと選定方法

## 18.1. Message

**予測モデルは、高度さではなく、必要性能・説明性・安定性・運用制約を満たすFit-for-useで選定する。**

## 18.3. Supporting Logic

### 18.3.1. Slide 18の役割

- Slide 17でPrediction Question、Validation、Holdout、Baselineを固定した。
- **Slide 18では、その固定条件の内側でどのModel FamilyとComplexityを採用するかを決める。**
- 主題はアルゴリズムカタログではなく、Question / Data / Decision条件へのFitである。

### 18.3.2. Model FamilyはDataとQuestionに合わせて候補化する

| Model Family | 向きやすい状況 | 主な留意点 |
|---|---|---|
| Linear / Logistic | 説明性重視、小〜中規模表形式 | 非線形・Interactionに限界 |
| Tree | 条件分岐・非線形 | 単木はVarianceが大きくなりやすい |
| Random Forest | 非線形、頑健な表形式予測 | Size、Calibration、局所説明 |
| Gradient Boosting | 表形式で高性能が必要 | Tuning、過学習、Calibration、Cost |
| Time-series / Forecasting | Trend・季節性・時間依存 | Horizon別Backtestが重要 |
| Survival / Time-to-event | Event発生までの時間を扱う | Censoring、評価時点、Calibration |
| Domain-specific / Other | Text、Image、Graph等 | Data量、基盤、専門的Validation |

- 故障予測ではClassificationだけでなくSurvival / Time-to-event、RUL回帰等も候補になり得る。
- 異常検知では教師あり分類だけでなく、正常状態からの逸脱を扱うUnsupervised / Semi-supervisedな設計もあり得る。
- ただし、重点テーマだから特定のModel Familyを標準解としない。

### 18.3.3. Fit-for-useは複数軸で判断する

1. Predictive / Detection Performance。
2. Calibration / Reliability。
3. 期間・設備・Segmentに対するStability。
4. Explainability / Reviewability。
5. Operational Fit：Latency、Batch / Online、更新頻度、Cost。
6. Data Fit：Sample Size、欠損、Drift、Failure Label availability。

- Candidateは同じSplit / Validation / MetricでBaselineと比較する。
- 性能改善が小さいのに運用Costだけ大きく増える場合は、単純Modelの方が合理的である。
- 逆に、False Negative Cost等が大きく、性能差がDecision Utilityへ直結する場合はComplexityが正当化されることがある。

### 18.3.4. Explainabilityは因果説明ではない

- Feature Importance、Permutation Importance、SHAP等はModel挙動の理解に利用できる。
- しかし「このFeatureを変えれば故障が減る」というTreatment Effectを意味しない。
- 設備Sensorの重要度が高くても、そのSensor値へ介入することの効果は別のCausal Questionである。

### 18.3.5. Model SelectionはValidationの内側で完結させる

- Hyperparameter Tuning、Feature Selection、Model Family比較はTrain / Validation内で行う。
- 最終Holdoutは選定に使わない。
- 当チームの価値は特定Algorithmの販売ではなく、Question / Data / Decisionに応じて必要十分なModelを選び、再現性と業務利用性を検証することにある。
- サービス提供範囲とAriadne現行実装のModel範囲を同一視しない。

## 18.4. Speaker Note

ここでは、どのAlgorithmが最も高度かを比較することが目的ではありません。Slide 17で固定した同じValidation条件の中で、Baselineからどれだけ改善し、説明性や安定性、運用Costまで含めて使いやすいかを判断します。

故障予測でも、Failure Probabilityを扱う分類、故障までの時間を扱うSurvival、RUL回帰など問いによって候補は変わります。異常検知もLabelの有無によって設計が変わります。したがって手法を先に決めず、DataとDecisionへFitするModelを選びます。

## 18.5. Slide 18からSlide 19への接続

> **Modelを選定した後は、単一のAccuracyではなく、未知データでの再現性・信頼性・失敗パターン・業務Utilityまで含めて利用可否を評価する。**
