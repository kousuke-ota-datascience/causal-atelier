# 6. Slide 6｜業務課題から意思決定までの接続

## 6.1. Message

**分析設計の起点は「何を分析したいか」ではなく、「誰が、何を、どう決める必要があるか」を明確にすることである。**

## 6.2. Chart

**チャートタイトル:** Business Question → Analysis Question → Decision Loop

Messageを説明・論証するための主たる視覚表現として、以下の構造を採用する。

### 6.2.1. Chart Structure

- 既存の論理フロー／概念図を主チャートとして用い、要素間の関係・順序が一目で追える構造にする。

```text
Business Question
「何を改善したいか」
        ↓
Decision / Action
「誰が何を変えるか」
        ↓
Analysis Question
「何を推定・予測すれば判断できるか」
        ↓
Data / Analysis / Validation
        ↓
Interpretation
「何が言え、何が言えないか」
        ↓
Decision / Actionへ戻す
```

**PowerPoint上の配置・強調**

- 縦型の循環フローとし、最後のInterpretationからDecisionへ戻る矢印を強調する。
- Business QuestionとDecisionを色分けし、分析工程は中間色で示す。
- 具体例はSpeaker Noteに置き、スライド上は構造を優先する。

### 6.2.2. Chart内の最小表示テキスト

実際のPowerPoint上では、以下のラベル・短文を中心に表示する。Supporting Logicの全文をスライド上へ掲載しない。

- Business Question
- 「何を改善したいか」
- Decision / Action
- 「誰が何を変えるか」
- Analysis Question
- 「何を推定・予測すれば判断できるか」
- Data / Analysis / Validation
- Interpretation
- 「何が言え、何が言えないか」
- Decision / Actionへ戻す

## 6.3. Supporting Logic

- Decision / Actionを先に定義することで、必要なTarget、Treatment、Outcome、評価指標が具体化する。
- 予測では「予測値を見て誰を対象にするか」、因果では「どの施策を採用・停止するか」まで定義する。
- 分析上の問いはBusiness Questionの単なる言い換えではなく、データから評価可能な形式へ変換する。
- 結果解釈では、推定値だけでなく不確実性・前提・適用範囲をDecisionに合わせて表現する。

- 補足論点：**業務意思決定を先に定義することで、必要な分析・データ・評価基準が逆算できる。**

## 6.4. Speaker Note

例えば「解約率を下げたい」だけでは分析仕様にならない。「営業担当が週次で上位N顧客へアプローチする」まで決めると予測閾値やKPIが定まる。因果なら「キャンペーンAを継続するか」まで定義する。

## 6.5. Slide 6からSlide 7への接続

> **分析結果を業務で利用するためには、利用者・タイミング・判断基準・失敗コストまで含めた利用設計が必要になる。**
