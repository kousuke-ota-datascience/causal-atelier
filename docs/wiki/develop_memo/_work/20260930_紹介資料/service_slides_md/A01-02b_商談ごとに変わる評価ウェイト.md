# A01-02b. Appendix｜商談ごとに変わる評価ウェイト

## A01-02b.1. Message

**同じ8つの選択基準でも、どの軸を重く見るかは商談ごとに変わる。**

## A01-02b.2. Chart

**チャートタイトル:** Deal ContextがCustomer Selection CriteriaのWeightを変える

### A01-02b.2.1. Chart Structure

```text
今回のDeal Context
────────────────────
Decision / Problem locus
Buying Situation
Perceived Risk / Criticality
Buying Center
Requested Scope
        ↓
8つのCustomer Selection Criteria
────────────────────
Fit / Capability / Delivery / Economics
Risk / Evidence / Governance / Org. Acceptability
        ↓
WeightがDealごとに変化
        ↓
今回のDealにFitするProviderが変わる
```

例：

| 商談例 | 重くなりやすいCriteria | 有力になりやすいProvider例 |
|---|---|---|
| 全社AI Strategy / Transformation | Fit / Evidence / Governance / Org. Acceptability | Consulting Analytics |
| 非定型・高度な分析PoC | Fit / Capability / Evidence | DS Specialist / Specialist Analytics |
| Production / Enterprise Integration | Delivery / Risk / Org. Acceptability | SIer Analytics |

下部に以下を置く。

> **ProviderのBase Strengthは同じでも、Deal Weightが変われば総合Positionは変わる。**

## A01-02b.3. Supporting Logic

### A01-02b.3.1. 顧客の評価Weightは固定ではない

Webster & WindはOrganizational Buyingを複数の組織・対人・個人要因を含む意思決定として扱い、Shethは購買関係者ごとに異なるExpectationと、Perceived RiskやPurchase Type等によるJoint Decisionの変化をモデル化した。[T1][T2]

BUYGRIDではNew Task / Modified Rebuy / Straight Rebuyによって情報探索・意思決定の深さが変化する。[T8]

従って「この顧客は価格重視」「この会社は実績重視」と固定的に捉えるのではなく、**今回のDealで誰が何を重要視するか**を見る必要がある。

### A01-02b.3.2. Deal Contextとして見る変数

本資料では、Weightを変える主要なDeal Contextとして以下を使う。

1. Decision / Problem Locus
2. Buying Situation
3. Perceived Risk / Criticality
4. Buying Center
5. Requested Scope

これらは単一理論の正式5分類ではなく、BUYGRID / Organizational Buying / Sheth等を踏まえた本資料の操作的整理である。

### A01-02b.3.3. 例1｜Corporate / Transformation

- Decision Altitudeが高い
- New Task
- Executive / Business / IT等のBuying Center
- Strategy / TransformationがRequested Scope

この場合、単なるAnalytics Capabilityより、Fit / Evidence / Governance / Organizational AcceptabilityのWeightが上がりやすい。

### A01-02b.3.4. 例2｜非定型Analytical PoC

- Problem Noveltyが高い
- Analytical Complexityが高い
- Business / Data-AI中心
- Requested ScopeはAnalytical PoC

この場合、Fit / Capability / EvidenceのWeightが高くなりやすい。

### A01-02b.3.5. 例3｜Production / Enterprise Integration

- Implementation Couplingが高い
- Criticalityが中〜高
- IT / Security / OperationがBuying Centerへ参加
- Requested ScopeにBuild / Operateが含まれる

この場合、Delivery / Risk / Organizational AcceptabilityのWeightが高くなりやすい。

### A01-02b.3.6. 概念モデル

```text
Weight_j = f_j(Deal Context)
```

同じProvider Base Profileでも、Weightが変わればDeal-level Positionは変わる。

```text
Provider Position
  = Base Strength × Deal-specific Weight
```

これは実証済み係数ではなく、Deal依存性を表現する概念モデルである。

### A01-02b.3.7. A01-03への接続

Deal Contextを毎回文章で記述するだけでは比較しにくい。

そこで次頁では、商談特性を共通の6軸へ落とし込み、連続的な`Deal Profile`として記述する。

## A01-02b.4. Speaker Note

8つの評価軸は共通ですが、重要度は案件ごとに変わります。高度な分析PoCではFitやCapabilityが前面に出ますが、本番System化ならDeliveryやRiskが重要になります。全社TransformationならEvidenceやGovernance、社内承認性のWeightが高くなります。

つまり競争力はProvider側だけで決まりません。Providerが持つBase Strengthと、今回の案件で顧客が何を重く見るかの組み合わせで決まります。次に、この案件条件を共通の6軸で表現します。
