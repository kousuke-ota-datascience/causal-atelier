# 7. Slide 7｜分析結果を業務で利用するための設計

## 7.1. Message

**分析結果を業務へ定着させるには、結果の利用者・利用タイミング・Action・判断基準をPoC段階から設計する必要がある。**

## 7.2. Chart

**チャートタイトル:** 分析結果を業務へ接続する4要素

Messageを説明・論証するための主たる視覚表現として、以下の構造を採用する。

### 7.2.1. Chart Structure

- 既存の論理フロー／概念図を主チャートとして用い、要素間の関係・順序が一目で追える構造にする。

```text
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ WHO      │→│ WHEN     │→│ DECIDE   │→│ ACTION   │
│ 誰が使う │  │ いつ使う │  │ 何を決める│  │ 何を変える│
└──────────┘  └──────────┘  └──────────┘  └──────────┘
                         ↑
                Threshold / Uncertainty
```

**PowerPoint上の配置・強調**

- WHO / WHEN / DECIDE / ACTIONの4ボックスを横並びにする。
- DECIDEの下にThreshold / Uncertaintyを置き、分析結果が判断条件へ変換されることを示す。
- IT実装図にはしない。

### 7.2.2. Chart内の最小表示テキスト

実際のPowerPoint上では、以下のラベル・短文を中心に表示する。Supporting Logicの全文をスライド上へ掲載しない。

- WHO
- WHEN
- DECIDE
- ACTION
- 誰が使う
- いつ使う
- 何を決める
- 何を変える
- Threshold / Uncertainty

## 7.3. Supporting Logic

- WHO：意思決定者・分析利用者・運用担当者を明確にする。
- WHEN：日次・週次・施策実施前後など、分析が必要となるタイミングを定める。
- DECIDE：閾値、比較基準、不確実性を踏まえて何を判断するかを定義する。
- ACTION：判断結果を受けて、対象変更・施策変更・資源配分等の具体的行動へ接続する。
- 誤判定コストや施策コストが大きい場合は、分析指標だけでなく業務損失関数を評価に組み込む。

- 補足論点：**業務接続は「ダッシュボードを作ること」ではなく、分析結果が具体的なDecision / Actionを変える仕組みを定義することである。**

## 7.4. Speaker Note

業務接続の設計はモデル本番化の後工程ではなく、PoCの分析仕様を決める入力であると説明する。

## 7.5. Slide 7からSlide 8への接続
