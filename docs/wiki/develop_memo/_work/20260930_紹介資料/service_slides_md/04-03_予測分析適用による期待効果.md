# 13. Slide 13｜予測分析適用による期待効果

## 13.1. Message

**予測分析は、誤りを含む予測でも、多数のDecisionで対象・時期・量をより良く選ぶことで、KPIの期待値を改善し得る。**

## 13.3. Supporting Logic

### 13.3.1. Slide 13の役割

- Slide 11ではPredictiveを `Decision時点の観測情報 → Prediction → Decision / Action` と定義した。
- Slide 12ではPredictionを先回りしたActionへ変換しやすい業務条件を整理した。
- **Slide 13では、Prediction Errorが残っても、Decision Ruleを介して多数の判断をBaselineより平均的に改善することがBusiness Valueの源泉であると示す。**
- ここまではPredictive全般の一般原則であり、Slide 14から当チームの重点テーマである故障予測・異常検知へ具体化する。

### 13.3.2. Predictiveの価値はDecision全体の期待値改善にある

- False Positive、False Negative、Forecast Error等は残り得るため、個々の事象を必ず正しく言い当てることを前提にしない。
- Predictionを使ったDecisionがBaselineより平均的に良ければ、反復する判断で差分を累積できる。
- 評価はAccuracyだけでなく、Ranking、Calibration、Error Cost、Capacity等を踏まえ、Decision Ruleが現行Ruleより有用かを見る。
- 一度の誤判定が不可逆・致命的で、Human ReviewやSafety Rule等でDownsideを緩和できない場合、Prediction単独の自動Decisionは適用しにくい。

### 13.3.3. Decision RuleがPredictionをActionへ変換する

| Action Pattern | Decision Ruleの例 | Operational Effectの例 |
|---|---|---|
| PRIORITIZE / REVIEW | Risk上位、一定Score以上を追加確認 | 見逃し・不要対応を減らす |
| SCHEDULE | Risk / RUL等に応じて時期を調整 | 早すぎ / 遅すぎ対応を減らす |
| ALLOCATE / PLAN | Forecast等に応じてCapacity配分 | Resource配分Mismatchを減らす |

- 同じPrediction性能でもThreshold、Capacity、Human Reviewの有無により業務価値は変わる。
- したがってModel単体ではなくDecision Ruleまで含めてValue Chainを評価する。

### 13.3.4. PoCで確認できることと追加検証を分ける

1. Prediction Performance：未知データでBaselineより有用か。
2. Decision Utility：実際のRule・Capacityで判断改善が期待できるか。
3. Actionability / Operating Fit：Action変更を実行でき、Errorを許容・緩和できるか。
4. Business Outcome Hypothesis：Operational EffectがKPIへ接続する合理的経路があるか。

- Offline検証でPrediction Performanceと一定のDecision Utilityは評価できる。
- 実Business Outcomeの改善を確認する場合はProduction比較、A/B Test、段階導入、因果評価等を必要に応じて設計する。

## 13.4. Speaker Note

ここで伝えたいのは、予測を一件ずつ必ず当てれば価値が出る、という話ではありません。Predictionには誤りが残りますが、RankingやThreshold等のDecision Ruleへ組み込み、多数の判断で現行Ruleより平均的に良いActionを選べれば、KPIの期待値改善につなげられます。

したがってAccuracyだけでなく、False Positive / False NegativeのCost、対応可能件数、Human Review、Safety Ruleまで含めて評価します。また、Prediction性能が高いことと実Business Outcomeが改善したことは同義ではありません。

次の3枚では、この一般原則を当チームの重点テーマである設備の故障予測・異常検知へ具体化します。
