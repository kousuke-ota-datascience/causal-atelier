# 1. Slide 1｜当チームが提供する分析PoCサービス

## 1.1. Message

**当チームは、将来を見通す「予測分析」と、施策による変化を捉える「因果推論」のPoCを、業務意思決定への接続まで含めて支援する。**

## 1.2. Chart

**チャートタイトル:** 2つの分析サービスと業務意思決定への接続

Messageを説明・論証するための主たる視覚表現として、以下の構造を採用する。

### 1.2.1. Chart Structure

- 既存の論理フロー／概念図を主チャートとして用い、要素間の関係・順序が一目で追える構造にする。

```text
業務課題・意思決定
        ↓
┌────────────────┐   ┌────────────────┐
│ Predictive     │   │ Causal         │
│ 何が起こるか   │   │ 何をすると変わるか │
└───────┬────────┘   └───────┬────────┘
        └──────────┬──────────┘
                   ↓
          意思決定・次アクション
```

**PowerPoint上の配置・強調**

- 中央にPredictive / Causalの2ボックスを横並びにする。
- 上段にBusiness Question、下段にDecision / Actionを置き、分析を中間手段として見せる。
- 製品名やアルゴリズム名は出さず、サービスの役割を主役にする。

### 1.2.2. Chart内の最小表示テキスト

実際のPowerPoint上では、以下のラベル・短文を中心に表示する。Supporting Logicの全文をスライド上へ掲載しない。

- 業務課題・意思決定
- Predictive
- Causal
- 何が起こるか
- 何をすると変わるか
- 意思決定・次アクション

## 1.3. Supporting Logic

- 予測分析は、未知・将来のOutcomeを予測し、優先順位付けや計画高度化を支援する。
- 因果推論は、施策・介入によるOutcomeの変化を推定し、施策選択や投資判断を支援する。
- 分析実装はデータサイエンティストによるスクラッチ開発を基本とし、必要に応じてOSSやAriadneを利用する。
- PoCの終点はモデル作成ではなく、業務で次に何を判断するかを明確にすることとする。

- 補足論点：**分析サービスの価値は「分析できること」ではなく、予測または介入効果を業務上の判断材料へ変換することにある。**

## 1.4. Speaker Note

冒頭では技術詳細へ入らず、当チームが何を提供し、最終的に何へつなげるサービスなのかを定義する。予測と因果を同じ「分析手法」の箱に平坦化せず、答える問いが異なることを示す。

## 1.5. Slide 1からSlide 2への接続
