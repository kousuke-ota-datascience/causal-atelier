# 16. Slide 16｜重点テーマ：故障予測・異常検知の期待効果

## 16.1. Message

**異常・故障の兆候を早く捉える価値は、保全の対象・時期・量を事前に変えられることにある。**

## 16.3. Supporting Logic

### 16.3.1. Slide 16の役割

- Slide 14では、異常検知と故障予測が何を捉えるかを区別した。
- Slide 15では、設備状態を観測でき、兆候に応じて保全Actionを変えられる業務が適用候補になることを示した。
- **Slide 16では、そのEvidenceをどのようにDecisionへ変換し、どのOperational Effectが期待できるかを具体化する。**
- 一般論のSlide 13を設備保全へ単純翻訳するのではなく、点検・交換・保守計画という設備特有のDecisionへ落とす。

### 16.3.2. 分析Outputは保全Actionそのものではない

- Anomaly Scoreは「通常状態からどの程度外れているか」の判断材料であり、交換指示そのものではない。
- Failure Riskは将来FailureのRiskであり、直ちに交換すべきことを意味しない。
- RULも不確実性を持つ推定値であり、安全条件、交換Lead Time、部品在庫、保全Capacity等と合わせてDecisionへ変換する。
- したがって、実務価値は `Evidence + Decision Rule + Operating Constraint` の組合せで決まる。

### 16.3.3. 代表的なDecision / Actionと期待効果

| Decision / Action | Evidenceの使い方 | Operational Effectの例 | 接続し得るKPI |
|---|---|---|---|
| 点検優先順位 | Anomaly / Failure Risk上位を重点確認 | 限られた点検Capacityを重要設備へ寄せる | 点検効率、見逃し、停止Risk |
| 交換判断 | Failure Risk / RULと安全条件を照合 | 早すぎる交換・遅すぎる交換を減らす | 保全Cost、Down Time、稼働率 |
| 保守Schedule | Risk / RULと操業計画を合わせる | 突発対応を計画保全へ寄せる | 稼働率、計画遵守、停止時間 |
| 人員・部品配置 | 将来Riskの分布から必要Capacityを見積もる | 不足・過剰在庫・待ち時間を減らす | Resource効率、Lead Time、在庫 |
| Human Review / Escalation | 不確実性・重大度に応じて追加確認 | 自動判断のDownsideを制御する | 安全性、誤対応Cost、Review効率 |

### 16.3.4. False Positive / False NegativeのCostを保全Decisionへ反映する

- **False Negative**：故障・重大異常を見逃し、突発停止、安全Risk、品質問題等につながり得る。
- **False Positive**：不要点検、早期交換、停止作業、保全Resource消費等につながり得る。
- どちらを重く見るかは設備Criticality、Safety、停止Cost、点検Cost等で変わる。
- そのためThresholdやTop-KをPrediction Metricだけで決めず、保全CapacityとError Costを含めて設計する。

### 16.3.5. 期待効果と因果効果を分ける

- Offline PoCでは、未知データでのDetection / Prediction性能や、Decision Ruleを使ったUtilityの仮説を評価できる。
- しかし、Predictionを使った保全Actionが実際にDown Timeや保全Costをどれだけ改善したかは、Offline性能だけからは確定しない。
- 特に「どの保全施策を実施すれば故障率がどれだけ下がるか」「予防交換を行うと停止時間がどれだけ減るか」はTreatment Effectの問いであり、必要に応じて実験・段階導入・因果評価を別途設計する。
- **高Failure Riskな設備 ≠ 特定保全施策で最も改善する設備**という境界を保持する。

### 16.3.6. 重点テーマ3枚で顧客へ伝えること

```text

        ↓
```

## 16.4. Speaker Note

故障予測や異常検知の価値は、故障を当てること自体ではありません。異常Scoreや故障Risk、RULを使って、どの設備を先に見るか、いつ交換するか、どこへ人員や部品を配分するかという保全判断を変えられることにあります。

ここでは誤りのCostも重要です。故障を見逃すCostが大きい設備と、不要点検のCostが大きい設備では、同じModelでもThresholdの置き方は変わります。そのため、Accuracyだけではなく実際の保全Capacityや安全条件を含めてDecision Ruleを設計します。

なお、予測精度が高いことと、予防保全によって実際の故障や停止が減ったことは別です。後者を確認したい場合は、必要に応じて本番での比較や因果評価を行います。
