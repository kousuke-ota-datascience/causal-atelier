# 11. Slide 11｜予測分析とは

## 11.1. Message

**予測分析は、観測情報から未知・将来のOutcomeを推定し、事前の判断を支える。**

## 11.2. Chart

**チャートタイトル:** 観測情報からPredictionを得て、結果が分かる前のActionへつなぐ

Slide 1〜3で示したPredictiveの意味論と、Slide 6〜10で示したDecision / Action起点のPoC設計を接続し、予測分析を「モデルを作る工程」ではなく、**Decision時点で利用可能な情報から未知・将来のOutcomeを推定し、その見通しを事前の判断材料として利用する分析**として示す。

### 11.2.1. Chart Structure

PowerPoint上では、左から右へ読む4段階の単一フローとする。

```text
┌────────────────────────┐   ┌────────────────────────┐   ┌────────────────────────┐   ┌────────────────────────┐
│ Decision時点の観測情報 │ → │ Predictive Model       │ → │ Prediction             │ → │ Decision / Action      │
│ X                      │   │                        │   │ 未知・将来のOutcome    │   │ 結果が分かる前に変える │
│ その時点で利用可能     │   │ 規則性を学習・適用     │   │ Risk / Probability /   │   │ 対象 / 時期 / 量 /     │
│                        │   │                        │   │ Forecast 等             │   │ 優先順位               │
└────────────────────────┘   └────────────────────────┘   └────────────────────────┘   └────────────────────────┘

          入力時点を固定                                      Predictionは判断材料
          未来情報を入れない                                  Actionは業務ルールで決める

                    予測の価値 = Outcomeが判明する前に判断を変えられること
```

**PowerPoint上の配置・強調**

- `Decision時点の観測情報 → Predictive Model → Prediction → Decision / Action` を一つの横フローとして示す。
- 最も強調するのはModelではなく、右側の `Prediction → Decision / Action` とする。モデルは判断材料を作る手段として扱う。
- 左端は単に「データ」とせず、**Decision時点で利用可能な観測情報**と明記する。予測時には利用できない未来情報やOutcome確定後の情報を入力できないことを直感的に示す。
- Predictionは、案件に応じてRisk、Probability、Class、数値予測、Forecast等の形を取り得るため、特定の出力形式へ限定しない。
- Decision / Actionでは、予測値そのものが自動的にActionを決めるようには見せない。Slide 8で定義したDecision Ruleや業務制約を介して、対象・時期・量・優先順位等を変更することを示す。
- 下段に `予測の価値 = Outcomeが判明する前に判断を変えられること` を置き、予測精度そのものを最終価値として見せない。
- Classification / Regression / Forecasting等の手法分類やAlgorithm名は主図に置かず、後続の予測分析章へ分離する。

## 11.3. Supporting Logic

### 11.3.1. Slide 11の役割

- Slide 1〜3では、Predictiveは「何が起こりそうか」という問いに対し、将来・未知のOutcomeの見通しを提供する分析であり、Causalとは推論対象・成立条件・評価基準が異なることを示した。
- Slide 4では、その見通しを使って対象・時期・対応を変えることでBusiness Outcomeへ接続するValue Chainを示した。
- Slide 6〜10では、Predictive / Causalに共通して、DecisionからAnalysis Questionを逆算し、利用ルール・PoC工程・Success Criteriaまで設計することを示した。
- **Slide 11では、ここまでの共通設計をPredictiveへ具体化し、予測分析の基本構造を「Decision時点の情報 → Prediction → 事前のDecision / Action」として定義する。**
- 次のSlide 12では、この構造が業務上成立しやすい課題、すなわちPredictionをOutcome判明前のActionへ接続できる業務を具体化する。

### 11.3.2. 予測分析が推定するもの

- Predictive analysisは、観測済みの情報 `X` を用いて、未観測または将来のOutcome `Y` に関するPredictionを得ることを目的とする。
- Predictionの形式は案件によって異なり、例えば以下がある。
  - Event / Class：解約、故障、不正、成約等の発生確率やClass。
  - Numeric Outcome：売上、需要、Lead Time、損失額、工数等の数値。
  - Time-indexed Outcome：需要、負荷、利用量等の将来系列。
- これらは代表的な出力形態であり、互いに完全に排他的な手法分類ではない。具体的なModel / Approachの選定は後続スライドで扱う。

### 11.3.3. 「Decision時点で利用可能な情報」が入力条件になる

- 実運用でPredictionを利用する時点を `t0` とすると、原則として入力に利用できるのは `t0` までに観測・取得可能な情報である。
- Outcome確定後にしか得られない情報や、予測対象期間の未来情報をFeatureへ含めると、Target Leakage / Future LeakageによりOffline評価が過大になる場合がある。
- したがって「何を予測するか」だけでなく、**いつ予測し、その時点で何が利用可能か**をPrediction Questionと検証設計で整合させる必要がある。
- データ上存在する列を使えるかではなく、実際のDecision時点で取得可能かを基準にFeature availabilityを判断する。

### 11.3.4. PredictionはDecisionの入力であり、Actionそのものではない

- Predictionは、未知・将来のOutcomeに関する不確実性を減らす判断材料である。
- 例えばChurn Riskが得られても、「何%以上なら対応するか」「何件まで対応するか」は、Calibration、誤判定コスト、対応可能件数、対象価値等を踏まえたDecision Ruleで決まる。
- 需要Forecastが得られても、発注量や要員数は在庫Cost、欠品Cost、Capacity、Lead Time等の業務制約を踏まえて決める。
- したがって、予測精度を高めることは重要だが、**高い予測性能だけで業務価値が自動的に生じるわけではない。** PredictionがDecision / Actionを改善できる条件まで含めてPoCで検証する必要がある。

### 11.3.5. PredictiveとCausalの境界を維持する

- Predictiveでは、未知データでも再現する関連がPredictionに有用であれば、FeatureとOutcomeの関係が因果関係であること自体は必要条件ではない。
- そのため、Feature importance、SHAP、PDP / ICE等で予測モデルの振る舞いを説明できても、そのFeatureを変更すればOutcomeが変化するとは限らない。
- `高Riskな対象` と `施策によって最も改善する対象` は一致するとは限らない。
- 施策・介入によってOutcomeがどの程度変化するかを知りたい場合は、Predictiveの出力をそのまま因果効果として解釈せず、Causal Questionとして別途扱う。

### 11.3.6. 予測分析の評価対象

- Predictiveの主要な科学的評価対象は、適切に分離された未知データに対してPredictionがどの程度再現するかというOut-of-sample predictive performanceである。
- 実務では単一のAccuracyだけでなく、案件に応じてCalibration、Precision / Recall、Ranking、Error Pattern、Segment別性能、予測誤差の業務コスト等も確認する。
- ただし、どの評価指標を採用するかはPrediction QuestionとDecision / Actionに依存する。詳細は後続の「予測モデルの評価と解釈」で扱う。

## 11.4. Speaker Note

ここからは、予測分析について具体的に説明します。

予測分析は、現在までに観測できる情報から、まだ分かっていないOutcomeや将来のOutcomeを推定する分析です。ただし、モデルを作って予測値を出すこと自体が目的ではありません。予測結果を、Outcomeが分かる前の判断材料として使えることに意味があります。

例えば解約対応であれば、対応計画を決める時点までに取得できる顧客情報から、今後の解約Riskを予測します。そのRiskを見ながら、対応可能件数や誤判定コスト等も踏まえて優先対象を決めます。需要予測であれば、将来需要の見通しを在庫や要員の計画へ利用します。

ここで重要なのは、左端の情報が「Decision時点で利用できる情報」に限られることです。結果が出た後にしか分からない情報を使って高い精度が出ても、実際の予測には利用できません。

また、PredictionはActionそのものではありません。どの値なら何をするかは、業務上のコストやCapacity、利用可能なResource等を含むDecision Ruleで決まります。このためPoCでは、未知データで予測が再現するかだけでなく、そのPredictionを事前の判断へ使えるかまで確認します。

なお、予測に役立つ特徴が、そのOutcomeの原因であるとは限りません。施策によってOutcomeを変えられるかを知りたい場合は、因果推論として別の問いを立てる必要があります。
