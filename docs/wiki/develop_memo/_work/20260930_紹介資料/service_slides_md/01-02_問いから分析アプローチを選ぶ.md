## 2.1. Message

## 2.2. Chart

**チャートタイトル:** 現状理解を土台に、問いに応じて予測・因果を使い分ける

データ分析で扱う問いを、完全な並列分類ではなく、「現状を理解する問い」を共通基盤として、その上で「何が起こりそうか」「何をするとどう変わるか」という2種類の意思決定Questionへ分岐する構造で示す。

### 2.2.1. Chart Structure

PowerPoint上では、上段に共通基盤となるExploratory、下段にPredictive / Causalを左右に並べた「1 → 2」の分岐チャートとする。

読み順は、上から下へ以下の通りとする。

1. まず、観測されたデータから現状・傾向・関係を理解する
2. その上で、知りたいことが将来・未知のOutcomeであればPredictiveへ進む
3. 施策・介入によるOutcomeの変化であればCausalへ進む

```text
                    現状、何が起きているか？
                         Exploratory
                  状態・傾向・関係を理解する
                              │
                              ▼
              知りたいこと・決めたいことを明確化
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
       何が起こりそうか？              何をするとどう変わるか？
          Predictive                         Causal
              │                               │
              ▼                               ▼
       未知・将来を見通す              介入による変化を捉える

           問いが違えば、必要な分析設計も変わる
```

**PowerPoint上の配置・強調**

- ExploratoryはPredictive / Causalと同列のサービスメニューとして見せず、両者に共通するデータ理解・現状把握の基盤として上段中央に置く。
- 「現状、何が起きているか？」はSlide 1で提示した新たな第3サービスではなく、Predictive / CausalのPoCを設計する際にも必要となる共通の分析的問いとして見せる。
- 下段ではPredictive / Causalを左右対称に配置し、Slide 1で提示した2つのPoCサービスとの連続性を保つ。
- Predictive / Causalの最上部では、「何が起こりそうか？」「何をするとどう変わるか？」という問いを最も大きく表示する。
- ExploratoryからPredictive / Causalへ一本の固定工程として流れるようには見せず、「知りたいこと・決めたいことを明確化」を介して分岐させる。分析目的や設計が探索結果によって事後的に決まることを一般化しないためである。
- 最下部に「問いが違えば、必要な分析設計も変わる」と置き、Slide 3のPredictive / Causal比較へ接続する。

## 2.3. Supporting Logic

### 2.3.1. ExploratoryとPredictive / Causalの位置づけ

- データ分析では、「現状、何が起きているか」「何が起こりそうか」「何をするとどう変わるか」といった異なる問いを扱う。
- ただし、本資料ではこれらを同列のサービス分類として扱わない。当チームが提供するPoCサービスの中心はSlide 1で示したPredictive / Causalであり、Exploratoryを第3の独立サービスとして追加する意図はない。
- Exploratoryな問いは、現状理解それ自体を目的とする分析として成立する一方、Predictive / CausalのPoCでもデータ品質、分布、傾向、変数間関係、データ生成過程等を理解するために必要となる。
- したがってSlide 2では、Exploratoryを「共通するデータ理解の基盤」、Predictive / Causalを「その先で答えたい主要な意思決定Question」として非対称に配置する。

### 2.3.2. Exploratory / Data Understanding

- Exploratoryは、観測されたデータについて、状態、分布、傾向、変数間の関係等を把握する問いを扱う。
- 例えば「どの顧客層で解約率が高いか」「売上は地域・時期によってどう異なるか」といった現状理解に利用できる。
- Predictive / CausalのPoCでも、データ品質の確認、欠損・外れ値の把握、分布確認、データ生成過程の理解等は分析設計・実行の重要な基盤になる。
- 一方で、観測された関係は、それ自体では将来の予測性能や介入による因果効果を意味しない。
- また、「Exploratoryが必ず先にあり、その結果からPrediction QuestionやCausal Questionを決める」と一般化しない。Confirmatoryな分析や事前に定義された実験・評価では、問い、Estimand、検証設計等をデータ観察前に固定することが重要な場合がある。

### 2.3.3. Predictive

- Predictiveは、現在までに観測できる情報を用いて、未知・将来のOutcomeを予測する問いを扱う。
- 例えば「来月の需要はいくつか」「どの顧客が解約しそうか」といった問いに対し、将来・未知のOutcomeに関する見通しを提供する。
- 予測できる特徴が見つかっても、その特徴を変えればOutcomeが変化するとは限らない。

### 2.3.4. Causal

- Causalは、Treatmentや施策・介入を変えたときに、Outcomeがどう変化するかという問いを扱う。
- 例えば「割引施策を実施すると購買額はどの程度変わるか」「施策Aと施策BではどちらがOutcomeを改善するか」といった問いに対応する。
- 観測された相関や高い予測性能だけでは介入効果を主張できず、因果構造、比較条件、Identification Assumption等を含む分析設計が必要になる。

### 2.3.5. 問いを分けるBusiness上の意味

- 現状理解だけで足りるのか、将来を見通す必要があるのか、施策効果まで知る必要があるのかによって、意思決定に必要な情報は異なる。
- そのため、分析手法やアルゴリズムを先に選ぶのではなく、「何を知り、その情報で何を決めたいか」を先に明確にする必要がある。
- Slide 2ではこの選定原則までを示し、Predictive / Causalで具体的に何が異なるかはSlide 3で扱う。

## 2.4. Speaker Note

Slide 1では、当チームが予測分析と因果推論という2種類のPoCを提供することを示しました。ここで突然3つ目のサービスを追加するわけではありません。

実際の分析では、予測や因果の実行に際して、手元のデータで何が起きているのか、どのような分布・傾向・関係があるのかを理解することが必要です。これがExploratoryな問いです。現状理解自体が分析目的になる場合もありますが、当チームのPredictive / Causal PoCでは、主としてデータ理解・分析設計の共通基盤として位置づけます。

その上で、業務上知りたいことが「今後、何が起こりそうか」であればPredictive、「何をするとどう変わるか」であればCausalというように、問いに応じて分析アプローチが分かれます。

ただし、Exploratoryを必ず最初に行い、その結果を見てから問いを決めるという意味ではありません。例えば施策効果を検証する実験では、何を効果として測るか、どの比較で評価するかを事前に定めることが重要です。ここで伝えたいのは、Predictive / Causalのどちらでもデータ理解が必要である一方、最終的に答えたい問いによって必要な分析設計が異なるということです。

特に「何が起こりそうか」と「何をするとどう変わるか」は混同されやすい問いです。次のスライドでは、この2つがなぜ同じ分析では答えられないのかを、目的・前提・評価の違いから整理します。
