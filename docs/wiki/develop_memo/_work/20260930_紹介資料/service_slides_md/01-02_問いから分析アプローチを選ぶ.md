## 2.3. Supporting Logic

### 2.3.1. Slide 2の役割

- Slide 1では、当チームがPredictive / Causalという2つのPoCサービスを提供し、それぞれが業務判断に異なる価値を提供することを示した。
- その直後に読み手が持つ自然な問いは、「では、自社の課題ではどちらを選べばよいのか」である。
- Slide 2は、このサービス選択の基準を示すことに集中する。

### 2.3.2. 業務課題だけでは分析アプローチは決まらない

- 「解約を減らしたい」「配送遅延を減らしたい」「不良を減らしたい」「設備停止を減らしたい」といった業務課題だけでは、必要な分析アプローチは一意に決まらない。
- 例えば「解約を減らしたい」という同じ業務課題でも、「誰が解約しそうか」を知りたい場合と、「Retention施策で解約がどの程度減るか」を知りたい場合では必要な分析が異なる。
- 同じ構造は、配送、品質、設備でも成立する。

```text
配送品質を改善したい
Predictive：どの配送が遅れそうか？
Causal：配送Process変更で遅延はどれだけ減るか？

不良を減らしたい
Predictive：どの製品が不良になりそうか？
Causal：工程条件を変えると不良率はどう変わるか？
```

- そのため、業務課題を「何を知りたいか」という具体的な問いへ落とし込む必要がある。

### 2.3.3. Predictiveを選ぶ問い

- Predictiveは、現在までに観測できる情報を用いて、未知・将来のOutcomeを見通したい場合に選ぶ。
- 例として、「誰が解約しそうか」「どの配送が遅れそうか」「どの製品が不良になりそうか」「どの設備が停止しそうか」「Caseの完了までどの程度かかりそうか」等がある。
- 得られた見通しは、計画、配分、優先順位、Escalation、Review等の業務判断に利用する。
- 予測できる特徴が見つかっても、その特徴へ介入すればOutcomeが変化するとは限らない。

### 2.3.4. Causalを選ぶ問い

- Causalは、施策や介入を変えたときにOutcomeがどう変化するかを知りたい場合に選ぶ。
- 例として、「Retention施策で解約はどれだけ減るか」「Coupon配布で購買はどれだけ増えるか」「Process Rule変更でLead Timeは短縮するか」「工程条件変更で不良率は変わるか」等がある。
- 得られた効果の情報は、施策の実施、継続、変更、対象選択、投資配分等の判断に利用する。
- 観測された相関や高い予測性能だけでは介入効果を主張できない。

### 2.3.5. 解約をConcept Anchorとして使う理由

- Open Data / Competition / Enterprise Caseを再調査した結果、Predictive / Causalの適用範囲はCustomer、Industrial、Operations等へ広く存在する。
- その中でもSlide 2では、同一OutcomeのままQuestionだけを変えられる「解約」が、両者の違いを最短で示せる。
- 解約を使うことは、サービス範囲をCRMへ限定する意図ではない。配送遅延、品質、設備停止等でも同じQuestion分解ができる。

### 2.3.6. Exploratory / Data Understandingの扱い

- Exploratory / Data Understandingは、Predictive / Causalのいずれを実施する場合でも、データ品質、分布、傾向、変数間関係、データ生成過程等を把握するために重要である。
- ただし本スライドでは、「Slide 1で示したPredictive / Causalのどちらを選ぶか」というサービス選択の問いに答えることを優先し、Exploratoryを第3の選択肢として主図には置かない。

## 2.4. Speaker Note

Slide 1では、当チームが予測分析と因果推論という2種類のPoCを提供することを示しました。次に生まれるのは、「自社の課題では、どちらを使えばよいのか」という疑問です。

その答えは、アルゴリズムやデータの種類から決めるのではなく、まず業務課題を確認し、その課題について何を知りたいかを明確にすることです。

例えば「解約を減らしたい」という業務課題があるとします。「誰が解約しそうか」を知り、対応対象の優先順位を決めたいのであればPredictiveです。一方、「Retention施策を実施すると解約率がどの程度下がるか」を知り、施策の実施や継続を判断したいのであればCausalです。

この構造は解約に限りません。配送品質なら「どの配送が遅れそうか」と「Process変更で遅延はどれだけ減るか」、品質なら「どの製品が不良になりそうか」と「工程条件変更で不良率はどう変わるか」という形で同じように分けられます。

つまり、同じ業務課題でも、知りたいことが違えば選ぶ分析も変わります。

次のスライドでは、「何が起こりそうか」と「何をするとどう変わるか」が、なぜ同じ分析では答えられないのかを、Predictive / Causalの目的・前提・評価軸の違いから整理します。
