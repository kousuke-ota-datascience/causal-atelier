# 29. Slide 29｜予測分析PoCの適用イメージ

## 29.1. Message

**予測PoCでは、解約等の将来リスクを予測するだけでなく、その確率を使って対応対象を優先し、業務施策へ接続するところまで検証する。**

## 29.2. Chart

**チャートタイトル:** 例：顧客解約予測のPoCストーリー

Messageを説明・論証するための主たる視覚表現として、以下の構造を採用する。

### 29.2.1. Chart Structure

- 既存の論理フロー／概念図を主チャートとして用い、要素間の関係・順序が一目で追える構造にする。

```text
Business Question
解約を減らしたい
        ↓
Prediction Question
次月に解約する顧客は誰か
        ↓
Data / Model
利用履歴・契約・問い合わせ等
        ↓
Prediction
顧客別解約Probability
        ↓
Decision / Action
上位リスク顧客をフォロー
        ↓
PoC評価
予測性能 + 対応可能件数 + 業務価値
```

**PowerPoint上の配置・強調**

- 6段階の縦フローで、Business QuestionからPoC評価までを一枚で示す。
- PredictionとActionの間を太い矢印で強調する。
- ケースの数値は架空にしない。

### 29.2.2. Chart内の最小表示テキスト

実際のPowerPoint上では、以下のラベル・短文を中心に表示する。Supporting Logicの全文をスライド上へ掲載しない。

- Business Question
- 解約を減らしたい
- Prediction Question
- 次月に解約する顧客は誰か
- Data / Model
- 利用履歴・契約・問い合わせ等
- Prediction
- 顧客別解約Probability
- Decision / Action
- 上位リスク顧客をフォロー
- PoC評価
- 予測性能 + 対応可能件数 + 業務価値

## 29.3. Supporting Logic

- 分析対象時点を固定し、将来情報のleakageを防ぐ。
- 現行ルールや全件対応をBaselineとして、モデルによる優先順位付けの増分価値を評価する。
- Precision / Recallだけでなく、実際に対応可能な件数や誤判定コストを踏まえて閾値を検討する。
- モデルの高リスク判定理由はExplainabilityで確認するが、施策が効くことまでは主張しない。

- 補足論点：**予測結果は「誰が解約しそうか」を示し、誰に施策が効くかという次の問いは必要に応じて因果推論へ接続する。**

## 29.4. Speaker Note

具体例は解約に固定するが、故障予測・需要予測などへ読み替え可能な構造にする。
