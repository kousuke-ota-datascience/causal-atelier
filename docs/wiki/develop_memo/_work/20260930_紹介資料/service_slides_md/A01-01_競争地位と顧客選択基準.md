## A01-01.3. Supporting Logic

### A01-01.3.1. 「他社もできる」は正しい

- 大手Consulting FirmはStrategyだけでなくAnalytics / Engineering / AI Implementationまで提供する。
- 大手SIerもConsulting / Analytics / AI Solutionを提供する。
- Data Science専門会社もBusiness ConsultingやSystem構築を提供する場合がある。
- AI VendorもProfessional Servicesを通じてWorkflow / System integrationまで支援する。

従って、競合比較を「このCapabilityができる / できない」で整理すると、ほぼ全社が重なる。

### A01-01.3.2. 差を見る単位をCapability Configurationへ変える

重要なのは、各Providerが、

- どのAssetへ継続投資しているか
- どの人材を多く持つか
- どの案件を繰り返し受注しているか
- どのDelivery Modelを標準としているか
- 顧客から何の専門家として想起されるか

である。

そのため、Capability単体ではなく、**Capability Configuration / Operating Model / Positioningの違い**として比較する。

### A01-01.3.3. 当チームの仮説

当チームはSIer内のデータ分析組織であり、Predictive / Causalの専門分析をスクラッチ中心で提供する。

現時点のPositioning仮説は、

> **Data Science Specialist寄りのAnalytical Flexibility**
>
> ×
>
> **SIerとしてのEnterprise Context**

を一つのPoCで利用できることにある。

この組合せが競争優位になるかは、商談条件とRelevant Competitorによって変わる。次頁では、顧客が何を重視するか自体が商談ごとに変化することを示す。

### A01-01.3.4. 理論的背景

Supplier側のPositioningとCustomer側のSupplier Selectionは別レイヤである。

Kotler系の競争地位論ではLeader / Challenger / Follower / Nicher等の供給側戦略を扱う。一方、Webster & Wind、Sheth等のOrganizational Buying研究では、顧客側の意思決定は複数基準・複数Stakeholderから構成される。

本スライドでは理論分類自体を前面には出さず、顧客向けに「各Providerの競争力の源泉が異なる」という結論へ翻訳している。

## A01-01.4. Speaker Note

確かに、今の大手コンサル、SIer、データサイエンス会社、AI Vendorは、いずれもかなり広い範囲をカバーしています。そのため、「因果推論ができる」「システムまで考えられる」といったCapabilityの有無だけでは差はつきません。

一方で、各社が何を本業として繰り返し提供し、どこへ人材やAssetを集中させているかは異なります。コンサルはStrategyやTransformation、SIerはIntegrationやProduction、AI VendorはProduct化とScale、専門会社は高度分析や柔軟性に強みを作りやすい構造があります。

当チームはその中で、分析専門組織としてのPredictive / Causalやスクラッチ分析と、SIer組織にいることによるEnterprise Contextを組み合わせるPositioningを取っています。ただし、この組み合わせがいつでも最適というわけではありません。案件ごとに顧客が重視することが変わるためです。

## A01-01.5. Appendix A01-01からA01-02への接続
