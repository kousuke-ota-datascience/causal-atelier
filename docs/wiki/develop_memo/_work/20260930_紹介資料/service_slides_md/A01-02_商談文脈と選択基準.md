# A01-02. Appendix｜商談文脈と選択基準

## A01-02.1. Message

**同じ顧客でも、商談文脈によってBuying Centerと選択基準は変わる。**

## A01-02.2. Chart

**チャートタイトル:** Deal Contextによって顧客の評価軸は変化する

### A01-02.2.1. Chart Structure

左から右へ3段階で示す。

```text
Deal Context
──────────────
何を決める？
どのレイヤ？
新規性は？
リスクは？
誰が決める？
どこまで委託？
      ↓
Selection Criteria
──────────────
Deal-specific Fit
Capability
Delivery
Economics
Risk
Evidence
Relationship
Org. Acceptability
      ↓
Vendor Comparison
```

Deal Contextの構成要素は以下の5つを中心に置く。

1. Decision / Problem Locus
2. Buying Situation
3. Perceived Risk / Criticality
4. Buying Center
5. Requested Scope

右側に「同じ顧客でも異なる商談」を3例置く。

```text
全社AI戦略
→ Executive / Strategy中心
→ Fit・Evidence・Governance重視

分析PoC
→ Business / Data-AI中心
→ Fit・Capability・Evidence重視

本番System化
→ IT / Security / Operation中心
→ Delivery・Risk・Org.Acceptability重視
```

### A01-02.2.2. Chart内の最小表示テキスト

- **Deal Context → Selection Criteria → Vendor Comparison**
- Buying Centerは企業固定ではなくDealごとに変わる
- 同じVendorでも商談条件によって評価は変わる

## A01-02.3. Supporting Logic

### A01-02.3.1. B2B購買は商談単位で見る

Webster & WindはB2B購買をorganizational decision-making processとして扱い、Shethは購買関係者ごとに異なるexpectationが存在することを示した。

BUYGRIDではBuying SituationをNew Task / Modified Rebuy / Straight Rebuyに分け、購買の新規性により情報探索や検討プロセスが異なることを示している。

従って、

> 「顧客Aは価格重視」
> 「顧客Bは品質重視」

という固定的な企業評価では粗い。

より正確には、

> **顧客Aの、このDealでは誰が関与し、何を買い、何をリスクと認識しているか**

を見る必要がある。

### A01-02.3.2. Problem / Solution FitをDeal-specificに再定義する

「自社課題へのFit」だけでは、経営課題・業務課題・分析課題・System課題を区別できない。

そこで、Selection Criteriaの1つ目を以下に再定義する。

> **Deal-specific Fit = 今回のDecision Problem / Requested ScopeにProviderの専門性・Operating Modelが適合するか。**

例えば、

- Corporate StrategyならStrategy / Stakeholder Alignment
- Analytical PoCならMethodological Capability
- ProductionならArchitecture / Integration / Security

のFitが重要になる。

### A01-02.3.3. Vendorの強みも条件付きで評価する

以下のような固定表現は避ける。

- コンサルはProblem Fitが強い
- SIerはDeliveryが強い
- DS専門会社はCapabilityが強い

代わりに、

- Corporate / Transformation-levelのNew Taskでは総合コンサルの比較優位が生じやすい
- System / Operation-levelでIntegration / Securityが重い商談ではSIerの比較優位が生じやすい
- Analytical / Methodologicalな非定型課題では専門Analytics組織の比較優位が生じやすい

と条件付きで表現する。

### A01-02.3.4. 数式上の整理

概念的には、Vendor評価を以下と考える。

```text
Vendor Score(V | D)
  = Σ weight_j(D) × score_j(V, D)
```

- `D` = Deal Context
- `weight_j(D)` = そのDealで評価軸jがどれだけ重要か
- `score_j(V,D)` = そのDeal条件下でVendorがどれだけ適合するか

この式は実証モデルではなく、商談依存性を明示するための概念モデルである。

## A01-02.4. Speaker Note

同じ顧客企業でも、全社AI戦略を依頼する場合と、因果推論PoCを依頼する場合と、本番システム化を依頼する場合では、参加する関係者も選択基準も変わります。

全社戦略では経営層や企画部門が中心になり、実績やStakeholder Alignmentが重くなるかもしれません。一方、未知の分析PoCではBusinessとData / AI担当が中心となり、Methodological Capabilityや関連実績が重くなります。本番化ではIT、Security、Operationが加わり、DeliveryやRiskが重要になります。

したがって、競合比較はVendorごとの固定Scoreではなく、Deal Contextに条件付けて行う必要があります。

## A01-02.5. Appendix A01-02からA01-03への接続

> ただし、商談をStrategy / PoC / Productionのような箱へ分けるだけでもまだ粗い。実際の商談は、複数の特性が連続的に変化する。
