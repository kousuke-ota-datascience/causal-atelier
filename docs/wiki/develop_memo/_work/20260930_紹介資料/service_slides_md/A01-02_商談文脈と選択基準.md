# A01-02. Appendix｜商談ごとに変わるProvider選択

## A01-02.1. Message

**顧客は「何でもできる会社」ではなく、今回の商談で重要な条件に強いProviderを選ぶ。**

## A01-02.2. Chart

**チャートタイトル:** 同じ顧客・同じProviderでも、商談が変われば評価軸は変わる

### A01-02.2.1. Chart Structure

左にDeal Context、中央にSelection Criteria、右に「強みが効きやすいProvider」の例を置く。

```text

────────────

分析の難しさ

      ↓

────────────────────

Organizational Acceptability
      ↓

```

右側に3つの商談例を置く。

| 商談例 | 重くなりやすい評価軸 | 強みが効きやすいProvider例 |

| 全社AI戦略・Transformation | Strategy Fit / Evidence / Governance | Consulting Analytics |
| 非定型・高度な分析PoC | Analytical Fit / Capability / Evidence | DS Specialist / Specialist Analytics |
| Production / System Integration | Delivery / Risk / Security / Org. Acceptability | SIer Analytics |

下部に一文を置く。

> **Providerの絶対的な優劣ではなく、「今回のDealとのFit」で選択が変わる。**

### A01-02.2.2. Chart内の最小表示テキスト

- Deal Context
- Selection Criteria
- Provider Fit
- **今回のDealで何が重要か？**
- **その条件に誰の強みが最も合うか？**

## A01-02.3. Supporting Logic

### A01-02.3.1. 顧客の評価基準は固定ではない

B2B購買では、同一企業でも購入対象・新規性・リスク・関係者によって意思決定プロセスが変わる。

Webster & WindはOrganizational Buyingを複数の組織・対人・個人要因を含む意思決定として扱い、Shethは購買関係者ごとに異なるExpectationと、Perceived RiskやPurchase Type等によるJoint Decisionの変化をモデル化した。

BUYGRIDではNew Task / Modified Rebuy / Straight Rebuyにより情報探索や検討の深さが変化する。

従って、「この顧客は価格重視」「この会社は実績重視」と固定的に捉えるより、**今回のDealで誰が何をリスクと感じ、何を買おうとしているか**を見る方が適切である。

### A01-02.3.2. 本資料で用いるSelection Criteria

顧客のProvider選択を、以下8軸で整理する。これは複数研究を統合した本資料独自の分析フレームであり、既存の単一理論名ではない。

1. Deal-specific Fit
2. Capability / Quality
3. Delivery Feasibility
4. Economic Value
5. Risk
6. Evidence / Credibility
7. Relational / Governance Fit
8. Organizational Acceptability

### A01-02.3.3. Deal-specific Fit

特に重要なのがDeal-specific Fitである。

> **今回のDecision Problem / Requested Scopeに、Providerの専門性・Operating Modelが適合するか。**

例えば、

- Corporate StrategyならStrategy / Stakeholder Alignment
- 非定型Analytical PoCならMethodological Capability / Flexibility
- ProductionならArchitecture / Integration / Security

がFitの主要因になりやすい。

### A01-02.3.4. 当チームへの意味

当チームがすべての評価軸で常に最高である必要はない。

重要なのは、当チームのCapability Configurationが顧客にとって重要になるDealを明確にすることである。

当チームの仮説上、

- Analytical Complexityが高い
- Standard Solutionへ載せにくい
- Enterprise利用条件を無視できない

という条件では、Specialist AnalyticsとEnterprise Baseの双方が評価対象になりやすい。

### A01-02.3.5. 概念モデル

内部分析では、Deal `D` におけるVendor `V` の評価を以下のように考える。

```text
Vendor Score(V | D)
  = Σ weight_j(D) × score_j(V, D)
```

これは実証済みの定量モデルではなく、商談ごとに評価WeightとProvider Fitが変わることを表現するための概念モデルである。

顧客向けには数式そのものより、**「今回の案件では何が重要か」→「その条件に誰が強いか」**という読み方を伝える。

## A01-02.4. Speaker Note

各社の強みの源泉が違っていても、どの会社が最適かは案件によって変わります。

例えば全社AI戦略なら、経営課題の整理やStakeholder Alignment、変革実績が重要になります。一方で、まだ解き方が定まっていない分析PoCなら、方法論の専門性や柔軟性が重要になります。本番System化なら、Integration、Security、Delivery Riskの比重が上がります。

つまり、顧客は会社名だけで選ぶのではなく、今回の案件で重要な条件とProviderの強みがどれだけ合うかを見ています。当チームについても同じで、次に「どのような案件条件で当チームの組み合わせが効くのか」を、より連続的なDeal Profileとして見ます。

## A01-02.5. Appendix A01-02からA01-03への接続

> ただし、実際の案件は「戦略」「PoC」「本番化」のような箱にきれいに分かれない。商談特性を連続的に捉えると、各Providerの強みが効く領域をより正確に説明できる。
