## A01-04b.3. Supporting Logic

### A01-04b.3.1. このProfileの特徴

分析方法自体を個別設計する必要があり、同時にPoC後のData / System / Security / Operation / Governanceも無視できない案件。

### A01-04b.3.2. ProviderごとのFit仮説

- **当チーム**：Predictive / Causal、Scratch / OSS、前提・評価設計とEnterprise Contextの双方が同時に価値化しやすい。
- **SIer Analytics**：Enterprise接続では有力。Analytical Complexityが高い場合は、該当組織の専門人材・方法論Capabilityが勝敗を左右する。
- **Consulting Analytics**：高度分析に加えてTransformation / Governanceまで含む場合は有力。Hands-on PoCのDelivery ModelやEconomicsは個社差が大きい。
- **DS Specialist**：高度分析では有力。Enterprise Integration / Security / Operationが重くなるほど追加Capabilityが必要になる。
- **AI / Platform Vendor**：Product Fitが高ければ有力だが、非定型性が高いほど標準化の強みが効きにくくなる可能性がある。

### A01-04b.3.3. 当チームのPosition

> **重点Positioning候補 / Right-to-Win検証対象。**

このProfileは当チームのCapability Bundle全体が最も活きやすい。一方、他SIer AnalyticsやConsulting Analyticsも同じ領域へ入れるため、現時点で「最優位」「空白地帯」とは主張しない。

検証すべきCompetitive Gap候補は、

- 方法論専門性
- SpecialistへのDirect Access
- PoCの柔軟性
- Product非固定
- Enterprise組織への接続
- Price / Lead Time
- Relevant Evidence

である。

## A01-04b.4. Speaker Note

このProfileは、現在最も当チームのPositioningと整合する候補です。高度な分析だけでも、Enterprise実装だけでもなく、両方が同時に重要になるためです。ただし、この領域は競合の空白地帯ではありません。他SIer AnalyticsやConsulting Analyticsも有力です。したがって「ここなら必ず勝てる」ではなく、「ここで当チームのCapability Bundleが最も価値化しやすく、競争優位を検証すべき」と捉えます。

## A01-04b.5. 次頁への接続

> 分析難易度が下がり、Enterprise接続が中心になると、当チームの分析専門性が差になりにくくなる。
