# 9. Slide 9｜PoC開始条件と成功基準

## 9.1. Message

**PoC開始時に「問い・Decision・データ・成功基準」を合意し、終了時は分析精度だけでなく業務利用可能性まで含めてGo / No-Goを判断する。**

## 9.2. Chart

**チャートタイトル:** Start GateとExit Gate

Messageを説明・論証するための主たる視覚表現として、以下の構造を採用する。

### 9.2.1. Chart Structure

- 既存の論理フロー／概念図を主チャートとして用い、要素間の関係・順序が一目で追える構造にする。

```text
START GATE                           EXIT GATE
┌─────────────────┐                ┌─────────────────┐
│ Business Question│                │ 分析成立性       │
│ Decision / Action│   PoC実施      │ 妥当性・再現性   │
│ Data availability│ ───────────▶   │ 業務価値・利用性 │
│ Success Criteria │                │ 次フェーズ条件   │
└─────────────────┘                └─────────────────┘
```

**PowerPoint上の配置・強調**

- 左右にStart Gate / Exit Gateを置き、中央にPoC実施を配置する。
- Exit Gateは技術・科学・業務の3観点が含まれることを示す。
- 数値閾値は案件ごとに設定するため、この資料では固定しない。

### 9.2.2. Chart内の最小表示テキスト

実際のPowerPoint上では、以下のラベル・短文を中心に表示する。Supporting Logicの全文をスライド上へ掲載しない。

- START GATE                           EXIT GATE
- Business Question
- 分析成立性
- Decision / Action
- PoC実施
- 妥当性・再現性
- Data availability
- 業務価値・利用性
- Success Criteria
- 次フェーズ条件

## 9.3. Supporting Logic

- 開始時：Business Question、Decision / Action、対象Population、TargetまたはTreatment / Outcome、利用可能データを整理する。
- 開始時：Baseline、制約条件、PoC成功基準を合意する。
- 終了時：分析上の問いに答えられたか、結果の妥当性は十分かを確認する。
- 終了時：業務上意味のある差・精度か、実際の業務プロセスへ接続できるかを確認する。
- 判断はGo / No-Goだけでなく、Additional ValidationやData Acquisitionも選択肢とする。

- 補足論点：**成功基準を事前合意することで、「後から都合のよい指標を選ぶPoC」を避け、次フェーズ判断を明確にする。**

## 9.4. Speaker Note

PoCのSuccess Criteriaは案件ごとに異なる。予測ではbaseline超過や業務閾値、因果では識別可能性・診断・不確実性などが中心となる。
