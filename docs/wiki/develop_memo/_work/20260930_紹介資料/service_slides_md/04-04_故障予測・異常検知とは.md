# 14. Slide 14｜重点テーマ：故障予測・異常検知とは

## 14.1. Message

**異常検知は現在の状態変化を捉え、故障予測は将来の故障・劣化を見通す。**

## 14.2. Chart

**チャートタイトル:** 設備状態を「現在」と「将来」に分けて捉え、保全判断へつなげる

### 14.2.1. Chart Structure

設備・センサーデータを起点に、左側を「現在を捉える」、右側を「将来を見通す」とした2列比較を置き、下段で共通の保全Decisionへ収束させる。

```text
設備・センサーデータ
運転条件 / 点検履歴 / 故障履歴
        ↓
┌────────────────────┬────────────────────┐
│ 現在を捉える       │ 将来を見通す       │
│                    │                    │
│ 異常検知           │ 故障予測           │
│ 状態監視           │ 故障確率           │
│ 変化点検知         │ RUL / 劣化予測     │
│                    │ Time-to-Failure    │
└────────────────────┴────────────────────┘
        ↓
Anomaly / State Evidence   Failure Risk / Remaining Life
        ↓
保全Decision
点検優先順位 / 交換判断 / 保守時期・計画
```

**PowerPoint上の配置・強調**

- 2列の違いを主役にし、アルゴリズム名は置かない。
- 左列は「現在の通常状態からの逸脱」、右列は「将来Outcome」を対象とする違いが一目で分かるようにする。
- 下段で両者を同じ保全Decisionへ接続し、重点テーマがModel分類ではなく業務判断の支援であることを示す。
- 最下部に `Anomaly Score ≠ Failure Probability` を短い境界注記として置く。

### 14.2.2. Chart内の最小表示テキスト

- 設備・センサーデータ
- **現在を捉える**
- 異常検知 / 状態監視 / 変化点検知
- **将来を見通す**
- 故障予測 / 故障確率 / RUL・劣化予測
- **保全Decision**

## 14.3. Supporting Logic

### 14.3.1. Slide 14の役割

- Slide 11〜13ではPredictiveを一般論として定義し、適用条件と価値発現を示した。
- Slide 14〜16では、その一般原則を当チームの重点テーマである設備の故障予測・異常検知へ具体化する。
- 本スライドではまず、異常検知と故障予測を同義にせず、**何を推定しているかという分析上の違い**を固定する。

### 14.3.2. 異常検知と故障予測は問いが異なる

| 分析課題 | 主な問い | 代表Output | 主な利用イメージ |
|---|---|---|---|
| 異常検知 | 現在の状態は通常状態から外れているか | Anomaly Score / Flag | 追加確認、点検候補抽出 |
| 状態・変化検知 | 状態がいつ・どのように変わったか | State / Change Point | 劣化兆候の把握、監視 |
| 故障予測 | 一定期間内に故障する可能性はどの程度か | Failure Probability / Risk | 点検・交換の優先順位 |
| RUL / Time-to-Failure | あとどの程度稼働できるか | Remaining Life / Time | 交換・保守時期の判断 |

- 異常検知は、必ずしも将来のFailure Outcomeを教師信号として学習する分析ではない。
- 故障予測は、Prediction Timeより後に発生するFailure EventやTime-to-event等をTargetとする典型的なPredictive Questionである。
- したがって、**異常であることから将来故障すると自動的に結論しない**。Anomaly ScoreとFailure Probabilityの意味を分ける。

### 14.3.3. 一連の保全分析テーマとしては接続できる

設備保全では、実務上は以下を組み合わせることがある。

```text
状態監視
  ↓
異常・変化の早期把握
  ↓
故障Risk / 劣化 / RULの推定
  ↓
点検・交換・保守Decision
```

- すべての案件でこの全工程を実施するわけではない。
- 利用可能なData、故障Label、Prediction Horizon、業務Decisionに応じて、どの問いをPoC対象にするかを定義する。

### 14.3.4. Scientific boundary

- Anomaly ScoreはFailure Probabilityではない。
- 異常を検知したFeatureが故障の原因であるとは限らない。
- 高いFailure Riskは、特定の保全施策による改善効果が大きいことを意味しない。
- 故障後にしか得られない情報を故障予測Featureへ含めない。
- 複数設備・時系列データでは、設備IDや将来期間の情報がTrain / Testへ漏れないValidationが必要である。

## 14.4. Speaker Note

設備領域では、故障予測と異常検知を重点テーマとして扱います。ただし、両者は同じ分析ではありません。

異常検知は主に「現在の状態が通常と違うか」を捉えます。一方、故障予測は「将来、一定期間内に故障する可能性がどの程度あるか」、RULは「あとどの程度使えるか」を見通します。

実務ではこれらを組み合わせる場合がありますが、異常Scoreが高いことをそのまま故障確率と解釈してはいけません。PoCでは、利用できる設備データと保全上のDecisionを確認し、どの問いを扱うかを先に定義します。
