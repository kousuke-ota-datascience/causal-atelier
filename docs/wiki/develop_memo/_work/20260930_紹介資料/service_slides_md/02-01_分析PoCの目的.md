# 6. Slide 6｜分析PoCの目的

## 6.1. Message

**PoCは、分析の成立性だけでなく、業務判断への利用可能性まで検証する。**

## 6.2. Chart

**チャートタイトル:** 分析PoCで検証する3つの観点

PoCの評価対象を、モデルや推定値そのものに限定せず、**分析成立性・業務利用性・次フェーズ判断**の3つの観点で示す。

### 6.2.1. Chart Structure

PowerPoint上では、横3列の単一チャートとして構成する。

```text
┌──────────────────────┬──────────────────────┬──────────────────────┐
│ ① 分析成立性         │ ② 業務利用性         │ ③ 次フェーズ判断     │
├──────────────────────┼──────────────────────┼──────────────────────┤
│ 問いに対して         │ 分析結果を           │ PoC結果を根拠に      │
│ 妥当な結果を         │ Decision / Actionの  │ 次に進むかを         │
│ 再現可能に得られるか │ 判断材料にできるか   │ 判断できるか         │
└──────────────────────┴──────────────────────┴──────────────────────┘
            ↓                     ↓                     ↓
      分析結果だけで終わらず、次の業務判断につながるEvidenceを残す
```

**PowerPoint上の配置・強調**

- 3列は左から `分析成立性 → 業務利用性 → 次フェーズ判断` の順に読ませる。
- `分析成立性` では、モデル構築やEffect Estimateの算出自体ではなく、対象の問いに対して妥当な結果を再現可能に得られるかを示す。
- `業務利用性` では、結果を誰かのDecision / Actionに利用できる判断材料として解釈できるかを示す。利用者・利用タイミング・具体的Action等の詳細設計は後続スライドで扱う。
- `次フェーズ判断` では、本番化、追加検証、追加データ取得、中止等について、PoC結果を根拠に判断できる状態を示す。個別のSuccess Criteriaは後続スライドで扱う。
- 最下段に3列を束ねる共通メッセージとして「分析結果だけで終わらず、次の業務判断につながるEvidenceを残す」を配置する。
- Predictive / Causal固有の評価指標や手法は本スライドでは扱わず、後続の各分析章へ分離する。

### 6.2.2. Chart内の最小表示テキスト

**① 分析成立性**

- 問いに対して妥当な結果を得られるか
- 再現可能か

**② 業務利用性**

- Decision / Actionの判断材料にできるか

**③ 次フェーズ判断**

- 本番化 / 追加検証 / 中止を判断できるか

**共通**

- **分析結果だけで終わらず、次の業務判断につながるEvidenceを残す**

## 6.3. Supporting Logic

### 6.3.1. Slide 6の役割

- Slide 1〜4では、Predictive / Causalが提供する判断材料と、それを業務Actionへ利用した場合の期待効果を示した。
- Slide 5では、当チームが問いに合う分析設計、非定型課題への柔軟な実装、Enterprise利用条件の考慮を一つのPoCで扱うことを示した。
- Slide 6では、そこからPoC共通設計へ入り、**PoCで何を検証対象とするか**を定義する。
- 業務課題から問い・Decisionをどう接続するか、分析結果を誰がいつどう使うか、PoCをどの工程で進めるか、Success Criteriaをどう定義するかは、それぞれ後続スライドで具体化する。

### 6.3.2. ① 分析成立性

- Predictiveでは、適切に分離した未知データに対して、業務利用を検討できる予測性能が再現するかを評価する。単一のAccuracyだけでなく、案件に応じてCalibration、Error Pattern、Segment別性能、誤判定コスト等も確認する。
- Causalでは、対象とするCausal Question / Estimandに対し、Identification Assumption、Estimation、Diagnostics / Sensitivity等を踏まえて、どの前提のもとでどこまでEffectを主張できるかを評価する。
- したがって「モデルが学習できた」「Effect Estimateを算出できた」こと自体は、分析成立性を示す十分条件ではない。
- 分析条件、前提、データ、評価方法、結果を追跡でき、同じ条件で結果を再確認できることも重要である。

### 6.3.3. ② 業務利用性

- 分析上妥当な結果が得られても、それを利用するDecision / Actionがなければ業務価値には接続しにくい。
- PoCでは、分析結果が「誰の、どの判断に、どのような形で使えるか」を検討し、判断材料として解釈可能な状態にする。
- Predictiveでは、予測を利用して対象、時期、量、優先順位等を変えられるかが重要となる。
- Causalでは、推定した効果と不確実性を、施策の実施・継続・変更等の判断へ利用できるかが重要となる。
- ただし、分析結果を利用したことからBusiness Outcomeが改善すると無条件には言えない。運用条件や実際のAction、その後の環境変化等も影響する。

### 6.3.4. ③ 次フェーズ判断

- PoCは、本番化を必ず前提とする工程ではなく、不確実性を減らして次の判断を行うための検証である。
- 終了時には、分析結果だけでなく、成立した条件、利用可能範囲、限界、残存リスク、追加データ・追加検証の必要性を整理する。
- そのEvidenceをもとに、本番化、追加PoC、追加データ取得、Scope変更、中止等を判断できる状態を目指す。
- 「良いモデルができた」「統計的有意差が出た」といった分析上の結果だけをPoC成功と定義しない。

### 6.3.5. PoC成果の考え方

```text
モデル / Effect Estimate
        ↓
分析条件・前提・評価・限界を含む分析結果
        ↓
Decision / Actionに利用できる判断材料
        ↓
本番化 / 追加検証 / 中止等の次フェーズ判断
```

- モデルやEffect Estimateは重要な成果物だが、PoCの最終目的そのものではない。
- PoCの成果は、**何が分かり、何がまだ分からず、その結果を使って次に何を判断できるか**を説明できる状態として捉える。
- この考え方により、十分な性能や識別可能性が得られなかった場合でも、追加データ取得やScope変更、中止を合理的に判断できるなら、PoCは意思決定Evidenceを提供している。

## 6.4. Speaker Note

ここからは、予測分析と因果推論に共通するPoCの設計を説明します。

PoCというと、モデルを作って精度を測ることや、因果効果を推定することが目的に見えやすいですが、それだけでは次の業務判断にはつながりません。当チームでは、PoCで確認する対象を3つに分けて考えます。

一つ目は分析成立性です。対象の問いに対して、妥当な分析結果を再現可能な形で得られるかを確認します。予測であれば未知データでも性能が保たれるか、因果であれば必要な前提のもとでどこまで効果を主張できるか、といった観点です。

二つ目は業務利用性です。分析結果が得られても、誰のどの判断にも使われなければ業務価値にはつながりません。そのため、結果をDecisionやActionの判断材料として利用できるかを確認します。

三つ目は次フェーズ判断です。PoCの終了時には、本番化するのか、追加検証や追加データが必要なのか、あるいは中止するのかを、PoCで得たEvidenceを根拠に判断できる状態を目指します。

つまりPoCの成果は、モデルや推定値だけではなく、「何が分かり、何がまだ分からず、その結果を使って次に何を判断できるか」を整理することです。

## 6.5. Slide 6からSlide 7への接続

> **分析結果を業務判断に使えるか検証するには、まず「誰が、何を、どう決めるのか」を明確にする必要がある。次に、業務課題からDecisionまでの接続を整理する。**
