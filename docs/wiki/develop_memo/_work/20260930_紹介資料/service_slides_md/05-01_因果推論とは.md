# 18. Slide 18｜因果推論とは

## 18.1. Message

**因果推論は、観測された関連ではなく「Treatmentを変えたときOutcomeがどう変わるか」という反実仮想の問いを扱う。**

## 18.2. Chart

**チャートタイトル:** Observationでは見えない「もう一方の結果」を推論する

### 18.2.1. Chart Structure

Customer Retentionを最小例として、左から右へ3段階で示す。

```text
① Observation
Retention施策あり群   解約率 低
Retention施策なし群   解約率 高
        ↓
この差だけでは施策効果とは言えない
        ↓
② Counterfactual Question
同じ対象に対して
施策あり / なしを切り替えたら
解約はどれだけ変わるか？
        ↓
③ Causal Effect
Y(1) - Y(0)
ただし同じ対象の両方は同時に観測できない
→ 比較可能性を作るDesign / Assumptionが必要
```

**PowerPoint上の配置・強調**

- 左：観測された群間差。
- 中央：同一対象の2つのPotential Outcomeを上下に置き、片方が未観測であることを視覚化する。
- 右：`Treatment Effect = Counterfactual Difference` を置く。
- 数式は `Y(1) - Y(0)` 程度に留める。
- 最下部に `観測差 ≠ 因果効果` を短く置く。

### 18.2.2. Chart内の最小表示テキスト

- Observation｜施策あり群となし群で結果が違う
- **観測差 ≠ 因果効果**
- Counterfactual｜同じ対象で施策あり / なしなら？
- `Y(1)` / `Y(0)`
- **Treatment Effect = Y(1) - Y(0)**
- 両方は同時に観測できない
- Design / Assumptionで比較可能性を作る

## 18.3. Supporting Logic

### 18.3.1. Slide 18の役割

- Section 04では、Predictiveを「Decision時点の情報から未知・将来のOutcomeを予測し、Outcome判明前のActionへ使う分析」と定義した。
- Section 04の最後では、Predictionが高性能でも、それ自体から「その対象へ特定施策を行えばOutcomeが改善する」とは言えない境界を明示した。
- **Slide 18では、その境界の先にあるCausalの推論対象を、ObservationではなくIntervention / Counterfactualとして定義する。**
- このSlideで確定するのは「因果推論とは何を推論する分析か」であり、具体的なEstimand、DAG、Identification Strategy、Estimatorは後続Slideへ分離する。
- 次のSlide 19では、同じCustomer Retentionの課題でPrediction RiskとTreatment Effectを並べ、両者が異なるTargetであることを具体化する。

### 18.3.2. ObservationとInterventionは答える問いが異なる

- 観測データで `Treatmentあり群の解約率 < Treatmentなし群の解約率` が見えても、それはまずGroup間のAssociationを表している。
- Treatmentを受けるかどうかが顧客属性、担当者判断、過去行動、契約状況等に依存していれば、群間差にはTreatment Effect以外の差が混在し得る。
- 因果推論が知りたいのは、**Treatment assignmentを変えたとき、同じ対象または同じ対象PopulationのOutcomeがどう変化するか**である。
- したがって、単なる `E[Y|T=1] - E[Y|T=0]` と、因果Estimandとしての平均Treatment Effectは一般には同一ではない。
- 「施策群の成績が良い」という観測事実と、「施策を実施したため成績が改善した」という因果主張を分けることが出発点になる。

### 18.3.3. Potential OutcomeとFundamental Problem

- Potential Outcomesの枠組みでは、各UnitについてTreatment状態ごとのOutcomeを考える。
  - `Y(1)`：そのUnitがTreatmentを受けた場合のOutcome。
  - `Y(0)`：そのUnitがTreatmentを受けなかった場合のOutcome。
- Individual Treatment Effectは概念上 `Y(1) - Y(0)` で表せるが、同一Unitについて観測できるのは実際に選択されたTreatment状態に対応するOutcomeだけである。
- もう一方のPotential OutcomeはCounterfactualであり直接観測できない。これがFundamental Problem of Causal Inferenceである。
- そのため実務では、Individual Effectを直接観測するのではなく、ATE、ATT、CATE等のPopulation-level / Conditional Effectを、適切な比較設計とAssumptionのもとで推論する。
- 「Counterfactualをどう補うか」が、後続のRandomization、Covariate Adjustment、DiD、RD、IV等のIdentification Strategyにつながる。

### 18.3.4. 比較可能性はDesign / Assumptionで作る

- Randomized Experimentでは、Treatment AssignmentをRandomizeすることで、Treatment以外の要因が群間で系統的に偏らない比較を設計する。
- Randomizationが実務上可能でない場合、Observational DataからCausal Effectを識別するために追加のAssumptionが必要になる。
- 代表例として、Pre-treatment Confounderを条件付けた交換可能性、Positivity、Consistency、DiDのParallel Trends、IVのExclusion Restriction等がある。
- これらのAssumptionは「因果推論という手法を使えば自動的に満たされる」ものではなく、業務Process、Treatment Assignment、Data Generating Processと照合して妥当性を検討する。
- したがって因果PoCでは、Estimatorの性能比較より前に、**何を比較対象とみなし、なぜその比較をCounterfactualとして使えるのか**を設計する必要がある。

### 18.3.5. 因果推論の出力は「原因一般」ではなく定義されたEffectである

- 因果推論の成果を「原因を発見した」「因果関係がある / ない」という一般的な二値判定として扱わない。
- EffectはTreatment、Outcome、Population、Time、Contrastに依存する。
- 例えば同じRetention施策でも、既存全顧客に対するATE、実際に施策を受けた顧客に対するATT、特定Segmentに対するCATEでは、答えるBusiness Decisionが異なる。
- 効果があるPopulationでも、別Population、別施策強度、別期間へ無条件にGeneralizeできるとは限らない。
- したがって、後続Slide 23でCausal QuestionをEstimandまで具体化し、「何の効果を主張するか」を固定する。

### 18.3.6. Predictiveとの境界を維持する

- Predictive Modelは、Outcomeを予測するために有用なAssociationを利用できれば成立し得る。FeatureとOutcomeの関係がCausalであることはPredictive Performanceの必要条件ではない。
- 一方、Causal QuestionではTreatmentを変更した際のOutcome差を推論するため、Counterfactual ComparisonとIdentificationが必要になる。
- 高いAUROC、低いRMSE、Feature Importance、SHAP等は、Treatment Effectを直接示すEvidenceではない。
- 「解約しそうな顧客」と「Retention施策によって解約が減る顧客」が一致しない可能性を、次Slideで具体的に示す。

## 18.4. Speaker Note

ここからは因果推論について説明します。最初に区別したいのは、**観測された差**と、**施策によって生じた差**です。

たとえばRetention施策を受けた顧客の解約率が、受けていない顧客より低かったとします。この事実だけを見ると施策が効いたように見えます。しかし、実際には担当者が解約しにくい顧客へ施策を出していた、契約状況の良い顧客だけが施策対象になっていた、といった可能性があります。つまり、観測された群間差には施策以外の違いが混ざり得ます。

因果推論で知りたいのは、同じ顧客について、施策を行った場合の結果 `Y(1)` と、行わなかった場合の結果 `Y(0)` がどれだけ違うかです。ただし同じ顧客について両方の結果を同時に観測することはできません。これが因果推論の基本的な難しさです。

そこで、A/B Testのように比較可能な群を実験で作るか、観測データであればTreatmentの割付がどう決まったか、どの交絡要因を観測できているかといった前提を整理し、Counterfactualとして使える比較を設計します。因果推論の専門性は、単に特定のEstimatorを適用することではなく、**なぜその比較から施策効果を読み取れるのかを説明できること**にあります。

また、因果推論の出力は「原因が分かった」という一般論ではありません。誰に対する、どの施策の、どのOutcomeへの、どの期間の効果なのかを明確にしたうえで、その範囲についてEffectを推論します。この点を後続のスライドで具体化していきます。
