# 12. Slide 12｜予測分析が適する業務課題

## 12.1. Message

**予測分析は、結果が出る前に予測を使って対象・時期・量を変えられる業務で特に有効である。**

## 12.3. Supporting Logic

### 12.3.1. Slide 12の役割

- Slide 11では、Predictiveを `Decision時点で利用可能な観測情報 → Prediction → Decision / Action` として定義し、Predictionの価値はOutcomeが判明する前に判断を変えられることにあると示した。
- Slide 6〜10では、Predictive / Causalに共通して、DecisionからAnalysis Questionを逆算し、利用ルール、PoC工程、Start Gate / Exit Gateを設計する考え方を示した。
- **Slide 12では、これらをPredictiveの適用判断へ具体化し、「どのような業務構造ならPredictionをActionへ接続しやすいか」を示す。**
- Slide 13では、そのPredictionをActionへ利用した場合に、どのような期待効果へ接続し得るかをValue Chainとして示す。そのため本スライドではBusiness Outcomeの種類を主題にしない。

### 12.3.2. Predictive PoC候補となる3条件

#### 12.3.2.1. ① BEFORE｜Outcomeが判明する前にDecisionがある

- Predictiveの価値は、未知・将来のOutcomeに関する見通しを、Outcome確定前のDecisionへ利用することにある。
- Outcomeが判明した後にしかActionできない業務では、PredictionによってDecisionを先回りさせる価値は生じにくい。
- したがって、「何を予測するか」だけでなく、**いつDecisionし、Outcomeはいつ確定し、Actionにどの程度のLead Timeが必要か**を確認する必要がある。
- 例えば、解約対応は実際の解約前、配送対応は遅延確定前、設備保全は停止前にPredictionを利用できることが前提となる。

#### 12.3.2.2. ② CHANGE｜Predictionに応じて変更可能なActionがある

- Predictionは判断材料であり、それ自体が業務価値ではない。
- Predictionを見ても何も変更できない場合、分析結果を業務Actionへ接続する経路が弱い。
- Predictiveで変更対象になりやすいActionには、以下がある。
  - **Prioritize**：どの対象へ先に対応するか。
  - **Review / Escalate**：どの案件を重点確認・追加審査するか。
  - **Schedule**：いつ点検、交換、Follow-up等を実施するか。
  - **Allocate / Plan**：人員、時間、Capacity等をどこへ配分するか。
- Actionは案件ごとに異なり、Predictionが自動的にActionを決めるわけではない。実際の利用時にはDecision Ruleや業務制約を介して判断する。

#### 12.3.2.3. ③ DIFFERENTIATE｜Predictionによって判断を変える余地がある

- 予測分析が特に有効なのは、対象、案件、時点等によってRiskや将来状態が異なり、それに応じてActionを差別化できる業務である。
- すべての対象へ同じActionを実施でき、かつそれが合理的である場合、個別Predictionによる優先順位付けの追加価値は小さい場合がある。
- 一方、対応可能件数、検査能力、保全要員、処理Capacity等に制約があり、全件へ同じ強度で対応できない場合、Predictionは限られたResourceの配分判断に利用しやすい。
- ただし、Predictionによる差別化が業務上許容されるかは別途確認が必要である。公平性、規制、契約条件、安全上の要件等により、Predictionに応じたAction変更へ制約がある場合がある。

### 12.3.3. 適用候補とTechnical Feasibilityを分ける

- 上記3条件は、**業務課題としてPredictiveを検討する価値があるか**を見るための条件であり、十分な予測性能を事前に保証するものではない。
- 実際にPredictionを業務で利用できるかはPoCで検証する。案件に応じて、少なくとも以下を確認する。
  - Decision時点で利用可能なFeatureとTarget / Outcomeを構成できるか。
  - Target Leakage / Future Leakageを避けた検証ができるか。
  - 適切に分離した未知データで、Baselineに対して有用な予測性能が再現するか。
  - Probability等を判断材料に使う場合、Calibrationが利用目的に対して十分か。
  - False Positive / False Negativeや予測誤差が、業務コストやCapacity制約に対して許容可能か。
  - 時間変化、対象母集団の変化、データ取得条件の変化によって性能が崩れないか。
- これらはSlide 14以降のPredictive固有workflow、Model Evaluation、Go / No-Goで具体化する。

### 12.3.4. 代表ユースケースは業界ではなくAction構造で見る

公開Competition、Open Data / Public Dataset、企業公開事例を再整理すると、Predictive Analyticsの適用対象はCustomer、Operations / Logistics、Business Process、Quality、Maintenance、Risk等へ広く存在する。

本スライドでは、サービスScopeを特定Domainへ限定して見せないため、以下のようにAction構造で代表例を整理する。

| Action構造 | Prediction Questionの例 | Prediction後のAction |
|---|---|---|
| Prioritize | 誰が解約しそうか / どの製品が不良になりそうか | Follow-up / 検査対象を優先 |
| Review / Escalate | どの配送が遅れそうか / どのCaseがDeviationしそうか | High-risk案件を重点管理 |
| Schedule | どの設備が停止しそうか / あとどの程度使えるか | 点検・交換時期を調整 |
| Allocate / Plan | Case完了までどの程度かかりそうか | 人員・Capacity配分を調整 |

- CustomerではChurn / Response、OperationsではDelivery Delay / Process Completion、QualityではDefect、MaintenanceではFailure / Remaining Useful Life等の公開Problemが存在する。
- これらはPrediction Target自体が異なっても、**Outcome判明前にPredictionを使ってActionを変える**という共通構造を持つ。
- 故障予測は有力なIndustrial Use Caseの一つだが、Predictive Service全体を代表する唯一の例ではない。

### 12.3.5. PredictiveとCausalの境界

- `高Riskな対象を見つけて対応優先順位を決める` ことはPredictiveの代表的な利用方法である。
- ただし、`高Riskな対象` と `特定施策によって最もOutcomeが改善する対象` は一致するとは限らない。
- 例えばChurn Riskが高い顧客を予測できても、Retention施策によるTreatment Effectが大きい顧客であるとは限らない。
- Predictionを原因分析や施策効果として解釈せず、施策によるOutcome変化を知りたい場合はCausal Questionとして別途扱う。

## 12.4. Speaker Note

前のスライドでは、予測分析を「結果がまだ分からない時点でPredictionを得て、事前のDecisionやActionへ使う分析」と整理しました。では、どのような業務で予測分析を使いやすいのでしょうか。

ポイントは、特定の業界やアルゴリズムではなく、業務の構造です。まず、結果が分かる前に何らかのDecisionがあること。次に、Predictionを見た後で対象、時期、量、優先順位等のActionを変えられること。そして、全件へ同じ対応をするのではなく、対象や時点によって判断を変える余地があることです。

例えば、解約Riskや不良Riskを使って対応対象を優先する、配送遅延Riskを使って重点管理する、設備停止RiskやRULを使って点検・交換時期を調整する、Case完了時間を使って人員やCapacityを配分するといった使い方があります。予測対象は違っても、「Outcomeが分かる前に見通しを使ってActionを変える」という構造は共通しています。

一方、この条件を満たすからといって、実際に十分な予測精度が得られるとは限りません。Decision時点で使えるデータがあるか、未来情報の混入なく未知データで性能が再現するか、誤りのコストが許容できるかはPoCで検証します。

また、高Riskな対象が、特定施策で最も改善する対象とは限りません。施策効果を知りたい場合は、予測とは別に因果の問いを立てます。

次のスライドでは、このようにPredictionをActionへつなげたとき、限られた人・時間・予算の配分や業務効率にどのような期待効果が生まれ得るかを整理します。

## 12.5. Slide 12からSlide 13への接続

> **予測分析の適用候補は、Outcome判明前にPredictionを使ってActionを変えられる業務である。では、そのAction変更はどのような業務効果へ接続し得るのか。**
