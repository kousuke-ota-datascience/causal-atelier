# A01-02. Appendix｜顧客がProviderを選ぶ8つの基準

## A01-02.1. Message

**顧客は、Fit・品質・実行力・価値・Risk・信頼性・協働性・社内承認性でProviderを比較する。**

## A01-02.2. Chart

**チャートタイトル:** Provider選定を8つのCustomer Selection Criteriaで捉える

### A01-02.2.1. Chart Structure

中央に、Provider選定に用いる8軸と「顧客が実際に確認したい問い」を対応させる。

| # | Customer Selection Criteria | 顧客の問い |
|---:|---|---|
| 1 | **Deal-specific Fit** | 今回の課題・Decision Problem・委託範囲に合っているか |
| 2 | **Capability / Quality** | 必要な専門性を持ち、高品質に遂行できるか |
| 3 | **Delivery Feasibility** | 時間・体制・Data / System条件の中で現実に完遂できるか |
| 4 | **Economic Value** | 費用・顧客側工数・後続Costに対して価値が見合うか |
| 5 | **Risk** | 失敗・不確実性・Security・依存・Lock-in等を許容できるか |
| 6 | **Evidence / Credibility** | 「できる」という主張を実績・人材・Reference等から信じられるか |
| 7 | **Relational / Governance Fit** | Communication・責任分界・意思決定を含め一緒に進められるか |
| 8 | **Organizational Acceptability** | Procurement・Legal・Security・Managementを含め社内で選定・承認できるか |

表の下に以下を置く。

> **CapabilityだけでProviderは決まらない。専門サービスの購買は、複数基準・複数Stakeholderによる組織的意思決定である。**

右下に注記する。

> ※この8軸は単一の既存理論ではなく、Organizational Buying / Industrial Buyer Behavior / Professional Service Selection / TCE等を統合した本資料用フレーム。

### A01-02.2.2. Chart内の最小表示テキスト

- Deal-specific Fit
- Capability / Quality
- Delivery Feasibility
- Economic Value
- Risk
- Evidence / Credibility
- Relational / Governance Fit
- Organizational Acceptability
- **Capabilityだけでは決まらない**

## A01-02.3. Supporting Logic

### A01-02.3.1. なぜ8軸で見るのか

分析PoCはB2B Professional Serviceであり、購入前に最終品質を完全には観測できない。また、実際の発注判断には事業部門だけでなくData / AI、IT、Security、Procurement、Legal、Management等が関与し得る。

そのため、単純な「技術力」「価格」「実績」の3軸だけではSupplier Selectionを十分に説明できない。

Webster & Wind (1972)はOrganizational Buyingを、Environmental / Organizational / Interpersonal / Individualな影響を受ける組織的意思決定としてモデル化した。[T1]

Sheth (1973)はIndustrial Buyer Behaviorにおいて、Engineer / User / Purchasing Agent等の関係者が異なるExpectationを持ち、Quality、Delivery、Price、After-sales Service等を異なるWeightで評価し得ることを示した。[T2]

このため本資料では、顧客がProviderを選ぶ際の主要な論点を8軸へ統合して扱う。

### A01-02.3.2. ① Deal-specific Fit

**問い:**

> 今回のDecision Problem / Requested Scopeに、このProviderの専門領域・Operating Modelが合っているか。

例：

- Business / Industry理解
- Predictive / Causal / Experimental等の問題への適合
- Strategy / PoC / Build / Operate等のRequested Scopeへの適合
- 顧客固有Data / Processへの適応力

Management Consultancyの選択研究では、client-industry experienceが重要なCriteriaとして確認されている。[T5]

ここから、本資料では一般的な企業能力とは別に、**今回の商談とのFit**を独立軸として扱う。

### A01-02.3.3. ② Capability / Quality

**問い:**

> このProviderは必要な仕事を高品質に遂行できるか。

例：

- Specialist Talent
- Methodology
- Analytical / Engineering Capability
- Quality Control
- Reproducibility
- Analytical Validity

ShethのIndustrial Buyer BehaviorでもQualityは主要なSupplier Expectationを構成する。[T2]

ただしProfessional Serviceでは購入前に真のQualityを直接観測しにくいため、CapabilityとEvidence / Credibilityは分離する。

### A01-02.3.4. ③ Delivery Feasibility

**問い:**

> Capabilityがあっても、この案件条件の中で本当に完遂できるか。

例：

- Staffing / Capacity
- Schedule
- Data access
- Security condition
- System integration
- Production / Operation
- Handoff

ShethではDeliveryもIndustrial BuyerのExpectation形成要因として扱われる。[T2]

したがって「できる」と「今回実行できる」は分けて評価する。

### A01-02.3.5. ④ Economic Value

**問い:**

> 費用に対して得られる価値は妥当か。

単純な見積額だけでなく、概念的には以下を含む。

- Provider fee
- 顧客側工数
- License / Platform cost
- Integration cost
- Operation cost
- Switching / Handoff cost

Patterson (1995)のManagement Consultancy選定調査ではfees / costが主要Criteriaの一つだった。[T5]

本資料では`Expected Value - Total Cost of Engagement`という考え方を用いるが、これは既存研究の定式ではなく本資料の分析表現である。

### A01-02.3.6. ⑤ Risk

**問い:**

> 選定・実施・将来利用に伴うDownsideや不確実性を許容できるか。

例：

- Project failure
- Model / Estimate uncertainty
- Security / Compliance
- Vendor dependency
- Product lock-in
- Switching cost
- Continuity

ShethはPerceived RiskをJoint Decisionへ影響する要因として扱う。[T2]

またTransaction Cost EconomicsはAsset Specificity / Uncertainty / Frequency等をGovernance Problemを考える重要属性として扱う。[T6]

ただしTCEの実証支持は一様ではなく、Risk軸を完全に説明する単一理論としては扱わない。[T7]

### A01-02.3.7. ⑥ Evidence / Credibility

**問い:**

> Providerが「できる」と言う根拠を信じられるか。

例：

- Relevant Case
- Reputation
- Client-industry Experience
- Specialist profile
- Publication / OSS / Patent
- Customer Reference

Pemer & Skjølsvik (2019)はProfessional Serviceのex ante購買で、顧客がResource / Delivery / Relational QualityをQuality Signalから判断すると整理している。[T4]

また`Qualifying Signals`と`Signals of Excellence`を区別している。[T4]

Pattersonの実証研究でもReputationとclient-industry experienceは上位Criteriaだった。[T5]

### A01-02.3.8. ⑦ Relational / Governance Fit

**問い:**

> 実際のProjectで意思決定・Communication・責任分界を成立させられるか。

例：

- Communication
- Responsiveness
- Escalation
- Decision rights
- Responsibility boundary
- Contract / Project governance

Pemer & SkjølsvikはProfessional Service QualityにRelational Qualityを含める。[T4]

Doney & Cannon (1997)はSupplier / Salesperson Trustが将来Interaction意向と関係することを示したが、過去経験・Supplier Performanceを統制後、current supplier choiceへの直接効果は確認しなかった。[T9]

したがって本資料では「Trustが高ければ勝つ」とはせず、Governance / Working Fitの一部として扱う。

### A01-02.3.9. ⑧ Organizational Acceptability

**問い:**

> Buying Center全体として、このProviderを社内で選定・承認できるか。

例：

- Procurement
- Legal
- Security
- Management approval
- Existing vendor relationship
- Contracting / Supplier registration

Webster & WindのBuying Center、ShethのJoint Decisionが主な理論的背景になる。[T1][T2]

Providerの技術評価が高くても、顧客組織内で承認できなければSupplier Selectionは成立しないため、独立軸として扱う。

### A01-02.3.10. 8軸は「本資料の統合フレーム」である

この8軸を、既存研究で確立した一つの`8-factor theory`として扱ってはならない。

整理は以下である。

**Published Evidence**

- Organizational Buyingは複数Stakeholder / 複数基準で行われる。[T1][T2]
- Professional ServiceではQuality Signal / Reputation / Experienceが重要になる。[T4][T5]
- Risk / Dependency / Governanceを考える理論としてTCE等がある。[T6][T7]

**本資料の分析統合**

上記を分析PoC Provider Selectionへ適用できるよう、

> Fit / Capability / Delivery / Economics / Risk / Evidence / Relational-Governance / Organizational Acceptability

の8軸へ整理した。

### A01-02.3.11. 後続スライドでの使い方

A01-02a以降では、この8軸を共通の比較基準として固定する。

```text
Customer Selection Criteria = 共通8軸
            ↓
Provider類型ごとに各軸のBase Strengthを整理
            ↓
Deal Profileによって各軸のWeightを変える
            ↓
今回のDealでのProvider Positionを評価
```

重要なのは、DealごとにProviderごと別々の基準を使うのではなく、**同じDealでは全Providerを同じ8軸・同じWeightで比較すること**である。

## A01-02.4. Speaker Note

競合比較をするとき、最初に「何を基準に比較しているのか」を固定します。

分析PoCでは、技術力だけでVendorを選ぶわけではありません。今回の課題へのFit、実際にDeliveryできるか、価格に見合うか、失敗や依存Riskを許容できるか、実績や担当者を信じられるか、Projectを一緒に進められるか、社内承認できるかまで含めて判断されます。

ここではそれを8軸へ整理しています。この8軸自体は既存の単一理論ではなく、Organizational BuyingやProfessional Service Selection研究を分析PoC向けに統合した本資料のフレームです。

次頁では、この8軸上で各Provider類型がどこに構造的Strengthを持ちやすいか、そして後続スライドの評価ラベルをどう読むかを定義します。
