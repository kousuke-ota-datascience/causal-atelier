# 27. Slide 27｜診断・感度分析とPoC成果物

## 27.1. Message

**因果PoCの成果はEffect Estimate単体ではなく、前提・診断・感度分析を含むEvidence Stackであり、それを基に次フェーズを判断する。**

## 27.3. Supporting Logic

### 27.3.1. Slide 27の役割

- Slide 22〜26では、Causal Question / Estimand、Causal Structure、Identification、Estimation、Strategy Selectionまでを順に設計した。
- **Slide 27では、それらをEffect Estimate単体で終わらせず、Assumption・Diagnostics・Sensitivity・Claim ScopeをEvidence Stackとして統合し、次フェーズ判断へ接続する。**
- Section 04のPredictiveがModelではなくEvidence Packageを成果としたのと対称に、CausalでもEstimatorやp-valueではなく「どこまで因果効果として主張できるかを追跡できるEvidence」を成果とする。
- このSlideがSection 05の締めであり、次のSection 06ではPredictive / Causal両方のEvidenceをどのような実装方針で作成・管理するかへ進む。

### 27.3.2. Layer 1｜Causal Question / Estimand：何を主張するEvidenceか

- Treatment、Outcome、Population、Time、Contrastを明示し、対象Effectを固定する。
- 最終報告でも分析開始時のEstimandと推定結果が一致しているかを確認する。
- Analysis途中で対象Population、Outcome Window、Contrastを変更した場合は、その変更理由と探索的 / 確証的な位置づけを記録する。
- Effectの数値だけを切り出すと適用範囲が失われるため、Estimand definitionをEvidence Stackの最上流に残す。

### 27.3.3. Layer 2｜Identification / Assumptions：なぜ因果効果と解釈できるか

- 使用したIdentification Strategyと、その成立に必要なAssumptionを明示する。
- 例：Covariate AdjustmentならConditional Exchangeability / Positivity / Consistency、DiDならParallel Trends、IVならRelevance / Independence / Exclusion等。
- Assumptionごとに、以下を区別する。
  1. Dataから直接確認可能なもの。
  2. 間接的なDiagnosticで整合性を確認できるもの。
  3. Domain Knowledgeに依存し、Dataだけでは検証できないもの。
- 「Diagnosticを通過したためAssumptionが真」とは表現しない。非検証可能なAssumptionはResidual Riskとして残す。

### 27.3.4. Layer 3｜Effect + Uncertainty：点推定だけで判断しない

- Effect Estimateには、案件に適したUncertaintyを併記する。
- Confidence Interval、Standard Error、Bootstrap Interval等は代表例だが、Design・Estimatorに応じて適切な方法を選ぶ。
- Statistical Significanceだけでなく、Effect MagnitudeとBusiness Relevanceを確認する。
- Sample Sizeが小さい、Cluster数が少ない、Overlapが弱い等の場合、標準的なAsymptotic Inferenceが不安定な可能性も考慮する。
- `p < 0.05` をPoCの成功基準にしない。大きなEffectでも不確実性が大きい場合はAdditional Validationが合理的な場合がある。

### 27.3.5. Layer 4｜Diagnostics：Designごとに確認する問題が異なる

Diagnosticsは共通チェックリストではなく、Identification Strategyへ対応させる。

| Design / Strategy | Diagnostics / Checkの例 | 主に確認すること |
|---|---|---|
| Covariate Adjustment | Balance、Overlap / Positivity、Weight Distribution、ESS | 比較可能なSupport、極端Weight、Adjustment後Balance |
| DiD | Pre-treatment Trend、Event-study、Placebo Timing | Trend仮定との整合、Anticipation等 |
| RD | Running Variable分布、Covariate Continuity、Bandwidth | Manipulation、Local Designの安定性 |
| IV | First-stage、Weak Instrument、Covariate関係 | Relevance、弱いInstrumentによる不安定性 |
| Synthetic Control | Pre-treatment Fit、Placebo、Donor Sensitivity | Counterfactual Fit、特定Donor依存 |
| RCT | Assignment Balance、Attrition、Compliance | Randomization後の実施・欠測上の問題 |

- Balanceが良いことは未観測Confoundingがないことを証明しない。
- Pre-trendが平行に見えることはPost-treatment Counterfactual Trendを証明しない。
- Strong First-stageはExclusion Restrictionを証明しない。
- Diagnosticsは、**確認可能な破綻を見つけるためのEvidence**として扱う。

### 27.3.6. Refutation / Placebo：明らかに出るべきでないEffectを確認する

- Placebo Treatment、Placebo Outcome、Placebo Timing、Fake Threshold等をDesignに応じて検討する。
- Treatment前Outcomeに大きなEffectが出る、無関係なOutcomeにも同様のEffectが出る等の場合、Identification StrategyやModel Specificationを再検討する。
- Refutation Testに通ったことも因果主張の証明ではないが、明らかなModel / Design Failureを検出するために有用である。
- どのRefutationを行うかは、具体的なData Generating Processに基づいて設計する。

### 27.3.7. Sensitivity｜結論がどの前提・仕様へ依存するかを明示する

- Adjustment Set、Functional Form、Window、Bandwidth、Trimming、Estimator等の合理的な代替仕様で結論がどう変わるかを確認する。
- 未観測Confoundingに対するSensitivity Analysisが可能な場合、どの程度の未観測Biasで結論が変わるかを評価する。
- Resultが特定仕様だけで成立する場合、そのFragilityを隠さずClaim Scope / Residual Riskへ反映する。
- 「全ての仕様で同じ結果になること」を要求するのではなく、Decisionを左右する合理的なAnalytic Choiceに対する依存性を評価する。

### 27.3.8. Layer 5｜Claim Scope：何が言えて、何が言えないかを成果物化する

最終的には、少なくとも以下を明示する。

- **What**：どのTreatment ContrastのEffectか。
- **Who**：どのPopulationへ適用できるか。
- **When**：どの期間のOutcomeか。
- **Under what assumptions**：どのAssumptionに依存するか。
- **How uncertain**：EffectとUncertaintyはどの程度か。
- **What remains unknown**：未観測Confounding、External Validity、Long-term Effect等の残存論点。
- **Decision use**：どの施策Decisionへ使えるか。

- Causal PoCの成果は「効果があった / なかった」だけでなく、このClaim Boundaryを第三者が追跡できることにある。

### 27.3.9. Decision Gate｜Next PhaseをEvidence全体から判断する

| Gate観点 | 判断する問い |
|---|---|
| Identification Credibility | AssumptionとData /業務Processの対応を説明できるか |
| Uncertainty | EffectのPrecisionはDecisionに必要な粒度を満たすか |
| Robustness | 合理的な仕様変更・Refutationに対して結論は安定か |
| Decision Relevance | Estimandが実際の施策選択・対象選定へ対応するか |
| Residual Risk | 残る仮定依存性・Data limitationを許容 / 追加検証できるか |

- Gateは単一Scoreではなく、Slide 10で合意したSuccess Criteriaと案件Riskに戻して判断する。
- Strong EffectでもIdentificationが弱ければGOとは限らない。
- Effectが不明確でも、追加Data / ExperimentでDecision可能性が高まるならAdditional Validationとなる。

### 27.3.10. GO / ADDITIONAL VALIDATION / NO-GO

**GO**
- 現在のEvidenceで次フェーズへ進む合理的根拠がある。
- 候補：限定展開、Implementation Design、Confirmatory Experiment、Prospective Validation等。
- GOはBusiness Outcome改善やROIの確定ではない。

**ADDITIONAL VALIDATION**
- Decisionを左右するResidual Uncertaintyが残るが、追加Evidenceで更新可能と判断する。
- 候補：追加Confounder取得、対象・期間拡張、より妥当なComparison、Experiment、External Validation等。
- 「とりあえずDataを増やす」のではなく、どのUncertaintyを減らすためかを明示する。

**NO-GO**
- 重要なIdentification Assumptionを合理的に支持できない。
- 比較可能なSupportが不足し、対象Effectが実質的にExtrapolationへ依存する。
- 結論が重要な仕様へ極端に依存する。
- EstimandがBusiness Decisionへ接続しない。
- この場合は中止だけでなく、Question / Data / Design / Treatmentの再設計を候補とする。

- Additional ValidationやNo-Goも、誤った因果主張や無効な投資を避けるための正当なPoC成果である。

### 27.3.11. Predictive Evidence Packageとの対称性

- Predictiveでは、Question / Data、Performance、Failure / Utility、Usage Conditions、Residual UncertaintyをEvidence PackageとしてNext Phaseへ渡した。
- Causalでは、Estimand、Identification、Effect / Uncertainty、Diagnostics / Sensitivity、Claim ScopeをEvidence Stackとして渡す。
- 両者に共通するのは、Model / Estimate単体を成果にせず、**第三者が成立条件・限界・判断理由を追跡できる形でEvidenceを返すこと**である。
- この共通思想を受けて、次SectionではData ScientistによるScratch + OSSとAriadneの役割を説明する。

## 27.4. Speaker Note

因果PoCの最後に返すものは、Effect Estimate一つではありません。何の効果を知ろうとしたか、どの前提でその効果を識別したか、推定値と不確実性はどうだったか、設計に応じた診断や感度分析でどこまで結論が安定していたかを、一つのEvidence Stackとしてまとめます。

まず、EstimandとIdentification Strategyを残します。例えばCovariate Adjustmentなら、どのConfounderを調整し、どのPopulationについてConditional Exchangeabilityを仮定したかを明示します。そのうえでEffectと信頼区間等のUncertaintyを示します。

次にDiagnosticsを行いますが、ここは解釈が重要です。Balanceが良いから未観測Confoundingがない、Pre-trendが平行だからParallel Trendsが証明された、ということではありません。Diagnosticsで確認できるのは、データから観測可能な破綻や不整合です。確認できない仮定はResidual Riskとして残します。

さらにPlaceboやSensitivityを使い、特定のWindow、Adjustment Set、Estimatorだけで結論が出ていないかを確認します。結果が不安定なら、それ自体を隠すのではなく「この条件では主張が弱い」とClaim Scopeへ反映します。

最終的には、どの前提で、誰について、どのTreatment ContrastのEffectをどこまで主張できるかを整理し、GO、Additional Validation、No-Goを判断します。強いEffectが出てもIdentificationが弱ければGOとは限りませんし、Effectがまだ不明確でも追加実験で解消できるならAdditional Validationが合理的です。

この考え方はPredictive PoCと共通しています。PredictiveではModelではなくEvidence Package、CausalではEffect EstimateではなくEvidence Stackを返します。どちらも、次の担当者が「なぜこの判断になったのか」「何がまだ分かっていないのか」を追跡できることを重視します。
