# 27. Slide 27｜診断・感度分析とPoC成果物

## 27.1. Message

**因果PoCの成果はEffect Estimate単体ではなく、前提・診断・感度分析を含むEvidence Stackであり、それを基に次フェーズを判断する。**

## 27.2. Chart

**チャートタイトル:** Evidence Stackから「どこまで主張できるか」とNext Phaseを判断する

**PowerPoint上の配置・強調**

- Evidence Stackは5層を同程度の視覚ウェイトで積み、Effect Estimateだけを中心成果に見せない。
- ④ Diagnostics / Refutation / SensitivityはDesign依存であることを小さく明示する。Balance / OverlapはCovariate Adjustment、Pre-trendはDiDなど、すべての案件へ同じ診断を当てない。
- 中央のDecision Gateでは `Identification Credibility / Uncertainty / Robustness / Decision Relevance / Residual Risk` を並べる。
- 下段はGO / ADDITIONAL VALIDATION / NO-GOを同じウェイトで並べ、追加検証やNo-GoもPoCの正当な成果であることを示す。
- 最下部に `Diagnostics ≠ Assumptionの証明` と `GO ≠ Business Outcome改善の確定` の2つの留保を置く。

## 27.3. Supporting Logic

### 27.3.1. Evidence Stackに含める内容

- **Causal Question / Estimand**：Treatment、Outcome、Population、Time、Contrast、対象とするEffectを明示する。
- **Identification / Assumptions**：どのData Generating Processを利用し、どのAssumptionのもとでEffectを識別するかを記録する。
- **Effect + Uncertainty**：点推定だけでなく、標準誤差、信頼区間等の案件に適したUncertaintyを併記する。
- **Diagnostics / Refutation / Sensitivity**：Designに応じて検証可能な問題、仕様依存性、反証可能性を確認する。
- **Claim Scope / Business Interpretation**：誰に対して、どのTreatment Contrastについて、どのAssumptionのもとで、どこまでDecisionへ使えるかを明示する。

### 27.3.2. DiagnosticsはIdentification Strategyに合わせる

代表例は以下だが、すべての案件へ一律に適用するものではない。

| Design / Strategy | Diagnostics / Checkの例 |
|---|---|
| Covariate Adjustment | Covariate Balance、Overlap / Positivity、Weight Distribution、Effective Sample Size |
| Difference-in-Differences | Pre-treatment Trend、Event-study pattern、Placebo timing等 |
| Regression Discontinuity | Running Variable分布、Threshold周辺のCovariate Continuity、Bandwidth依存性等 |
| Instrumental Variable | First-stage relevance、Weak Instrument懸念、仕様感度等 |
| Synthetic Control | Pre-treatment Fit、Placebo / Donor Sensitivity等 |

- これらのDiagnosticsは、データから確認可能な含意や実装上の問題を調べるものであり、未観測交絡がないこと、Exclusion Restrictionが成立すること等の非検証可能なAssumptionを証明するものではない。

### 27.3.3. Refutation / Sensitivityで結論依存性を確認する

- Placebo Treatment / Outcome / Timing等、Designに応じたFalsificationを検討する。
- Adjustment Set、Window、Bandwidth、Trimming、Estimator、Model Specification等を変えたときに結論が大きく変わらないかを確認する。
- 未観測交絡に対するSensitivity Analysisが可能な場合は、どの程度の未観測Biasで結論が変わるかを評価する。
- Sensitivity結果が不安定な場合、それ自体を隠さずResidual Risk / Claim Scopeへ反映する。

### 27.3.4. Decision Gate

PoC終了時は、少なくとも以下の観点から次フェーズを判断する。

| Gate観点 | 判断する問い |
|---|---|
| Identification Credibility | AssumptionとData /業務Processの対応を説明できるか |
| Uncertainty | Effectの大きさと不確実性はDecisionに必要な粒度を満たすか |
| Robustness | 合理的な仕様変更・Refutationに対して結論はどの程度安定か |
| Decision Relevance | 推定したEstimandは実際の施策選択・対象選定へ対応しているか |
| Residual Risk | 残る仮定依存性・Data limitationを次フェーズで許容または検証できるか |

### 27.3.5. Next Phaseの3択

- **GO**：現在のEvidenceで次フェーズへ進む合理的根拠がある。案件に応じて限定展開、実装設計、Confirmatory Experiment / Prospective Validation等へ進む。
- **ADDITIONAL VALIDATION**：判断を左右するResidual Uncertaintyがあり、追加Data、追加期間、より妥当なControl、Experiment、追加Confounder取得等で解消可能性がある。
- **NO-GO**：重要なIdentification Assumptionを支持できない、Overlap等が実質的に不足する、結論が重要な仕様へ極端に依存する、あるいはEstimandがDecisionへ接続しない等の場合は、中止またはQuestion / Data / Designを再設計する。
- No-GoやAdditional Validationは分析の失敗ではなく、「現在のEvidenceでは何を言えないか」を明確にするPoC成果である。
- GOはPoC時点でBusiness Outcome改善やROIが確定したことを意味しない。

## 27.4. Speaker Note

因果PoCの成果物は、効果の数値一つではありません。何の効果を知ろうとしたか、どの前提でその効果を識別したか、推定値と不確実性はどうだったか、設計に応じた診断や感度分析でどこまで結論が安定していたかを、一つのEvidence Stackとして返します。

重要なのは、Diagnosticsを行ったから仮定が証明されたと考えないことです。データから確認できる問題は診断し、確認できない仮定依存性は残存リスクとして明示します。そのうえで、次フェーズへ進むのか、追加検証するのか、現時点ではNo-Goとするのかを判断します。
