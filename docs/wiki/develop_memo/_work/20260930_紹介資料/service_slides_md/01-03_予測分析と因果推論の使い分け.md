# 3. Slide 3｜予測分析と因果推論の使い分け

## 3.1. Message

**予測と因果は、答える問いだけでなく、必要な前提と評価基準も異なる。**

## 3.2. Chart

**チャートタイトル:** 予測分析と因果推論は、推論対象・成立条件・評価が異なる

Slide 2で示した「何を知りたいかによってPredictive / Causalを選ぶ」という分岐を受け、その違いが単なる手法名の違いではなく、**何を推論するか、何を前提とするか、何をもって良い分析と判断するか**の違いであることを比較表で示す。

## 3.3. Supporting Logic

### 3.3.1. Slide 3の役割

- Slide 2では、業務課題を「何を知りたいか」という問いへ落とし込み、その問いによってPredictive / Causalを選ぶことを示した。
- Slide 3では、その選択が単なる分析手法の選好ではなく、推論対象・必要な前提・評価基準の違いに基づくことを説明する。
- 本スライドは、後続のPredictive章とCausal章で分析プロセスや評価方法が別構成になる理由を理解するための境界線を示す。

### 3.3.2. Predictiveが扱うもの

- Predictive analysisは、観測済みの情報から未知・将来のOutcomeを予測することを目的とする。
- 予測モデルでは、因果関係であること自体は必要条件ではない。未知データでも再現する安定した関連であれば、予測に利用できる場合がある。
- 主要な評価対象は、適切に分離された未知データに対するOut-of-sample predictive performanceである。
- 実務ではAccuracy等の単一指標だけでなく、Calibration、Precision / Recall、error pattern、segment別性能、業務上の誤判定コスト等も評価する。
- Target leakage、data leakage、未来情報混入があると、見かけ上の性能が高くても実運用時の予測性能を意味しない。

### 3.3.3. Causalが扱うもの

- Causal analysisは、Treatment / Interventionを変えたときにOutcomeがどの程度変化するかという介入効果を対象とする。
- 観測された群間差や相関をそのまま介入効果とは解釈できない。対象とするCausal Question / EstimandとIdentification Assumptionを明示する必要がある。
- 必要な前提は研究デザインやIdentification Strategyによって異なる。観測データでは未観測交絡がないことやOverlap等の仮定が必要になる場合があるが、すべての因果分析に同一の仮定が適用されるわけではない。
- 因果推論の妥当性はEffect Estimate単体では判断できない。Identification、推定方法、不確実性、Diagnostics / Sensitivity等を合わせて、「どの前提のもとでどこまで主張できるか」を評価する。

### 3.3.4. 同じ業務課題でもPredictive TargetとCausal Targetは異なる

**Customer Retention**

```text
Predictive
誰が解約しそうか？
= Churn Risk

Causal
Retention施策で解約はどれだけ減るか？
= Treatment Effect
```

**Manufacturing Quality**

```text
Predictive
どの製品が不良になりそうか？
= Defect Risk

Causal
工程条件を変えると不良率はどう変わるか？
= Process Intervention Effect
```

**Operations / Logistics**

```text
Predictive
どの配送が遅れそうか？
= Delay Risk

Causal
配送Processを変更すると遅延はどれだけ減るか？
= Process Change Effect
```

- Open Data再調査により、Predictive / Causalの対称例は設備保全だけでなく、Customer、Quality、Operationsにも構成できることを確認した。
- したがって本資料では「故障予測 vs 保守効果」へ過度に依存せず、複数Domainで同じ意味論差が成立することをSupporting Logicとして保持する。

### 3.3.5. 高い予測精度と正しい介入判断は別問題

- Outcomeを高精度に予測できる変数が、必ずしも介入すべき原因であるとは限らない。
- Feature importance、SHAP、PDP / ICE等のPredictive Explainabilityは、原則として予測モデルの振る舞いや関連を説明するものであり、介入によるOutcomeの変化を直接示すものではない。
- 「Churn Riskが高い顧客」と「Retention施策で最もChurnが減る顧客」は一致するとは限らない。
- 同様に「不良Riskが高い条件」が、その条件を変更したときの因果効果が大きいことを意味しない。
- したがって、「予測性能が高いから施策判断にも使える」「予測上重要な変数だから操作すればOutcomeが改善する」という推論は成立しない。

### 3.3.6. PredictiveとCausalは排他的ではない

- PredictiveとCausalは競合する分析ではなく、異なる問いへ答えるための分析である。
- 一つの業務プロセスで両者を組み合わせることもある。例えばPredictiveで将来リスクの高い対象を把握し、Causalで候補施策の効果や対象別の効果差を検討する役割分担があり得る。
- Criteo Uplift DatasetやACIC Data Challengeのように、CATE / Treatment Effect Estimation自体を評価するPublic Benchmarkも存在する。
- ただし両者を組み合わせる場合でも、PredictionとCausal Effectの意味論・前提・評価を混同しないことが必要である。

## 3.4. Speaker Note

Slide 2では、「何が起こりそうか」を知りたいならPredictive、「何をするとどう変わるか」を知りたいならCausalと整理しました。このスライドでは、なぜ問いによって分析を分ける必要があるのかを説明します。

違いはアルゴリズム名ではありません。そもそも推論したい対象が異なります。Predictiveでは、将来や未知のOutcomeをどこまで予測できるかを扱います。そのため、重要なのは学習した関係が未知データでも再現し、予測性能が保たれるかです。

一方Causalでは、施策や介入を変えたときにOutcomeがどう変わるかを扱います。ここでは、観測された差をそのまま効果とは呼べません。その比較を介入効果として解釈するための因果構造やIdentification Assumptionを整理し、どの前提のもとでどこまで効果を主張できるかを評価する必要があります。

例えば、解約しそうな顧客を高精度に当てられても、その顧客がRetention施策によって最も解約を減らせる顧客とは限りません。同じことは品質や物流でも成立します。不良Riskを当てることと工程変更の効果を推定すること、配送遅延を当てることとProcess変更の効果を推定することは別問題です。

つまりPredictiveとCausalでは、「何を知りたいか」だけでなく、「何を前提とし、何をもって分析が妥当と判断するか」まで異なります。

## 3.5. Slide 3からSlide 4への接続

> **Predictive / Causalでは、得られる情報とその妥当性の確かめ方が異なる。では、それぞれの情報を業務判断へ使うことで、どのような価値が期待できるのか。**
