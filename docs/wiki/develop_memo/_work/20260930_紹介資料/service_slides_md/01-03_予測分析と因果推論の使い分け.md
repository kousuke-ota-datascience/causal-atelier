# 3. Slide 3｜予測分析と因果推論の使い分け

## 3.1. Message

**予測と因果は、答える問いだけでなく、必要な前提と評価基準も異なる。**

## 3.2. Chart

**チャートタイトル:** 予測分析と因果推論は、推論対象・成立条件・評価が異なる

Slide 2で示した「何を知りたいかによってPredictive / Causalを選ぶ」という分岐を受け、その違いが単なる手法名の違いではなく、**何を推論するか、何を前提とするか、何をもって良い分析と判断するか**の違いであることを比較表で示す。

### 3.2.1. Chart Structure

PowerPoint上では、Predictive / Causalを左右に並べた単一の比較表とする。

比較する観点は以下の4点に絞る。

1. 問い
2. 推論対象
3. 成立条件
4. 評価

│              ↓               │              ↓               │

**PowerPoint上の配置・強調**

- Predictive / Causalの2列は同じ視覚ウェイトとし、優劣ではなく目的の違いとして見せる。
- 最上段の問いはSlide 2と同じ「何が起こりそうか？」「何をするとどう変わるか？」を用い、前スライドとの連続性を保つ。
- 2段目では、Predictiveは「将来・未知のOutcome」、Causalは「介入によるOutcomeの変化」とし、推論対象の違いを明示する。

- 4段目では、「良い分析」の評価基準が異なることを示す。Predictiveは未知データに対する予測性能、CausalはIdentification Assumptionを含む前提・推定・診断の妥当性を評価する。

## 3.3. Supporting Logic

### 3.3.1. Slide 3の役割

- Slide 2では、業務課題を「何を知りたいか」という問いへ落とし込み、その問いによってPredictive / Causalを選ぶことを示した。
- Slide 3では、その選択が単なる分析手法の選好ではなく、推論対象・必要な前提・評価基準の違いに基づくことを説明する。
- 本スライドは、後続のPredictive章とCausal章で分析プロセスや評価方法が別構成になる理由を理解するための境界線を示す。
- 具体的な業務効果はSlide 4、Predictive / Causalそれぞれの詳細な設計・手法・評価は後続章で扱う。

### 3.3.2. Predictiveが扱うもの

- Predictive analysisは、観測済みの情報から未知・将来のOutcomeを予測することを目的とする。
- 予測モデルでは、因果関係であること自体は必要条件ではない。未知データでも再現する安定した関連であれば、予測に利用できる場合がある。
- したがって主要な評価対象は、学習データへの当てはまりではなく、適切に分離された未知データに対するOut-of-sample predictive performanceである。
- 実務ではAccuracy等の単一指標だけでなく、問題に応じてCalibration、Precision / Recall、error pattern、segment別性能、業務上の誤判定コスト等も評価する。
- Target leakage、data leakage、時系列で利用できない未来情報の混入があると、見かけ上の性能が高くても実運用時の予測性能を意味しない。

### 3.3.3. Causalが扱うもの

- Causal analysisは、Treatment / Interventionを変えたときにOutcomeがどの程度変化するかという介入効果を対象とする。
- 観測された群間差や相関をそのまま介入効果とは解釈できない。Treatment assignmentやデータ生成過程を踏まえ、対象とするCausal Question / EstimandとIdentification Assumptionを明示する必要がある。
- 必要な前提は研究デザインやIdentification Strategyによって異なる。観測データでは、未観測交絡がないこと、十分なOverlapがあること等の仮定が必要になる場合があるが、すべての因果分析に同一の仮定が適用されるわけではない。
- 因果推論の妥当性はEffect Estimate単体では判断できない。Identificationの妥当性、推定方法、不確実性、利用可能なDiagnostics / Sensitivity等を合わせて、「どの前提のもとでどこまで主張できるか」を評価する。
- 因果推論に必要な仮定の一部はデータだけから完全には検証できないため、ドメイン知識、時間順序、実験・制度設計、データ生成過程の理解が必要になる。

### 3.3.4. 高い予測精度と正しい介入判断は別問題

- Outcomeを高精度に予測できる変数が、必ずしも介入すべき原因であるとは限らない。
- 例えば、Outcomeの強い予測因子が単なるproxy、結果に近い下流変数、あるいは介入不可能な属性である場合、その変数を使って予測することは有効でも、その変数への介入効果を意味しない。
- Feature importance、SHAP、PDP / ICE等のPredictive Explainabilityは、原則として予測モデルの振る舞いや関連を説明するものであり、介入によるOutcomeの変化を直接示すものではない。
- 逆に、因果効果の推定ではOutcomeそのものを高精度に予測することが主目的ではない。対象とする介入効果をIdentificationでき、必要な前提のもとで妥当に推定できることが重要である。
- したがって、「予測性能が高いから施策判断にも使える」「予測上重要な変数だから操作すればOutcomeが改善する」という推論は成立しない。

### 3.3.5. PredictiveとCausalは排他的ではない

- PredictiveとCausalは競合する分析ではなく、異なる問いへ答えるための分析である。
- 一つの業務プロセスで両者を組み合わせることもある。例えばPredictiveで将来リスクの高い対象を把握し、Causalで候補施策の効果や対象別の効果差を検討する、といった役割分担があり得る。
- ただし、両者を組み合わせる場合でも、PredictionとCausal Effectの意味論・前提・評価を混同しないことが必要である。

## 3.4. Speaker Note

Slide 2では、「何が起こりそうか」を知りたいならPredictive、「何をするとどう変わるか」を知りたいならCausalと整理しました。このスライドでは、なぜ問いによって分析を分ける必要があるのかを説明します。

違いはアルゴリズム名ではありません。そもそも推論したい対象が異なります。Predictiveでは、将来や未知のOutcomeをどこまで予測できるかを扱います。そのため、重要なのは学習した関係が未知データでも再現し、予測性能が保たれるかです。

一方Causalでは、施策や介入を変えたときにOutcomeがどう変わるかを扱います。ここでは、観測された差をそのまま効果とは呼べません。その比較を介入効果として解釈するための因果構造やIdentification Assumptionを整理し、どの前提のもとでどこまで効果を主張できるかを評価する必要があります。

したがって、高い予測精度が得られても、それだけで「この変数へ介入すればOutcomeが改善する」とは言えません。Feature importanceやSHAP等で予測上重要な特徴が分かっても、それを因果効果として読むことはできません。

逆に、因果分析ではOutcomeを最も高精度に当てるモデルを作ること自体が目的ではありません。知りたい介入効果を妥当に識別・推定できることが中心です。

つまりPredictiveとCausalでは、「何を知りたいか」だけでなく、「何を前提とし、何をもって分析が妥当と判断するか」まで異なります。この違いが、後続のPredictive章とCausal章で分析プロセスや評価方法を分けて説明する理由です。

## 3.5. Slide 3からSlide 4への接続

> **Predictive / Causalでは、得られる情報とその妥当性の確かめ方が異なる。では、それぞれの情報を業務判断へ使うことで、どのような価値が期待できるのか。**
