## A01-04a.3. Supporting Logic

### A01-04a.3.1. このProfileの特徴

分析方法そのものの設計、仮説検証、モデル評価等が案件価値の中心であり、System / Security / Operationとの結合が弱い。

### A01-04a.3.2. ProviderごとのFit仮説

- **DS Specialist**：専門人材、方法論、柔軟なスクラッチ分析が直接価値になりやすい。
- **Consulting Analytics**：高度分析人材を持つ場合は十分競争可能。ただしStrategy / Transformationが主要価値でない案件では追加価値が限定される可能性がある。
- **当チーム**：Predictive / Causal、Scratch / OSS、前提・評価設計はFitする。一方、このProfileではEnterprise Baseが選定理由として効きにくい。
- **SIer Analytics**：高度分析Capabilityが十分なら競争可能だが、Integration / Productionの強みは評価されにくい。
- **AI / Platform Vendor**：Product Capabilityへ高くFitする場合を除き、非定型分析では適合度が下がり得る。

### A01-04a.3.3. 当チームのPosition

> **Competitive。ただし構造的な相対優位は未確認。**

当チームの分析Capabilityは活きるが、Enterprise BaseというCapability Bundleの片側が効きにくいため、DS Specialist等に対する明確なCompetitive Gapは現時点では主張しない。

## A01-04a.4. Speaker Note

高度な分析が必要でも、その結果が分析レポートや意思決定支援で完結し、システム接続や運用条件がほとんど重要でない案件では、分析専門会社が非常に自然な選択肢になります。当チームも十分対応できますが、このProfileではSIerとしてのEnterprise Baseが差になりにくいため、当チーム固有の相対優位を前提にはしません。
