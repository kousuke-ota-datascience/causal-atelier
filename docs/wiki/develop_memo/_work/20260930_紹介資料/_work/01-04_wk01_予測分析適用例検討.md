# 01-04 wk01｜予測分析適用例検討

## 1. 調査目的

本書は、サービス紹介資料 `01-01` 〜 `01-04` および後続のPredictive章で用いる**予測分析（Predictive Analytics）の適用例候補を整理するための調査メモ**である。

当チームでは需要予測をサービス対象として扱わないため、本調査では**需要予測を除外**し、その他にどのような業務課題・予測対象へPredictive Analyticsを適用できるかを幅広く整理する。

単なるユースケース名の列挙ではなく、各適用例について以下を整理する。

1. **何を予測・推定するのか（Prediction Target）**
2. **どのような分析問題として定式化できるか**
3. **予測結果によってどのDecision / Actionを変えられるか**
4. **どのようなBusiness Outcomeへ接続し得るか**
5. **サービス紹介資料の例として使いやすいか**
6. **根拠となる出所**

なお、本書でいうPredictive Analyticsは原則として、**観測済み情報から将来または未知のOutcomeを予測する分析**を指す。

状態推定、異常検知等はPredictive Analyticsと密接に関連するが、必ずしも「将来Outcomeの予測」ではないため、隣接領域として区別して整理する。

---

## 2. 調査上の前提

### 2.1. Predictive Analyticsは「時系列予測」だけではない

予測分析は、時間系列の将来値を予測するForecastingだけに限定されない。

代表的には以下の問題設定を含む。

| 問題設定 | 予測対象の例 | 代表的な出力 |
|---|---|---|
| Classification | 故障するか、解約するか、不良か | class / probability |
| Regression | 品質指標、消費電力量、処理時間 | continuous value |
| Survival / Time-to-event | 故障までの時間、残存寿命 | survival probability / time-to-event |
| Time-series Forecasting | 将来の電力量、温度、設備状態 | future trajectory |
| Ranking / Risk Scoring | 対応優先度、点検優先度 | score / rank |
| Image / Signal Classification | 外観不良、異常状態 | class / probability |

この整理は、「予測分析 = 需要予測」という狭い印象を避けるうえで重要である。

- 次回故障時点

**資料への適性:** **非常に高い**

## 4. 隣接領域

### 4.1. State Estimation

**対象**

直接観測できない現在の内部状態を、センサ等から推定する。

例：

- Battery State of Charge（SOC）
- State of Health（SOH）
- 設備内部状態
- 現在の劣化状態

これは「未来のOutcome予測」ではなく、**現在だが直接観測できないLatent Stateの推定**である。

したがって厳密にはPredictionと分けて扱う方がよいが、状態推定結果を初期条件として将来状態・RUL予測へ接続するケースが多く、Predictive Analyticsの周辺技術として重要である。

**出所**

- NASA, *An Integrated Approach to Battery Health Monitoring using Bayesian Regression, Classification and State Estimation*  
  https://data.nasa.gov/dataset/an-integrated-approach-to-battery-health-monitoring-using-bayesian-regression-classificati
- NASA Software Catalog, *Prognostics Algorithm Library*  
  https://software.nasa.gov/software/ARC-17735-1

### 4.2. Anomaly Detection

**対象**

- 通常状態から外れた挙動
- 未知の異常兆候

Label付きFailure Predictionとは異なり、異常検知では必ずしも具体的な将来Outcomeを予測しない。

ただし、設備故障等では**Pre-failure Behaviorの検知 → 重点監視 → 故障予測**という形でPredictive Maintenanceと組み合わせられる。

**出所**

- IBM Maximo, *Predictive model templates*  
  https://www.ibm.com/docs/en/ma-pmis?topic=data-predictive-model-templates

---

### 4.3. Diagnostic Classification

現在の観測データから、現在だが未知の状態・カテゴリを推定する問題もある。

例：

- 現在のDefect種類
- 故障Mode
- 文書Category
- 画像Category

これはFuture Forecastingではないが、未知Outcome Predictionという広義のPredictive Modelingには含められる。

サービス資料で「予測分析」を将来予測として説明する場合には、混乱を避けるため主例にはしない方がよい。

## 5. サービス紹介資料で特に使いやすい候補

資料上の説明力、Business Actionへの接続、需要予測との差別化、Predictive / Causalの区別のしやすさを考えると、優先候補は以下と考える。

| 優先度 | 適用例 | Prediction | Decision / Action | Business Outcome |
|---|---|---|---|---|
| A | **設備停止・故障リスク予測** | どの設備が停止しそうか | 点検・保守対象を優先化 | 停止損失・保守費削減 |
| A | **劣化 / RUL予測** | いつ寿命に達しそうか | 交換・保守時期を決める | 稼働率向上・過剰交換削減 |
| A | **解約予測** | 誰が解約しそうか | 対応対象を優先化 | 対応効率・Retention改善機会 |
| A | **不良 / 品質予測** | どの製品が不良になりそうか | 検査対象を重点化 | 品質改善・検査費削減 |
| A | **消費電力量予測** | 将来どの程度使用しそうか | 運転計画を調整 | Energy Cost削減 |
| B | Lead Time / 遅延予測 | どのJobが遅れそうか | Follow-up・配置を変更 | 納期遵守・生産性改善 |
| B | Fraud Risk | どの取引が不正らしいか | Review対象を優先化 | 不正損失・審査費削減 |
| B | Propensity | 誰が反応しそうか | 接触対象を優先化 | 営業効率改善 |
| B | Safety Risk | どこでIncidentが起きそうか | 監視・点検を重点化 | Risk低減 |

## 6. 01-01〜01-04へ使うならどの例がよいか

### 6.1. 第一候補｜設備停止・故障リスク予測

```text
設備停止リスクを予測
        ↓
高リスク設備を特定
        ↓
点検・保守対象を優先化
        ↓
突発停止 / 過剰保全を削減
        ↓
停止損失・保守コスト削減
```

**利点**

- 「何が起こりそうか」が明確
- Prediction → Decision / Actionが明確
- Business Outcomeが具体的
- Causal Effectとの意味論的な区別がしやすい
- Classification / Survival / RUL等、後続の技術説明へ拡張できる

現状の01-01 / 01-04で採用している方向性は妥当。

---

### 6.2. 第二候補｜解約予測

```text
解約リスクを予測
        ↓
高リスク顧客を特定
        ↓
対応対象を優先化
        ↓
限られた対応リソースを重点配分
```

さらにCausalとの対比が非常に作りやすい。

```text
Predictive
誰が解約しそうか？

Causal
どの施策が解約を減らすか？
```

01-02の「同じ業務課題でも問いによって分析が変わる」の例として特に強い。

---

### 6.3. 第三候補｜品質 / 不良予測

```text
品質・不良リスクを予測
        ↓
高リスク製品 / ロットを特定
        ↓
重点検査・追加確認
        ↓
検査効率 / 品質を改善
```

Prediction Targetが明確であり、製造・研究開発領域の顧客には理解されやすい。

---

### 6.4. 第四候補｜消費電力量予測

```text
将来の消費電力量を予測
        ↓
運転計画を調整
        ↓
Peak / 非効率運転を抑制
        ↓
Energy Cost / 使用量を削減
```

Forecastingの代表例として使える。

ただし「需要予測」と同じ時系列Forecastingに見えやすいため、当チームのScopeを誤解させたくない場合は主例より補助例がよい。

---

## 7. PredictiveとCausalを混同しやすい適用例

### 7.1. Churn Prediction

```text
誰が解約しそうか
= Predictive
```

対して、

```text
誰にRetention施策を行えば解約率がどれだけ下がるか
= Causal
```

高Churn RiskだからといってRetention施策の効果も大きいとは限らない。

---

### 7.2. Conversion Propensity

```text
誰が購入しそうか
= Predictive
```

```text
誰に広告を出すことで購入が増えるか
= Causal / Uplift
```

既存施策下での購買確率とIncremental Effectは別である。

---

### 7.3. Failure Prediction

```text
どの設備が故障しそうか
= Predictive
```

```text
どの保守施策を行うと故障率がどの程度下がるか
= Causal
```

故障の予測因子が分かっても、その因子へ介入した効果が分かるわけではない。

---

### 7.4. Quality Prediction

```text
どの製品が不良になりそうか
= Predictive
```

```text
工程条件Xを変更すると不良率がどの程度変わるか
= Causal
```

Feature ImportanceやSHAPで品質と関連する変数が得られても、それを操作した場合の品質改善効果とは限らない。

---

## 8. 調査結果からの示唆

### 8.1. 「予測分析 = 需要予測」と見せる必要はない

外部資料を確認してもPredictive Analyticsの実務適用範囲は広く、少なくとも以下を十分に代表例として利用できる。

- 設備故障予測
- RUL / 劣化予測
- 品質・不良予測
- Energy Consumption Forecasting
- 解約予測
- Fraud / Risk Prediction
- Lead Time / Delay Prediction

したがって、サービス紹介資料では需要予測を外してもPredictive Analyticsの説明力は損なわれない。

### 8.2. 「設備故障」と「解約」は特に説明力が高い

- 設備故障：製造・設備・産業系Businessへ直結
- 解約：顧客・サービス系Businessへ直結

この2つを併用すると、Predictiveが特定業界だけの分析ではないことも表現できる。

### 8.3. 例示はPredictionだけで終わらせない

サービス資料では、

```text
Prediction Target
    ↓
Decision / Action
    ↓
Business Outcome
```

まで示した方がよい。

例えば「劣化予測」「品質予測」という分析名だけでは顧客価値が見えにくい。

```text
劣化予測
→ 交換時期を判断
→ 過剰交換 / 突発停止を削減
```

とすることで、分析サービスとしてのValueが明確になる。

### 8.4. PredictiveとCausalの境界を説明できる例を優先する

01-01〜01-04はPredictive / Causalの違いを説明する章でもあるため、単に分かりやすい例だけでなく、両者の問いの違いを示せる例が望ましい。

特に以下は強い。

```text
解約予測
誰が解約しそうか？
vs.
解約抑止施策の因果効果
どの施策を行うと解約が減るか？
```

```text
設備故障予測
どの設備が故障しそうか？
vs.
保守施策の因果効果
どの保守を行うと故障が減るか？
```

```text
品質予測
どの製品が不良になりそうか？
vs.
工程介入の因果効果
工程条件を変えると不良率がどう変わるか？
```

---

## 9. 結論

需要予測を除外しても、Predictive Analyticsには十分に広い適用対象が存在する。

紹介資料の主要例としては、以下を推奨する。

1. **設備停止・故障リスク予測**
2. **劣化 / Remaining Useful Life予測**
3. **解約予測**
4. **品質指標 / 不良予測**
5. **消費電力量予測**

特に01-01〜01-04では、主例として**設備故障・停止リスク予測**を使用し、補助例として**解約予測・品質予測・消費電力量予測**を散らす構成が、適用範囲の広さと説明の一貫性を両立しやすい。

## 11. 調査上の留保

- 本書はPredictive Analyticsの適用可能性を整理したものであり、当チームがすべての業界・ユースケースを現時点で提供可能であることを意味しない。
- 各案件で実現可能性を判断するには、Prediction Targetの定義、利用可能データ、ラベル品質、Prediction Horizon、利用時点で取得可能な特徴量、Actionability、評価指標等の確認が必要である。
- Predictive Performanceが高くてもBusiness Outcomeが自動的に改善するわけではない。予測結果を利用してDecision / Actionを変更できることが必要である。
- Feature ImportanceやPredictive ExplainabilityはCausal Effectを意味しない。
- State Estimation、Anomaly Detection、Diagnostic ClassificationはPredictive Analyticsと隣接するが、厳密な「将来Outcome予測」とは区別する。
