# 01-04 wk02｜予測分析適用例再調査と代表例選定

## 1. 調査目的

本書は、`01-04_wk01_予測分析適用例検討.md` の調査範囲が狭かったことを踏まえ、**予測分析（Predictive Analytics）が実務上どのような対象へ適用されているかを、公開コンペ・Open Data・企業公開事例から広く再調査し、サービス紹介資料で使う代表例を選ぶための判断基準と仮説を構築する**ことを目的とする。

特に以下を検証する。

1. Predictive Analyticsの適用対象は、設備故障・解約・品質・電力等よりさらに広いのではないか。
2. 公開Datasetから、どのようなBusiness Prediction Problemを構成できるか。
3. サービス紹介資料の代表例として、設備故障予測を第一候補とすることは本当に妥当か。
4. 一つの代表例ではなく、複数カテゴリを使い分ける方が適切ではないか。

当チームでは需要予測をサービス対象として扱わないため、**需要予測は代表例候補から除外**する。ただし、Predictive Analytics全体の広さを確認するため、外部Dataset / Competitionとして存在すること自体は調査対象に含める。

---

## 2. 調査アプローチ

### 2.1. 公開コンペ

Kaggle等のPrediction Competitionを確認する。

**目的**

- 実際に定式化されているPrediction Targetの幅を把握する。
- Classification / Regression / Forecasting / Time-to-event / Ranking / Sequence Prediction等の問題設定を確認する。

### 2.2. Open Data / Public Dataset

UCI、NASA、政府Open Data、研究Dataset、業務Dataset等を確認する。

**目的**

- 特定VendorのMarketing Caseではなく、公開Dataから成立するPrediction Problemの幅を把握する。
- 顧客行動、物流、信用、設備、品質、ERP、交通、営業、Text等までDomainを広げる。
- 単一Prediction Target Datasetだけでなく、複数の分析課題を切り出せる「業務データ基盤型Dataset」も評価する。

### 2.3. 企業公開事例

Google Cloud、AWS、Microsoft、Siemens等のCustomer Story / Case Studyを確認する。

**目的**

- Predictionが実務のどのDecision / Actionへ利用されているかを確認する。
- Prediction Accuracyではなく、Business Outcomeへの接続を確認する。

# 6. サービス紹介資料の代表例を選ぶ判断項目

代表例は「Datasetが多い」「よく見る」だけでは決めない。

## 6.1. Question Clarity

何を予測するのか一読で分かるか。

## 6.2. Actionability

Predictionから具体的なDecision / Actionへつながるか。

## 6.3. Business Outcome Clarity

Actionの結果としてCost / Revenue / Risk / Productivity等を想像できるか。

## 6.4. Predictive / Causal Contrast

同じBusiness Issueに対してPredictive QuestionとCausal Questionを分けて説明できるか。

## 6.5. Domain Neutrality

特定業界専用サービスに見えすぎないか。

## 6.6. Scope Misunderstanding Risk

例を出すことで当チームの提供Scopeを誤認させないか。

## 6.7. Predictive Analytics Representative Coverage

Classification / Regression / Time-series等の一部だけに見えないか。

## 6.8. Data Intuitiveness

顧客が入力Dataを想像しやすいか。

## 6.9. Ethical / Regulatory Burden

Credit / Medical等、例示時に別論点を過度に呼び込まないか。

## 6.10. Business Process Proximity

今回のOpen Data再調査を踏まえて追加する。

> 顧客企業の日常業務Dataから自然に構成できるPrediction Problemか。

completejourney、Olist、BPI Challenge、Bank Marketing等を見ると、実務上は「専用Dataset」が存在するというより、Transaction / Event / Master / Sensor / Interaction DataからTargetを定義する。

したがって、**実案件へ想像を移しやすいこと**も代表例選定では重要である。

## 7.1. 結果

Open Data再調査後は、**故障予測を第一候補とする根拠はさらに弱くなった。**

- 解約予測

# 8. 結論の修正

## 8.1. 修正前

> 故障予測が代表例として最も強い。

これは狭すぎた。

## 8.2. 修正後

> **単一の代表例を選ぶべきではない。**

Open Data / Competition / Enterprise Caseを横断すると、Predictive Analyticsは少なくとも以下の3系統を見せる方が適用範囲を誤解なく示せる。

### Customer / Commercial

- 解約予測
- 購買 / Response Propensity
- Customer Value

### Industrial / Quality

- 故障予測
- RUL / 劣化予測
- 不良 / 品質予測

### Operations / Process

- 配送遅延予測
- Lead Time / Completion Time予測
- Energy Consumption / Operational Forecast

この3系統で、

- Customer / Transaction Data
- Sensor / Manufacturing Data
- Event Log / Operational Data

というDataの幅も表現できる。

# 9. Slide別の推奨仮説

## 9.1. 01-01｜サービス全体像

単一例ではなく、短いBreadth Examplesを置く。


これは製造設備に限定されず、Business Processに近い例として使いやすい。

# 10. 最終仮説

### 仮説1

Predictive Analyticsの適用範囲は、設備・需要・顧客だけではなく、**Business Process、物流、信用、交通、Text / Interaction**まで広い。

### 仮説2

Open Dataを見る際は、単一Prediction Taskだけでなく、**completejourneyやBPI Challengeのような複数Prediction Problemを切り出せる業務Dataset**が重要である。

### 仮説3

故障予測は最良の単一代表例ではない。

**故障 = Industrialの強い例**であり、Customerには解約、Operationsには配送遅延 / Lead Time等、カテゴリごとのAnchorを持つ方がよい。

### 仮説4

Intro Deckの主目的は技術Catalogではなく、

```text
Business Question
→ Prediction
→ Decision / Action
→ Business Outcome
```

を理解させること。

したがって代表例の選定では、Dataset数や技術的知名度より、**Question Clarity / Actionability / Business Outcome / Domain Biasの低さ**を優先する。

### 仮説5

現時点でのExample Portfolioは以下が有力。

```text
Customer
解約予測

Industrial
故障 / 品質予測

Operations
配送遅延 / Lead Time予測
```

必要に応じて、Forecastingの幅を示す補助例として消費電力量予測を追加する。

# 12. 調査上の留保

- 添付されたOpen Data候補一覧を、今回のOpen Data節の拡張に利用した。
- Datasetが存在することは、そのUse Caseの市場規模・案件頻度・当チームのDelivery Capabilityを直接証明しない。
- Kaggle / Vendor Datasetには二次配布・加工版が存在するため、実利用時は原典・License確認が必要。
- Synthetic Dataset、Simulation Dataset、Research-only / Non-commercial Datasetは、商用PoC利用可否とExampleとしての説明価値を分けて扱う。
- Predictive Performanceが高くてもBusiness Outcomeは自動的に改善しない。Decision Rule / Actionabilityが必要。
- Propensity / Risk PredictionはIntervention Effectを意味しない。
- State Estimation / Anomaly Detection / Classificationは、狭義のFuture Predictionと区別して扱う必要がある。
