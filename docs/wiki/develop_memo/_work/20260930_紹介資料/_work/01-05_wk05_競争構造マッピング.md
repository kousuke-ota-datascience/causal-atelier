# 01-05 wk05｜8軸による競争構造マッピング

## 1. 目的

`01-05_wk04_顧客が企業サービスを選ぶ基準.md` で整理した8つのCustomer Selection Criteriaを用いて、以下の競合類型と当チームの競争構造を整理する。

- コンサルAnalytics
- SIer Analytics
- AI Vendor
- Data Science専門会社
- 当チーム

本書の目的は、「誰が最も優れているか」を一般論で決めることではない。

目的は、各類型について、

1. どの選考軸が構造的に強いか
2. どの軸はTable Stakesになりやすいか
3. どの軸で相対的なDifferentiationが生まれ得るか
4. 当チームについて何が事実として言え、何がEvidence Gapとして残るか

を整理し、`01-05 Why Us` に載せるべき候補を逆算することである。

なお、本書の競合評価は**類型レベルの仮説**であり、個別企業・個別チームには多数の例外がある。特に、大手コンサル・SIer・専門会社の各社には複数部門があり、Analytics / Consulting / Engineering / Productの境界は重なる。

したがって「コンサルはできない」「SIerは弱い」といった断定は行わず、**各類型の事業構造上、どこに比較優位が生じやすいか**として読む。

---

## 2. 比較に用いる8軸

| # | 選考軸 | 顧客の問い |
|---:|---|---|
| 1 | Problem / Solution Fit | 自社の課題に合っているか |
| 2 | Capability / Quality | 高品質に遂行できるか |
| 3 | Delivery Feasibility | 現実に完遂・実装できるか |
| 4 | Economic Value | 費用に見合う価値があるか |
| 5 | Risk | 選定・導入・依存リスクを許容できるか |
| 6 | Evidence / Credibility | 「できる」という主張を信じられるか |
| 7 | Relational / Governance Fit | 一緒に仕事を進められるか |
| 8 | Organizational Acceptability | 社内で選定・承認しやすいか |

この8軸自体は既存の単一理論ではなく、Webster & Wind、Sheth、professional service selection / quality signal研究等を統合した本資料用フレームである。詳細は`wk04`参照。

---

## 3. 評価ラベル

競争構造を以下のラベルで整理する。

| Label | 意味 |
|---|---|
| **Structural Strength** | 類型の事業構造・Asset・組織能力から比較優位が生じやすい |
| **Competitive** | 十分競争可能だが、その類型だけの差別化にはなりにくい |
| **Table Stakes** | 持っていることが前提で、単独では差別化になりにくい |
| **Potential Weakness** | 他類型と比べて相対的不利が出る可能性がある |
| **Evidence Gap** | 当チームについて優位を仮説化できるが、裏付け事実が不足 |
| **Unknown** | 現時点の資料では評価不能 |

# 4. 競合類型ごとのRight to Win

## 4.1. コンサルAnalytics

### 4.1.1. 顧客が選ぶ主な理由

典型的には、

> **Business Transformationや経営課題を起点に、分析をStrategy / Process / Organizationまで接続できること。**

がRight to Winになりやすい。

Deloitteは公式に、AI / Dataを用いて企業が変革機会を見出し、意思決定を改善し、AI戦略からCustom AI Solution構築まで支援すると説明している。

AccentureもAI / Dataを業務効率化・顧客体験・企業変革へ接続するService Portfolioを持つ。

したがって、「Business-first」「意思決定につなげる」「Transformationまで見る」は、この類型では明確な競争能力である。

### 4.1.2. 8軸評価

| 軸 | 仮説評価 | 理由 |
|---|---|---|
| Problem / Solution Fit | **Structural Strength** | Industry / Strategy / Business Consultingとの接続により上流課題を定義しやすい |
| Capability / Quality | **Competitive〜Structural Strength** | Analytics専門人材を持つ大手も多く、方法論も広い |
| Delivery Feasibility | **Competitive** | Technology Deliveryまで持つFirmは強いが、実装主体が別組織になる場合もある |
| Economic Value | **Potential Weakness** | 高単価になりやすい。ただし大規模Transformationでは相対的に合理化され得る |
| Risk | **Structural Strength** | ブランド、Governance、グローバル標準、Security対応等で安心感がある |
| Evidence / Credibility | **Structural Strength** | Reputation、Case、Industry Experience、ブランド力が強い |
| Relational / Governance Fit | **Structural Strength** | Stakeholder alignment、経営層対応、PMO等が本業 |
| Organizational Acceptability | **Structural Strength** | 大手ブランド、調達実績、契約基盤により承認されやすい |

### 4.1.3. Why Us検討への意味

当チームが以下を主差別化にすると、この類型と正面衝突する。

- 業務課題から考える
- 経営判断へつなげる
- 関係者を巻き込む
- Strategyから実装まで考える

したがって、これらはWhy Usの核ではなくTable Stakes / Supporting Capabilityとして扱う方がよい。

---

## 4.2. SIer Analytics

### 4.2.1. 顧客が選ぶ主な理由

典型的には、

> **分析PoCを既存システム・データ基盤・Security / Governanceと接続し、Productionへ移行できること。**

がRight to Winになりやすい。

NTT DATAは公式AI Consultingで、prototypeのmodel / agent / algorithm / tool選定から、pilot、full-scale deployment、existing systems / processesへのintegration、governanceまでEnd-to-End supportを掲げている。

同社のAI Platformでもarchitecture design、vendor selection、deployment、integration、model training、managed services、governanceを一貫して提供している。

したがってSIer Analyticsにとって、

- Enterprise Integration
- Security
- Productionization
- Managed Services

は構造的な強みである。

### 4.2.2. 8軸評価

| 軸 | 仮説評価 | 理由 |
|---|---|---|
| Problem / Solution Fit | **Competitive** | 長期顧客では業務・IT環境理解が深い。Consulting機能を持つ場合は上流も強い |
| Capability / Quality | **Competitive** | 高度分析チームを保有するSIerも多く、一概に弱いとは言えない |
| Delivery Feasibility | **Structural Strength** | System Integration / Production / Operationが本業 |
| Economic Value | **Competitive** | PoC単体では高コストの場合もあるが、後続実装込みではTransaction Costを下げられる場合がある |
| Risk | **Structural Strength** | Security、Governance、Support、継続性、既存環境理解 |
| Evidence / Credibility | **Structural Strength** | 大規模導入実績、既存取引、企業ブランド |
| Relational / Governance Fit | **Structural Strength** | 長期顧客関係、Enterprise PM、契約対応 |
| Organizational Acceptability | **Structural Strength** | 既存Vendor、調達・Security承認、企業体力 |

### 4.2.3. Why Us検討への意味

当チーム自身もSIerのデータ分析部門であるため、以下は**自社類型の共通強みであり、他SIer Analyticsとの差別化にはならない可能性が高い**。

- Enterprise Systemを理解できる
- Security / Governanceを考慮できる
- PoC後に本番実装へ接続できる
- System Integrationまで考えられる

従って、Why Usでは「SIerだからできる」だけでなく、**同じSIer Analytics群の中で何が違うのか**まで必要になる。

---

## 4.3. AI Vendor / AI Platform Vendor

### 4.3.1. 顧客が選ぶ主な理由

典型的には、

> **Productized / ReusableなAI Capabilityを使い、短期間で業務へDeployし、継続利用・Scaleできること。**

がRight to Winとなる。

PalantirはOperational Applicationを「意思決定を起点に情報・Simulation・Actionを同じWorkflowへ統合するもの」と位置づけている。単なるDashboardではなく、DecisionそのものをApplicationへ組み込む。

この例からも、「意思決定につなげる」はAI Platform Vendorにも十分可能である。

### 4.3.2. 8軸評価

| 軸 | 仮説評価 | 理由 |
|---|---|---|
| Problem / Solution Fit | **Structural Strength if fit / Weak if not fit** | Product Capabilityに課題が適合すれば非常に強いが、非定型問題ではFitが落ちる可能性 |
| Capability / Quality | **Structural Strength in product domain** | Product / IP / reusable componentsに集中投資できる |
| Delivery Feasibility | **Structural Strength** | 標準化、Deployment mechanism、Platformによる再利用性 |
| Economic Value | **Structural Strength if reuse works** | 複数顧客へ共通Assetを展開できれば限界費用を下げられる |
| Risk | **Competitive** | Product成熟度・Securityは強い一方、Lock-in等の新たなRiskもある |
| Evidence / Credibility | **Structural Strength** | Product実績、導入社数、Benchmark、Reference等を示しやすい |
| Relational / Governance Fit | **Competitive** | Professional Services組織を持つVendorでは十分強い |
| Organizational Acceptability | **Competitive〜Structural Strength** | 大手Vendorなら高い。新興Vendorでは企業継続性等が懸念になり得る |

### 4.3.3. Why Us検討への意味

AI Vendorとの差は、「AIを業務Actionにつなげる」ではない。

相対的なWhite Spaceがあるとすれば、

- Standard ProductにFitしない非定型問題
- 特定Productを前提にしないTechnology Selection
- 研究的な検証比率が高い問題

等だが、これらもDS専門会社やコンサルAnalyticsと競合する。

## 4.4. Data Science専門会社

### 4.4.1. 顧客が選ぶ主な理由

典型的には、

> **専門人材と多数案件のAnalytics Know-howを集積し、幅広いデータ活用テーマを専門的に支援できること。**

がRight to Winになる。

BrainPadは公式に、

- データ活用コンサルティング
- データ基盤構築
- データ分析・アルゴリズム開発
- データ活用人材育成

を提供し、戦略立案、Solution選定、効果測定、システム構築までを支援している。

また「ベンダーフリーで中立的な立場」も明示している。

従って、以下だけではDS専門会社との差別化にならない。

- Vendor-neutral
- スクラッチ分析
- 予測・最適化等の高度分析
- Business Consulting
- System構築
- 人材育成

### 4.4.2. 8軸評価

| 軸 | 仮説評価 | 理由 |
|---|---|---|
| Problem / Solution Fit | **Competitive〜Structural Strength** | Analytics課題に特化し、多様な案件知見を蓄積しやすい |
| Capability / Quality | **Structural Strength** | DS専門人材とMethodologyが中心Asset |
| Delivery Feasibility | **Competitive** | Engineeringまで持つ会社もあり、分析だけとは限らない |
| Economic Value | **Competitive** | Specialistとして高単価でも、総合コンサルよりLeanな場合がある |
| Risk | **Competitive** | 企業規模・Security体制・継続性による差が大きい |
| Evidence / Credibility | **Structural Strength** | Analytics案件数・専門人材・Caseを示しやすい |
| Relational / Governance Fit | **Competitive** | 専門サービス型として顧客との共同作業に慣れている |
| Organizational Acceptability | **Competitive** | 大手に比べると調達面で不利な場合があるが、実績次第 |

### 4.4.3. Why Us検討への意味

当チームに最も近い外部競合の一つである。

「分析専門性」「幅広い手法」「Vendor-neutral」「スクラッチ対応」だけでは差別化が難しい。

従って当チームがこの類型に勝つには、

- Enterprise credibility
- 顧客既存Systemへの接続性
- 特定の専門領域
- Delivery Model
- 独自Asset
- 実績

等の組合せが必要になる可能性が高い。

# 5. 当チーム｜現時点で確認できる事実

本資料およびユーザーから明示された情報から、現時点で確認できる範囲を限定して記載する。

### 5.1. 確認済み

- 当チームは**SIerのデータ分析部門**に所属する。
- Predictive Analysis / Causal InferenceのPoCサービスを提供する。
- 分析実装はData Scientistによるスクラッチ開発を基本とし、成熟OSS / Libraryを必要に応じて利用する。
- Predictive / Causalを意味論・前提・評価軸まで区別して扱うことを資料設計方針としている。
- CausalではCausal Question / Estimand、Assumptions、Identification、Estimation、Diagnostics / Sensitivityを必要に応じて分けて扱う。
- Ariadneは必須製品ではなく、Analysis Context、条件、結果、判断理由、Lineage等の追跡・再現性を補助する選択肢として位置づける。

### 5.2. 未確認 / Evidence Gap

以下は差別化候補になり得るが、現時点では事実確認がない。

- 担当DSのSeniority / 経歴 / 専門資格 / 論文 / 特許
- Predictive / Causalの案件実績件数
- 特定Industryでの実績集中
- Business Outcomeの定量実績
- Repeat率 / 顧客評価
- PoC期間 / Price competitiveness
- Senior DSが顧客折衝からHands-on実装まで一貫担当するか
- 他SIer AnalyticsよりLeanなDelivery Modelか
- 特定Product / Solution販売KPIから独立した組織か
- PoC後の本番実装を他Vendor / 顧客内製へPortableに渡せるか
- Ariadneが実案件で品質・再現性へ与えた実績
- Causal Inferenceが組織として希少な専門Capabilityか

これらは推測で埋めない。

第一に、**大手競合は8軸のどこか一つだけで勝っているわけではない**。

特にコンサルAnalytics / SIer Analyticsは、顧客組織から見て、

- Capability
- Risk
- Evidence
- Governance
- Organizational Acceptability

まで総合的に高い。

したがって「我々は業務理解があります」「科学的に正しいです」という単一Capabilityでは比較優位が作りにくい。

- Delivery
- Risk
- Organizational Acceptability

しかしこれは**同じSIer Analyticsとの比較ではTable Stakes**になる。

第三に、当チームの差別化を本当に決める可能性があるのは、現時点ではむしろ、

- Capabilityの特化度
- Evidence
- Economic Value
- Delivery Model

のような、まだ事実を棚卸ししていない領域である。

# 8. Table StakesとPotential Differentiatorを分ける

## 8.1. 現時点でTable Stakesとみなすべき候補

以下は重要だが、競合も十分主張・実行できるため、単独ではWhy Usにしない。

### Problem / Fit系

- Business Questionから入る
- Decision / Actionへ接続する
- 顧客課題を理解する

### Capability系

- 最適な分析手法を選ぶ
- Predictiveを適切に評価する
- CausalをIdentificationから考える
- Scientific validityを重視する
- Data Generating Processを理解する

### Delivery系

- OSS / スクラッチを柔軟に利用する
- PoCから本番化を考える
- System制約を考慮する

これらは**「このチームなら安心して候補に入れられる」理由**にはなるが、「競合ではなくこのチームを選ぶ」決め手としては不足する。

# 9. Potential Differentiator候補

8軸に沿って考えると、次の候補を事実確認する価値が高い。

## 9.1. Capability / Quality｜Specialization

### 仮説

> Predictive / Causalのうち、特にCausal Inferenceを含むDecision Science領域へ組織的に特化している。

**差別化条件:**

- 単に「できます」ではなく、案件数・専門人材・方法論・成果物の標準化等で証拠化できること。

---

## 9.2. Capability × Delivery｜Scientist-direct Delivery

### 仮説

> Scientist本人がBusiness Question整理からCoding、Validation、Interpretationまで深く関与する。

これは大規模Professional Serviceの分業モデルとの差になり得る。

**差別化条件:**

- 実際の標準Delivery Modelがそうなっている。
- Seniorityを証拠化できる。

---

## 9.3. Economic Value｜SIer内専門チームとしてのLean PoC

### 仮説

> 総合コンサルの大規模チームよりLeanに、高度な専門分析へ直接アクセスできる。

**差別化条件:**

- Price / team size / duration等の比較事実が必要。
- 根拠なしに「安い・速い」と主張してはいけない。

---

## 9.4. Risk × Organizational Acceptability｜Specialist capability with enterprise-grade vendor base

### 仮説

> 専門ブティックに近い分析専門性を、SIerの契約・Security・Enterprise Delivery基盤の上で利用できる。

これは組合せ差別化である。

```text
Specialist Analytics
       ×
Enterprise Vendor Base
```

単独要素は他社にもあるが、顧客購買の8軸上では、

- Capability
- Risk
- Organizational Acceptability

を同時に満たす価値として意味を持つ可能性がある。

**差別化条件:**

- 専門性側をEvidenceで証明する必要がある。
- 「SIerだから安心」だけでは同業との差にならない。

---

## 9.5. Evidence / Credibility｜専門性を可視化するAsset

### 仮説

Ariadne、分析設計標準、Case Study、Publication等を、単なる内部Assetではなく**Quality Signal**として使える可能性がある。

重要なのはAriadneの機能を売ることではなく、例えば、

> 「当チームではCausal Question / Identification / Assumption / Diagnosticsをこの形式で必ず成果物化する」

という**observable evidence of process quality**へ変換することである。

これはPemer & SkjølsvikのQuality Signalの観点と整合的である。

---

# 10. 現時点で最も重要な発見

差別化仮説を考える際、これまでの議論では主に、

> **Capabilityの中で他社にないものを探す**

ことに偏っていた。

しかし顧客の実際のSupplier Selectionは8軸で行われる。

従って競争優位は、必ずしも「唯一の技術」である必要はない。

例えば、以下の組合せも強い選定理由になり得る。

```text
高度な専門性
    ×
既存Vendorとしての安心感
    ×
LeanなDelivery
    ×
具体的な実績
```

各要素単独では競合も持つ。

しかし、顧客は各Capabilityを独立して買うのではなく、**Provider全体を8軸の組合せとして選ぶ**。

これはAbsolute Differentiationを探し続ける必要がないことを意味する。

# 11. Why Us候補を逆算するための次の作業

現時点では、Why Usを確定するには当チーム側のEvidenceが足りない。

特に以下を棚卸しする必要がある。

## 11.1. Capability Evidence

- チーム人数
- Seniority
- Predictive / Causal案件数
- 特に強いMethodology
- 業界別実績
- Publication / Patent / Conference / OSS

## 11.2. Delivery Evidence

- Typical team structure
- Senior DSのHands-on比率
- Business discussionから実装までの担当分離度
- Typical PoC期間
- 顧客側必要工数

## 11.3. Economic Evidence

- 契約規模
- Competitive price positioning
- 大規模Consulting engagementとの違い

## 11.4. Credibility Evidence

- Case Study

# 14. Evidence / Inferenceの区別

## 14.1. 外部資料から確認した事実

- DeloitteがAI / Dataをbusiness transformation、decision improvement、AI strategyからcustom solution構築まで接続して提供すると説明している。
- NTT DATAがAI Consultingにおいてprototypeのmodel / algorithm / tool選定、pilotからfull-scale deployment、integration、governanceまでを提供すると説明している。
- PalantirがDecisionを起点にsimulationとactionまで含むOperational Applicationを提供している。
- BrainPadがdata consulting、data platform、analysis / algorithm development、人材育成を提供し、vendor-freeな立場も掲げている。

## 14.2. 本書で行った推論

- 各競合類型の8軸上のStructural Strength / Weakness評価。
- 当チームがSpecialist Analytics × Enterprise Vendor BaseとしてPositioningできる可能性。
- Scientist-direct Delivery、Lean PoC等が差別化候補となり得るという仮説。

これらは個別競合に対する実証済み優位ではない。

特に当チームについては、実績・人材・価格・Delivery Modelの具体的Evidenceが不足しているため、次段階で事実確認が必要である。
