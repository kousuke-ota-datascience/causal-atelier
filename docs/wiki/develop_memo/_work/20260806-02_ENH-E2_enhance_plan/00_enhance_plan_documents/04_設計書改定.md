# 設計書改定 — ENH-E2

- 改定日: 2026-08-06
- 改定識別子: `ENH-E2`
- 対象: `00`、`21`、`22`、`23`、`30`

## 1. プロダクトコンセプトメモ改定

### 1.1. 追加原則

- 利用者が操作結果と状態変化を予測できること
- Project管理と分析作業を分離すること
- OutcomeをDiscoveryからInferenceへ一貫して継承すること
- Graph CandidateをProvenanceを失わず統合操作すること
- 説明可能性を科学結果だけでなくUI操作にも適用すること

## 2. 論理データ設計改定

### 2.1. Project

既存`status = ACTIVE / ARCHIVED`を使用する。

```text
ACTIVE --archive--> ARCHIVED
```

- ARCHIVEDからACTIVEへの復元はENH-E2対象外
- hard delete禁止
- read-only Lineage参照は許可

### 2.2. Graph Version

`designated_outcome_node`を追加する。

- DRAFT: nullable
- FIXEDかつInference利用対象: required
- Dataset schemaおよびGraph nodesとの一致を検証
- 子Graph Versionは親の値を既定継承
- 明示変更時は新Versionと理由を要求

### 2.3. Query Model

次を非Entityとして追加する。

- `GraphCandidateView`
- `GraphComparisonView`
- `OperationAvailabilityView`

### 2.4. Discovery Result

Discovery Result payload / summaryへ`designated_outcome_node`を保持する。Algorithm Output自体のGraph構造とは分離したmetadataとして扱う。

## 3. プロダクト基本設計改定

### 3.1. 設計粒度

基本設計で次を定義対象に追加する。

- 操作可能状態
- 読取対象
- 生成・更新対象
- 操作後状態
- UI Gate
- 拒否時挙動

### 3.2. 画面構成

```text
Global Header
├── Project selector
└── Project Register & Management

Project Analysis
├── Project / Data
├── Discovery
├── Inference
└── Results / Lineage
```

### 3.3. Project Register & Management

- Project register
- Project list
- delete confirmation
- ACTIVE / ARCHIVED境界

### 3.4. Discovery

- Discovery Setup
- Feature selector modal
- Outcome selector
- Execution status
- Graph Candidates
- Graph inspect/edit modal
- Graph comparison modal
- Direct Graph registration

### 3.5. Graphモーダル状態

| 対象 | 初期モード | 編集動作 |
|---|---|---|
| Discovery Result | read-only | DISCOVERED root作成後に子DRAFT作成 |
| Graph Version DRAFT | editable | 同一Version更新 |
| Graph Version FIXED | read-only | 子DRAFT作成 |

### 3.6. Inference

- Outcome入力欄を削除
- Graph VersionのOutcomeをread-only表示
- Graph選択変更時にOutcomeを再取得
- Identification受付時に一致検証

## 4. API・インターフェース設計改定

### 4.1. Project API

- `DELETE /projects/{project_id}`を論理削除として追加
- Project一覧へstatus filterを追加
- ARCHIVED Projectへのwriteを拒否

### 4.2. Graph Candidate API

- Graph Candidate一覧Query
- Graph Candidate詳細Query
- Graph Candidate比較Query
- 状態に応じた編集DRAFT作成Command

### 4.3. Discovery Contract

`operation_spec`へ`designated_outcome_node`を追加する。

### 4.4. Graph Version Contract

Graph Version create / responseへ`designated_outcome_node`を追加する。

### 4.5. Inference Contract

Causal Question OutcomeはGraph Versionの値と一致必須とする。Web AppはGraph Versionから値を設定し、利用者入力を受け付けない。

## 6. 状態・操作境界の必須表

各画面に次の形式の表を置く。

| 操作 | 対象 | 前提状態 | 読取 | 生成 | 更新 | 操作後 | UI拒否 |
|---|---|---|---|---|---|---|---|
| Project削除 | Project | ACTIVE | Project | なし | status | ARCHIVED | 確認取消または既ARCHIVED表示 |
| DRAFT編集 | Graph Version | DRAFT | Graph | なし | graph / rationale | DRAFT | FIXEDは編集不可 |
| FIX | Graph Version | DRAFT | Graph | なし | status | FIXED | validation error |
| FIXED編集 | Graph Version | FIXED | Parent | Child DRAFT | なし | Child DRAFT | Parent不適格を表示 |
| Estimation | Identification Result | IDENTIFIED等 | Result / Graph | Execution | なし | QUEUED | Gate理由表示 |
