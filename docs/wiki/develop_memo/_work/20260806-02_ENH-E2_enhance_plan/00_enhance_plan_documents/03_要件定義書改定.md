# 要件定義書改定 — ENH-E2

- 改定日: 2026-08-06
- 改定識別子: `ENH-E2`
- 改定名称: 操作・状態連動型UIおよびGraph操作統合
- 改定対象: `10_Revised_requirements_definition_documents/10_要件定義.md`
- 改善要望: `../../20260806-02_bug_and_improvement/bug_and_improvement.md`

## 1. 適用範囲

ENH-E2はENH-E1 / ENH-E1aの科学的妥当性要件を変更しない。次を追加する。

- 全画面の説明、用語補足、入力支援
- Project管理画面
- Project論理削除
- Discovery列選択支援
- DiscoveryでのOutcome指定
- Graph Candidate統合表示
- DAG確認・編集モーダル
- DAG比較モーダル
- Inference Outcome継承
- 操作と状態遷移の一意化

## 3. 追加E2Eシナリオ

### 3.1. E2E-07 Project Register & Management

1. 管理画面を開く
2. Projectを登録する
3. Project一覧に表示される
4. Projectを選択しProject / Dataで編集する
5. 削除確認後にProjectをARCHIVEDへ変更する
6. ARCHIVED Projectが通常Project選択から除外される
7. 既存Result / Lineageは保持される

### 3.2. E2E-08 Discovery入力支援とOutcome固定

1. Dataset Versionを選択する
2. Feature selectorで複数列を選択する
3. Outcome selectorで1列を選択する
4. Discoveryを実行する
5. ResultとGraph VersionにOutcomeが保持される
6. DAG表示でOutcome nodeが可能な限り右側に配置される

### 3.3. E2E-09 Graph Candidate統合操作

1. Discovery ResultとGraph Versionを同一一覧で確認する
2. Discovery Resultを未編集のDISCOVERED Graph Versionとして固定する
3. FIXED Graph Versionから子DRAFTを作る
4. edgeを編集し理由を記録する
5. DRAFTをFIXEDにする
6. 親子関係、OriginおよびFIXED状態を一覧で確認する

### 3.4. E2E-10 Graph比較とInference継承

1. 2件以上のGraph Candidateを選択する
2. 比較モーダルで各DAGをタブ表示する
3. 構造差分summaryを確認する
4. FIXED Graph VersionをInferenceで選択する
5. Outcomeがread-onlyで継承される
6. Outcomeの不一致を作成できない

## 4. 追加機能要件

### 4.1. 説明・入力支援

| ID | 要件 | 優先度 |
|---|---|---|
| FR-068 | 各ページは目的、作業概要および主要用語の説明を表示すること | MUST |
| FR-069 | 各セクションはタイトルと操作説明を持つこと | MUST |
| FR-070 | 主要入力項目はツールチップまたは入力例を提供すること | MUST |

### 4.2. Project管理

| ID | 要件 | 優先度 |
|---|---|---|
| FR-071 | Project登録、一覧および削除をProject Register & Management画面で行えること | MUST |
| FR-072 | Project削除操作は確認を要求し、`ACTIVE`から`ARCHIVED`へ遷移させること | MUST |
| FR-073 | ARCHIVED Projectは通常選択、新規Dataset登録、新規Execution、Graph作成およびAnnotation更新の対象外とすること | MUST |
| FR-074 | ARCHIVED Projectの既存Dataset、Execution、Result、Graph Version、ArtifactおよびLineageを保持すること | MUST |

### 4.3. Discovery入力

| ID | 要件 | 優先度 |
|---|---|---|
| FR-075 | Feature columnsを選択Datasetのschemaから複数選択できること | MUST |
| FR-076 | Feature columnsのテキスト値と選択モーダルを決定論的に同期すること | MUST |
| FR-077 | Outcomeを選択Datasetの列から1件選択できること | MUST |
| FR-078 | OutcomeをDiscovery Snapshot、Discovery ResultおよびGraph Versionへ引き継げること | MUST |
| FR-079 | DAG表示はdesignated outcome nodeを可能な範囲で右端へ配置し、存在しない場合は警告すること | SHOULD |

### 4.4. Graph Candidate

| ID | 要件 | 優先度 |
|---|---|---|
| FR-080 | Discovery Graph Resultと同一ProjectのGraph Versionを統合したGraph Candidate一覧を生成できること | MUST |
| FR-081 | Graph Candidate行は選択、FIXEDフラグ、親またはSource、status、summaryおよび確認・編集操作を表示すること | MUST |
| FR-082 | Discovery Resultを直接更新せず、未編集採用または派生Graph Version作成として操作すること | MUST |
| FR-083 | DRAFT Graph Versionのみ同一Version内で編集できること | MUST |
| FR-084 | FIXED Graph Versionの編集は当該Versionを親とする新しいDRAFTを生成すること | MUST |
| FR-085 | Graph確認・編集をモーダルで行い、独立Graph Version editorセクションを廃止すること | MUST |
| FR-086 | 2件以上のGraph Candidateを選択して視覚的に比較できること | MUST |
| FR-087 | Graph比較を生JSONの羅列だけで表示せず、DAG表示、タブおよび差分summaryを提供すること | MUST |

### 4.5. Inference

| ID | 要件 | 優先度 |
|---|---|---|
| FR-088 | Inference画面はIdentificationおよびData Eligibilityの説明を表示すること | MUST |
| FR-089 | Inference画面のOutcome入力欄を廃止し、FIXED Graph VersionのOutcomeを表示すること | MUST |
| FR-090 | Inference受付時にGraph VersionのOutcomeとCausal QuestionのOutcome一致を検証すること | MUST |
| FR-091 | Outcome未指定のGraph Versionを新規Inference入力として使用できないこと | MUST |

### 4.6. 操作・状態境界

| ID | 要件 | 優先度 |
|---|---|---|
| FR-092 | 各状態変更操作は操作可能状態、生成・更新対象および操作後状態を一意に定義すること | MUST |
| FR-093 | UIの操作可否はAPIが返す正本状態と同一規則から導出すること | MUST |
| FR-094 | UIで無効化した操作をAPI直接呼出しで実行できないこと | MUST |
| FR-095 | 状態不整合による拒否は技術障害と区別可能なerror codeおよび説明を返すこと | MUST |

## 6. 受入れ基準

1. 全ページと全セクションに目的説明がある
2. Project登録が管理画面へ移管されている
3. Project削除時に確認が表示され、ProjectがARCHIVEDになる
4. ARCHIVED Projectで新規分析操作を実行できない
5. Feature selectorとテキスト入力が同期する
6. Datasetに存在しない入力値がselectorで選択済みにならない
7. OutcomeがDiscoveryからGraph Versionへ保持される
8. InferenceでOutcomeを編集できない
9. Graph ResultsにDiscovery Resultと子Graph Versionが表示される
10. Discovery Result、DRAFT Graph、FIXED Graphでモーダル操作が状態に応じて変わる
11. FIXED Graphの編集で新しい子DRAFTが生成される
12. Graph比較は2件から起動できる
13. 比較画面が生JSONだけではない
14. 基本設計の操作・状態対応表と実装Testが対応している
15. ENH-E1aのData Eligibility、Identification status、Revised Executionおよび探索後推論警告が30へ統合されている
