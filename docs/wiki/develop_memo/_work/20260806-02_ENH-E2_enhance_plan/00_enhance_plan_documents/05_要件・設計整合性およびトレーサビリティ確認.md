- 操作可否はUIとBackendで同一規則を検証する

## 3. 構造整合性

### 3.1. 7 Entity原則

新しい主要Entityを追加していない。

- Graph Candidate: Query Model
- Graph Comparison: Query Model
- Modal: UI state
- Operation Availability: Query / Response metadata

### 3.2. Project削除

`21_論理データ設計.md`の既存Project statusと整合する。FK `RESTRICT`およびLineage保持方針とも矛盾しない。

### 3.3. Graph Provenance

- Discovery Resultは不変
- DISCOVERED Graph VersionはSource Result参照
- USER_EDITED Graph VersionはParent参照
- DRAFT / FIXED状態遷移を維持

### 3.4. Outcome

OutcomeはGraph構造そのもののedge semanticsではなく、Graph Versionに付随するdesignated analysis nodeとして保持する。Inference Causal Questionへ複製されるが、受付時に一致検証するため二重正本化しない。

## 4. 操作・状態整合性

| 対象 | 状態 | 許可操作 | 禁止操作 |
|---|---|---|---|
| Project | ACTIVE | edit、dataset、execution、archive | hard delete |
| Project | ARCHIVED | read-only lineage | edit、新規分析 |
| Graph Version | DRAFT | edit、fix | inference入力 |
| Graph Version | FIXED | view、derive、inference | direct edit |
| Execution | QUEUED | view、cancel | snapshot edit |
| Execution | RUNNING | view、cancel | retry、snapshot edit |
| Execution | FAILED | view、retry | condition change in same execution |
| Result | scientific negative | view、compare、lineage | technical failure扱い |
