## 3. Canonical rerun contract

Product-facing Predictive rerunは:

```text
base canonical Predictive Execution
        ↓
same scientific conditions
        ↓
new canonical Execution
        ↓
new persistent StageExecution set
```

として成立させる。

必須:

```text
new execution_id != base execution_id

base_execution_id
    = original canonical Execution ID

analysis_family
    = PREDICTIVE

revision_kind
    = RERUN

change_reason
    = NONE

scientific conditions
    = baseと同一
```

---

## 4. Preserve Predictive scientific conditions

rerunでは少なくとも以下をbase canonical snapshotからlosslessに再構成する。

```text
dataset_version_id
analysis_view_id where applicable

analysis specification
analysis_specification_id where projected

execution plan semantics
execution_plan_id where projected

algorithm / estimator
parameters
seed

code/runtime snapshot according to canonical contract
family-specific runner metadata
```

rerunを成立させるために旧 `FamilyExecutionOrm` をbase snapshot authorityとして使用してはならない。

---

## 5. RERUN と REVISED を混同しない

rerunではscientific conditionsを意図的に変更しない。

したがってexpected canonical resultは:

```text
revision_kind = RERUN
change_reason = NONE
```

である。

以下は禁止する。

```text
rerunなのにseedを再生成する

rerunなのに新しいplan/specを意味なく作る

rerunなのにchange_reasonを自動生成する

canonical comparisonを回避するため
revision_kindをservice側で強制的にRERUNへ偽装する
```

canonical ExecutionServiceによるactual condition comparisonを通すこと。

---

## 6. New StageExecution identity

rerunはretryと異なる。

```text
retry:
    same Execution
    same StageExecution identity

rerun:
    new Execution
    new StageExecution identity set
```

を明確にtestする。

rerun後のStageExecutionはbase ExecutionのStageExecution IDを再利用してはならない。

ただしstage plan semantics:

```text
stage_key
stage_type
dependencies
ordinal
```

は同一scientific conditionsに対応するplanとして整合すること。

---

## 7. No legacy Family authority

rerunによって以下をnew writeしてはならない。

```text

FamilyResultOrm

```

禁止:

```text

    + shadow FamilyExecution

    + shadow FamilyStageExecution
```
