## 2. 今回の唯一の実装課題

Product-facing Predictive retryを、

```text
PredictiveWorkflowService
    -> canonical ExecutionService
    -> canonical Execution
    -> existing persistent StageExecution
    -> next StageExecution attempt
```

というcanonical lifecycleとして成立させる。

retry時に新しいExecutionを作らない。

retry時に既存StageExecutionを削除・再作成しない。

## 4. Retry semantics

Product-facing Predictive retryのcompletion contract:

```text
Execution ID
    = unchanged

StageExecution ID set
    = unchanged

Execution retry_count
    = canonical ruleに従いincrement

StageExecution attempt history
    = previous attemptsを保持

next worker execution
    = new attemptとして記録

Predictive family
    = PREDICTIVEのまま

Predictive immutable snapshot
    = preserved
```

保持対象:

```text
analysis specification context
execution plan context
dataset_version_id
analysis_view_id
seed
family-specific runner metadata
```

## 6. StageExecution retry preparation

現在のcanonical retry pathがExecution retry_count更新だけで、workerが再claimしてもStageExecutionが再実行可能にならない場合は、**G03 contractに沿ったminimal lifecycle integration**を追加する。

ただし、以下を勝手に決めない。

```text
FAILED stageを単純にPENDINGへ戻せばよい
全stageを無条件resetすればよい
attempt historyをclearすればよい
```

G03で既に承認・テストされたStageExecution state/attempt semanticsをactual sourceから特定し、それに従う。

必要ならExecutionService側にcanonical retry orchestrationを追加する。

family service側へStageExecution lifecycle logicを複製しない。
