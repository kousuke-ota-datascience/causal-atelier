# Ariadne / ENH-E4 要件定義書改定記録

## 1. 改定対象
主対象はsnapshot `Revised_requirements_definition_documents/10_要件定義.md`。設計上の検証条件は21、22、23、30のsnapshotへcross-referenceする。baselineは `docs/wiki/requirement_definition/` の6文書であり、sourceは変更しない。

## 2. 改定概要
既存のfamily別lifecycleを、family/typeをworkflow semanticsとして保持する一つのcanonical Product persistent Executionへ統合する。Stage、Result、Artifact、Lineage、legacy、migration、CLIのauthorityと境界を明文化する。Current behaviorをTarget実装済みとは扱わない。

## 3. 主要差分
| Requirement ID | Before | After | Reason |
|---|---|---|---|
| E4-REQ-001〜002 | Product/legacy rootsの境界が分散 | Product API/workerのみcanonical | ADR-001/009 |
| E4-REQ-003〜010 | family別Execution lifecycle | one Execution、共通state/claim/mutation | ADR-002/003 |
| E4-REQ-011〜014 | Stage persistenceとrunner責務が非対称 | 全workflowにStageExecution、GenericExecutorは従属 | ADR-004/005 |
| E4-REQ-015〜020 | Result/Artifact ownershipとphysical keyが混在 | semantic level/metadata owner/store portを分離 | ADR-006/007 |
| E4-REQ-021〜025 | typed/derived/generic lineageが重複 | relationごとにtypedまたはgeneric-only | ADR-008 |
| E4-REQ-026〜029 | legacy runtimeとshared capabilityが近接 | orchestrationをretire/archive、scienceを保持 | ADR-009 |
| E4-REQ-030〜032 | bootstrap chainのcanonical性が不明確 | Product migrationsのみ、root legacyはhistory-only | ADR-010 |
| E4-REQ-033〜035 | CLI/legacy namingの境界が不明確 | utility boundaryとcompatibility evidenceを要求 | ADR-011/012 |
