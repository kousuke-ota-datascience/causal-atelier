# 要件定義書改定 — ENH-E1

- 改定対象: `../10_Revised_requirements_definition_documents/10_要件定義.md`
- 改定識別子: `ENH-E1`
- 改定方式: 既存要件を維持し、以下を追加または変更する
- 改定状態: 承認済み

> **本書はENH-E1に関するシステム要件の正本である。**
>
> **実装、既存コード、DBスキーマ、API、UI、テスト結果から本書を逆生成または事後更新してはならない。**

## 1. 適用範囲

### 1.1. Golden Pathの改定

既存Golden Pathを以下へ拡張する。

```text
Dataset登録
→ 因果探索またはGraph登録
→ Graph比較・選定・固定
→ Causal Question／Causal Design指定
→ Identification
→ Data Eligibility
→ ATE／ATT推定
→ Diagnostics
→ Refutation／Sensitivity
→ Result比較
→ Claim／Limitation記録
→ Lineage確認
```

### 1.2. 対象Estimand

ENH-E1では、二値Treatmentの以下を対象とする。

- ATE
- ATT

### 1.3. 非対象

以下はENH-E1の対象外とする。

- 連続Treatment
- CATE／HTE
- IV
- DiD
- RDD
- Synthetic Control
- 時系列因果分析
- 生存時間Outcome
- 反復介入
- Policy Optimization
- Monitoring
- 独立Approval Workflow

## 11. Data Eligibility検査項目

ENH-E1では最低限、以下を検査する。

- Treatment、Outcome、Covariateの存在
- 型互換性
- Analysis Unitの重複
- 定数列
- Treatment Prevalence
- Missingness Summary
- Post-treatment Variableの混入
- Adjustment SetへのTreatment／Outcome混入
- Graph Nodeとの整合性
- Sample Size
- Propensity Estimation可能性
- Overlapの初期診断
- Extreme Weightの発生リスク

総合Statusが`FAIL`の場合、Estimationを実行してはならない。

## 15. 受入れシナリオ

### 15.1. E2E-04 Identification-first

1. Dataset Versionを登録する
2. FIXED Graph Versionを選択する
3. Causal QuestionおよびCausal Designを入力する
4. Identification Executionを実行する
5. Identification ResultとData Eligibility Resultを保存する
6. `IDENTIFIED`の場合のみEstimationへ進む
7. 同じIdentification Resultを2種類以上のEstimatorが参照する
8. Diagnosticsを比較する
9. RefutationとSensitivityを実行する
10. Annotationへ採用理由、Assumptions、Limitationsを記録する
11. Resultからすべての上流条件へ遡る

### 15.2. E2E-05 非識別結果

1. 識別不能なGraph／Causal Questionを指定する
2. Identification Executionは技術的に`SUCCEEDED`となる
3. Identification Resultは`NOT_IDENTIFIED`となる
4. 非識別理由が保存される
5. 通常Estimationの受付は拒否される
6. Result比較およびLineage確認は可能である

### 15.3. E2E-06 Graph Provenance

1. Discovery ResultからGraph Versionを作成する
2. Constraintを適用したGraph Versionを別Versionとして作成する
3. User Editを別Versionとして作成する
4. 各VersionのOrigin、Parent、理由を確認する
5. Algorithm Outputを人為編集結果として表示しない

## 16. 受入れ基準

以下をすべて満たすこと。

- DeterministicなIdentification Scenarioで期待Statusが全件一致する
- Post-treatment Adjustmentを拒否する
- Colliderを既知の不適切Adjustment Setとして拒否または警告する
- Poor Overlap Scenarioを`WARN`または`FAIL`として検出する
- `NOT_IDENTIFIED`からEstimationを作成できない
- 同一Identification Resultを複数Estimatorで利用できる
- Refutation／Sensitivity Resultを再実行できる
- CPDAG／PAGをDAGへ暗黙変換しない
- 旧Run／Attempt／独立Resourceを追加していない
- 実装から要件定義書を更新していない
