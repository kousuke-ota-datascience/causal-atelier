## 4. 構造上の整合性確認

### 4.1. 7 Entityとの整合性

矛盾なし。

Identification、Data Eligibility、Diagnostics、Refutation、SensitivityをExecutionおよびResultで表現する。

新しい主要Entityを追加しない。

### 4.2. Research Context独立Resource対象外との整合性

矛盾なし。

Research ContextをExecution Snapshotへ格納する。

独立Resource、Version、専用Tableを追加しない。

### 4.3. Analysis Specificationとの整合性

矛盾なし。

Causal Question、Causal Design、Operation Specを構造化された`analysis_spec_json`として固定する。

### 4.4. Execution Planとの整合性

矛盾なし。

Execution Planを独立Entityにせず、Executionの不変Snapshotとして保持する。

### 4.5. Comparison非Entityとの整合性

矛盾なし。

新しいResult Typeの比較もQuery Projectionとして提供する。

### 4.6. Lineage Relation非Entityとの整合性

矛盾なし。

`input_result_id`、Dataset、Graph、Source Result等の明示的な参照関係からLineage Viewを生成する。

### 4.7. Stage／Attempt対象外との整合性

矛盾なし。

OperationはExecutionの種別であり、Stage EntityまたはAttempt Entityではない。

### 4.8. Approval Workflow対象外との整合性

矛盾なし。

Validation OverrideおよびClaimはExecution SnapshotまたはAnnotationへ記録する。

独立Review／Approval Workflowは追加しない。

### 4.9. 将来機能対象外との整合性

矛盾なし。

CATE、IV、DiD、時系列、Policy、MonitoringはENH-E2以降へ延期する。

## 5. 科学的方法論上の整合性確認

### 5.1. Identification-first

要件と設計は、IdentificationをEstimationとは別のExecutionとして扱う。

整合している。

### 5.2. 識別可能性と計算可能性

Identification ResultとTreatment Effect Resultを別Result Typeとして扱う。

整合している。

### 5.3. 技術状態と科学状態

Execution StatusとResult Scientific Statusを分離する。

整合している。

### 5.4. Graph Provenance

Algorithm Output、Post-hoc Constraint、User Editを別Graph Versionとして保持する。

整合している。

### 5.5. CPDAG／PAG

Endpoint Semanticsを保持し、暗黙DAG化を禁止する。

整合している。

### 5.6. Refutation

Refutation成功を仮定の証明として扱わない。

整合している。

### 5.7. Sensitivity

Base Specificationとの差および結論依存性として表示する。

整合している。

## 8. 実装前の未解決事項

現時点で、実装者が独自判断しなければならない未解決要件はない。

ただし、実装時に以下が判明した場合は、実装判断で補完せず設計変更手続へ戻る。

- CPDAG／PAGのEndpointを現行Graph Schemaで保持できない
- Graph Constraintの適用方式を判別できない

- Result Chainが単一`input_result_id`では不足する
- Scientific Backendが必要なScientific Statusを表現できない
- 受入条件を満たすために新しい主要Entityが必要になる
- Benchmark閾値が対象Estimatorに不適切である
